# M39 · U4 串口诊断（端口枚举 / 波特率探测 / ID 扫描 / 日志导出）

- **日期**：2026-08-06
- **完成了什么**：新增 `components/so101/SerialDiagnostics.tsx` —— 浏览器内串口诊断面板：WebSerial 特性检测 → `getPorts()` 端口枚举（vendor/product ID）→ 选口后按 **1M / 115200 / 9600** 三档波特率探测（每档 ping ID 1–7，逐 ID 报在线/型号）→ 结论提示 → **日志一键下载**（`botversex-serial-diag-<ts>.txt`）。接入两个入口：扫不到舵机的卡片内联（先释放主连接再诊断）+ 断开状态的「串口诊断 / 导出日志」入口。
- **解决了什么**：
  - M31 三方共识的致命问题二：「插上 USB 扫不到舵机」是最高频真实故障（供电/驱动/USB 芯片/ID 冲突），此前浏览器内无法诊断、团队也看不到——现在诊断搬到浏览器内，日志可导出给支持团队远程定位。
  - 多波特率探测只弹一次授权框：`FeetechSerialPort.attachGrantedPort()` 绑定已授权端口后逐档重开（9600/115200 常是用户误配波特率的真相）。
  - 安全纪律不变：只做只读诊断（ping 是只读指令），不写寄存器、不改 ID。
- **关键命令**：前端 tsc（SerialDiagnostics + BrowserDirectPanel）零错误；协议冒烟 24/24 保持（协议层未动，仅加 attachGrantedPort）。
- **最终结果**：已提交。真实故障场景（真机 + 浏览器）验证待硬件。
