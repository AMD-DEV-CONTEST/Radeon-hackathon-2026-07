# omima · VOX 分镜草稿（快节奏 / 类 PPT）

> **成片时长**：主片 **约 4 分 30 秒**（可剪 90s 超短版）  
> **节奏**：类 PPT 翻页 + VOX 动能字幕 · **每镜 2–5 秒为主**，少长镜头  
> **思想**：`core-thesis.md`  
> **口播全文可按镜拼接**；数字以 `00-PACKAGE.md` 为准  
> **视觉规范**：见文末「美术板」；分镜板 HTML：`storyboard-board.html`

## 0. 节奏与形式

| 参数 | 设定 |
|------|------|
| 画幅 | 16:9 · 1920×1080 |
| 底色 | 深空黑 `#0B0E14` |
| 主强调色 | 信号青 `#13B8A6` / 警示红 `#FF4D4F`（仅 DENY） |
| 辅色 | 冷灰字 `#A8B0BD` · 白标题 `#F5F7FA` |
| 字体感 | 无衬线粗标题 + 细数字；动能字可错层、弹出、扫光 |
| 转场 | 硬切 70% · 擦除/缩放 20% · 闪白/色块 10% |
| 音乐 | 120–128 BPM 电子脉冲，口播句末可踩点 |
| 禁止 | 长实机 UI、慢推空镜、超过 6 秒的单屏说教 |

**VOX 活力点**：每 3–5 秒换信息核；标题≤8 字；一屏一主张；数字全屏砸一下再收。

## 4. 口播连贯稿（主片，可稍改语气）

> 为什么 AI 交付总是差一点？不是模型不够大——是工程没闭环。  
> omima：从需求长出来的效率工程。六大类需求推演实现，三大要素收敛成果。  
> 先看用户要什么：基础、推理、创作、知识、安全、长程 Agent。覆盖面先定死。  
> 需求定了，系统该长什么就被推出来：协议算法、模型设置、工作方法。  
> **第一**，系统化协议与算法：谁入网、怎么调、记忆归谁、何时拦截。星站可复制；越权框架 DENY；协作、边界、审计一次写清。  
> **第二**，内化大模型设置：1B 阵眼、9B 工具、35B 军师——岗位内化，不是碰运气。上岗验证落在 AMD Instinct。  
> **第三**，内化工作方法：创意、论证、规划、执行、审查；串流不跳拍，能并就并；每步可审计。  
> 三要素合拢，才指向高满意度交付。  
> 这不是单点技巧：Harness 管工具与复用，Loop 管多步边界，硬件管岗位对硅片。缺一角，就靠自觉、协作乱、或算力空转。  
> 一次交付：落到需求大类，走完五拍，记忆留阵眼，铁律挡越权，审查盖章。  
> 硬件切面账在 MI300X：FP8 约加百分之六十五，tool-call 八分之九，岗位权重可拉。测速微调中规中矩——为上岗。  
> 六大类需求，三大要素，一套效率工程。终点是用户满意的成果。  
> Order Made In Mayhem, Always. 秩序，总从混乱中生成。
