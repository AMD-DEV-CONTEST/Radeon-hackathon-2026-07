## 执行摘要

**omima — 不追风，只补缺口。**

个人 AI 有两条断头路：**数据交给云端，隐私没了；Agent 各自为战，编排没有。** omima 把路接上——但接法不是再堆一个聊天壳，而是一套**完整的效率工程设计**。

### 收敛表述（评委可先读）

1. **起点**：产品由**六大类应用需求**推演——基础能力、推理与科学、对话与创作、知识与百科、安全与责任、长文本与 Agent（工程上展开为六类二十八种任务谱系）。需求决定要实现哪些算法与系统能力。  
2. **收敛为三大要素**：  
   - **系统化协议与算法**（协作、边界、状态可回放）；  
   - **内化大模型的设置**（1B / 9B / 35B 岗位内化，含训练与服务参数）；  
   - **内化的工作方法**——**创意 → 论证 → 规划 → 执行 → 审查**，多 Agent **串流并行**，每步可审计。  
3. **工程切面**：同一设计覆盖 **Harness**（工具约束与经验复用）、**Loop 工程**（有边界的多步与串并行）、**硬件编制**（端侧 + 星罗棋布，岗位对硅片）。  
4. **终点**：**用户高满意度的交付成果**——覆盖需求、不越权、可审计、长程任务能走完工序。

思想定稿全文见 **`core-thesis.md`**。演示为**VOX 动画**（按 `demo-storyboard-vox.md`，3–5 min/90s）。

### 形态摘要

**omima**（Order Made In Mayhem, Always）在形态上是 **Astral Metro Domain**——**基于 AMD 算力底座设计的分布式异构星网系统**，通过 **Porphyrion 协议**互联，分三层：

| 层 | 构成 | 职责 |
|----|------|------|
| **工具侧（harness 编排层）** | Xagent（桌面，DEMO）· omima APK（手机，DEMO） | 用户入口与编排：铁律、工具约束、五拍工序、经验复用 |
| **星网 POS 层（低算力补充配置）** | 无状态 ECS / 云电脑（CPU 级） | 登记能力、领任务、执行、回传、遗忘 |
| **模型层（按需取用）** | omima-1B 路由（常驻）· 9B/35B 作业（按需拉起） | 路由常驻，作业模型按需上岗；岗位对应硅片。三个模型均在 AMD MI300X (ROCm) 上调优后训练——赛前 AMD 提供的算力准备，**非产品运行配置** |

层间用 **Porphyrion 通信协议**对接：**稳定长连接 + 事件回调**，**无视云电脑「无 22 端口 / 无公网 IP」的缺陷**——异构设备真正组网，不是一台设备对抗超级单体，是**整个私人星网对抗一个超级单体**。三个模型的后训练与军师验证主链在 **AMD MI300X（ROCm）** 上发生——这是**赛前准备阶段 AMD 提供的算力准备**，用来证明岗位模型可上岗；不作为 omima 的产品可选配置（该配置对普通用户过于专业），产品运行以消费级为主。详见 **`amd-rocm-technical.md`**。

## 1. 问题定义

### 1.1 你的数字生活没有 OS

| 现存 OS | 管理什么 | omima 管理什么 |
|---------|---------|---------------|
| Windows / macOS | 进程、内存、文件系统 | 注意力、上下文、隐私边界 |
| Android / iOS | App 生命周期、通知 | 跨设备任务编排、异构算力调度 |
| 云服务 AI | 你的数据（上传一切） | 你的数据（永不出设备） |

### 1.2 现有 AI 助手的三重困境

1. **隐私困境**：ChatGPT/Gemini/Claude 默认收集用户数据用于训练。omima 的 1B Polaris 在本地把用户意图转成纯任务描述，仅将此发给云端。**云端从未接触你的记忆**——记忆留在设备上，出设备的只是脱掉上下文的纯任务描述。

2. **成本困境**：云端 API 按 token 计费，成熟产品的订阅价是公开的——ChatGPT Plus $20/月、Claude Pro $20/月、GitHub Copilot $10/月、Cursor Pro $20/月。重度用户一个月烧掉几十美元订阅费，换来的是"对话不被记住"。omima 的成本控制不是靠省——是靠**复用**：Xagent 从 Reasonix 移植的缓存命中机制让云端推理的重复部分直接命中缓存，调用云端 DeepSeek API 的边际成本被压到接近免费。这个机制在真实使用里已经被验证（见 3.6 节真实数据）。

3. **算力困境**：手机 Agent 是"天残"——算力匮乏的短板。omima 通过 Astral Metro Domain 将散布的 AMD 设备编织为私人星网：**35B 级复杂推理跑在统一内存主机或按需 GPU 上**、ECS CPU 做工具执行、手机 GPU 做离线感知。算力成本结构上，ECS/云电脑这类 CPU 级算力相对 GPU 算力是绝对的低价——日常任务跑在 CPU 级实例上，GPU 只在真正需要时出现。不是一台设备对抗超级单体——是**整个私人星网对抗一个超级单体。**（注：MI300X 是赛前 AMD 提供的训练/验证算力，非产品运行配置。）

## 2. 为什么是 AMD——比赛是入口，编制才是咬合点

直接说：omima 参赛 AMD 黑客松，是因为 AMD 办了这场比赛。没有更深的「哲学必然」。

但「参赛」不等于「硬凑」。omima 要跑的模式是 **端侧 + 星罗棋布**：记忆与路由在阵眼，执行摊在许多台机器上，模型按岗位编制而不是塞进一个单体。AMD 的产品图谱——消费级 NPU、统一内存客户端、Instinct 数据中心卡、海量 x86 云实例——正好能托住这张编制表：

| 模式岗位 | 硬件落位（产品预期） | 本赛主链 |
|----------|----------------------|----------|
| 阵眼常驻 / 路由 | 手机 SoC；可选 **Ryzen AI** | 控制面与 1B 角色定义 |
| Worker 跟手推理 | **Ryzen AI 笔记本**（9B） | MI300X 上训出 omima-9B；CPU GGUF 验证 tool-call |
| 军师深推理 | **MAX 395+/400 类统一内存主机**（35B） | **MI300X** 上 FP8 服务点 + omima-35B LoRA |

NVIDIA 数据中心是另一条赛道。omima 不贬低它，也不包装「选 AMD 是信仰」——**编制需要分层硅片，AMD 把分层放在同一世界观里，比赛给了 Instinct 上的小时数。**

### 2.1 模型栈——1B / 9B / 35B 是编制，不是购物清单

模式要求三条时间尺度同时成立：**永远在线、日常执行、深度思考**。一个尺寸做不到。

| 模型 | 岗位 | 部署想象 | 许可 / 基座 |
|------|------|----------|-------------|
| **omima-1B**（Polaris） | 唯一记忆持有者 · 路由 · 任务提炼 | 手机优先「无处不在」；可选 Ryzen AI 常驻 | 开源权重；功能按阶段开放 |
| **omima-9B** | 工具循环 · 跟手推理 · 星站 Worker | 产品：Ryzen AI 笔记本；验证：CPU GGUF | MIT（Ornith-1.0-9B） |
| **omima-35B** | 军师 · 隐私向深推理 | 产品：MAX 类统一内存主机；实验室：**MI300X** | Ornith-1.0-35B LoRA / Qwen3.6-35B-A3B FP8 服务向 |

部署自由度仍在：不装本地模型可走云端 API（见 2.3）；装了就按岗位上岗。  
**本赛已上岗的权重与数字，主证据在 MI300X（ROCm）**——见 2.2 与专章。消费级整机是模式落位，不作「已在本赛逐台刷完」的表述。

推理双轨：端侧/本地岗位模型处理隐私与日常；云端 DeepSeek 等处理尖峰——Polaris 路由，云端不持记忆。

**数据**：

### 2.3 推理路由：云端建议 DeepSeek——不慕强，按需调用

**先摆事实**：DeepSeek 的能力属于第一梯队。这不是我们的判断，是它自己的成绩单——开源权重、评测前列、调用成本比闭源对手低一个数量级。

**再摆定价**（官方公开价）：Claude Fable 5（Anthropic 最强）$10/MTok input / $50/MTok output；Claude Sonnet 5 起步 $3/$15；DeepSeek 未命中 ¥2/MTok、缓存命中 ¥0.2/MTok。差距不是一个数量级，是两个。

那么问题来了：既然能力够、价格低，为什么很多人还是觉得"闭源顶尖模型更好"？

因为 **大多数人都没有掌握用好 DeepSeek 的正确方法**（基于我们服务真实开发会话的观察）。

- DeepSeek V4 的能力覆盖绝大多数人群的日常使用需求——从写代码到写方案，从数据分析到知识问答
- 但大多数人在使用时，只是把它当成一个聊天窗口：上下文不复用、记忆不保存、工具链不组织、重复问题反复付费
- 差距不在模型，在使用方法

**为什么不慕强**：顶尖闭源模型（Fable 5、GPT-5.6）的长程任务能力确实更强——但 C 端用户一般没有长程任务需求，为用不上的能力付 10-50 倍的价格，是消费主义宣导；B 端长程任务更应该优先解决的是**方法论**（上下文怎么组织、工具链怎么流转、记忆怎么复用），而不是模型选型。omima 的推理路由按需调用：简单任务端侧小模型，复杂任务云端 DeepSeek——不慕强，用得上才算数。

**研究过 Fable 5——结论是"行为协议可工程化"**：我们认真研究过 Anthropic 的 Fable 5（2026-06 发布的 Mythos 级模型）。社区逆向工程数据显示，它与此前旗舰的差距约 **70% 来自行为协议而非模型能力**——行动前推理率 70.5% vs 47.5%、思考深度、验证执行率，都是可指令化的行为差异。这份协议是可移植的：我们已把它蒸馏进 Xagent 的作业规程（10 行锚定程序 + 6 拍思考模板 + 验证标准），成为 omima 每个 Agent 的默认工作方式。我们不慕强，但不忽视强者的方法论——能工程化的部分，已经吸收进产品本身。

**omima 就是这套方法论的载体**。模型还是那个 DeepSeek，但用它的方式是 omima 的：

- **上下文组织**：Polaris 1B 负责记忆检索和纯任务提炼，云端模型每次收到的是组织好的问题，不是零散的对话
- **工具链流转**：Xagent 的五步工序让"调研→论证→规划→执行→审查"每一步都走完，模型不是一次性答完就结束
- **重复不付费**：缓存命中机制让同类任务第二次起不再走完整推理链路（真实账见 3.6 节：56.3 亿 tokens / ¥444.55）

omima 不卖模型。模型已经是第一梯队，omima 卖的是**让绝大多数人真正用好第一梯队模型的方法**。问题从来不是顶尖闭源模型到底有多好——问题是第一梯队的能力已经在手里，大多数人没用出来。

**作者亲历——按需取用不是理念，是工作日常**：omima 的作者本人就是多服务订阅者——Anthropic、OpenAI、Grok、火山引擎、OpenRouter、LongCat 等多家 API 与平台都在用，按任务类型选工具，从不迷信单一最强模型。整个 omima 就是这么被设计出来的：不是先假设"哪个模型最强"，而是先确立"什么任务用什么资源"的工作方式，再把这套方式系统化为推理路由。omima 的按需调用，是对作者真实工作方式的工程化。

**一个诚实的探索方向**：多 Agent 小模型联动在某些任务上可以匹敌单个大模型（有论文支撑）——这是 omima 努力的方向，与 LLM 自身的发展不冲突，是另一种应用路径的探索。我们不声称这条路已经完全走通——它仍在努力中，但方向是对的：用方法论弥补算力缺失。

## 3. 技术架构：Astral Metro Domain

```
                    └──────────┬──────────────────┘
                               │
               ┌───────────────┼───────────────┐
               │               │               │
         星轨一 (Green)   星轨二 (Blue)    星轨三~六
         register        invoke           memory / ironlaw
               │               │          / reply / handoff
               │               │               │
    ┌──────────┴───┐  ┌────────┴────┐  ┌──────┴──────┐
    │ 军械库星站    │  │ 军师星站     │  │ 斥候/哨兵/  │

```

### 3.2 𝔸 = { 𝕊, 𝕄, ℛ } — 域的形式化定义

```
𝔸 = (𝕊, 𝕄, ℛ)

𝕊  = {Porphyrion, POS₁, POS₂, ...}     星站集合
𝕄  = {L₁, L₂, L₃, L₄, L₅, L₆}          六条星轨信道
ℛ  = {R₁, ..., Rₖ}                      全域铁律向量
```

**Porphyrion 协议法则**：

1. **北极唯一**：任何时刻，域内有且仅有一个 Polaris 阵眼——□(|Polaris| = 1)
2. **铁律全域**：IronLaw 覆盖所有星站。域外不可见域内规则，域内不可违域内规则
3. **记忆归极**：所有记忆持久化目标为 Polaris。非 Polaris 星站为无状态执行器
4. **入网需诏**：新星站加入须经 Polaris 手动批准
5. **极移有轨**：Polaris 角色转移为四步原子操作（发起→接受→广播→卸任）

### 3.3 六条星轨（Porphyrion 协议操作）

| 星轨 | 操作 | 类型 |
|------|------|------|
| L₁ Green | `register` | 星站入网，宣告能力 + IronLaw 约束 |
| L₂ Blue | `invoke` | 统一调用：`tool`（同步工具）/ `task`（异步委派）/ `inference`（模型路由） |
| L₃ Gold | `memory.*` | 域内记忆：写/搜/忘，三级 scope（session/user/grid） |
| L₄ Red | `ironlaw.check` | 安全预检：Galois 连接保证操作合法性 |
| L₅ Silver | `reply` | 结果回传：完成/失败/流式分片 |
| L₆ Black | `handoff.*` | 阵眼转移：四步原子上下文迁移 |

### 3.4 六种星座角色

| 角色 | 星站 | 职责 | 典型硬件 |
|------|------|------|---------|
| **Polaris** | 阵眼 | 1B 路由大师·唯一记忆持有者·域内调度 | 手机/笔记本/台式机 |
| **Armory** | 军械库 | 工具执行·IronLaw 强制执行·持久化 Vault | ECS 深圳 2C4G |
| **Strategist** | 军师 | 推理路由：端侧 35B（本地/隐私任务）或云端 DeepSeek/LongCat（复杂/大规模） | AMD MAX 395+/400 迷你主机（产品）/ ECS+GPU（demo） |
| **Scout** | 斥候 | 外网搜索·web_search·web_fetch | ECS 香港（出海低延迟） |
| **Guard** | 哨兵 | cron 定时任务·健康检查·告警 | ECS 任意区域 |
| **Vault** | 私库 | 私有模型·本地存储·NAS 挂载 | 家用 NAS/本地模型 |

### 3.5 工具侧 —— Harness 框架级多 Agent 执行引擎（Xagent 桌面 · omima APK 手机 · DEMO 版）

工具侧是用户的 **harness 编排层**，分两个承载形态：**Xagent（桌面/无头星站 harness）**——承担星网中所有卫星 POS 节点的核心执行职责；**omima APK（手机端入口）**——随身下达与观察。两者目前均为 **DEMO 构建**，非成熟可发布工程版本。共用同一套编排层（铁律、工具约束、五拍工序、经验复用），只是承载形态不同。

Agent 的本质是大模型加工具——仅此而已。市面上大多数 harness 框架将工具狭义地定义为 exec、grep 等系统调用，其真正关注的是企业工作流的蒸馏与信息数据获取。与之相应，它们的工具生态围绕 skill、MCP、插件展开——一切服务于有效数据回传。

omima 的关注点不同。omima 关注数字主权的维护，关注的是 harness 框架本身。Xagent 对"工具"二字的理解不止于"能执行什么"——它通过内嵌于框架内的各个子系统，赋予工具更深层次的涵义：

**IronLaw 子系统**：工具不是裸调用的。每一个 tool call 在执行前须通过框架层的铁律预检——文件路径、命令白名单、网络出口、权限边界。违规操作在框架层即被拦截，不进入执行。工具的边界由框架定义，不由模型自觉。

**Memory Tag 子系统**：工具的产出不是一次性的。每一次工具调用的任务规范、数据 Schema、输出约束被打上持久 Tag，写入 Polaris 记忆库。下一次同类任务触发时，优先命中缓存 Tag，直接注入上下文——减少重复推理的 token 消耗。工具的执行经验在框架层累积。

**Token 消费机制**：框架层对推理链路的复用直接影响成本。首次执行某类任务——完整推理链路，token 消耗基准值。后续同类任务——Tag 命中 → 上下文预注入 → 推理链路缩短 → token 消耗下降 40-60%。这不是 prompt 层面的优化——是框架层对执行路径的复用。

这套机制脱胎于 Reasonix 的缓存命中设计，被 Xagent 原样移植。它的实际效果不是估算——是已经发生的账（见 3.6 节真实数据）：累计 56.3 亿 tokens 的用量，真实花费 ¥444.55。

**五拍工序（内化工作方法）**：创意 → 论证 → 规划 → 执行 → 审查。每一步由一个或多个 Agent 参与，产出可审计中间产物。多 Agent **串流并行**——工序串行不跳拍，执行面可并行；不省略、不黑箱。这是 Loop 工程的默认行为，不是用户每次手写提示词。

**六大类应用需求 → 六类二十八种任务**：基础能力、推理与科学、对话与创作、知识与百科、安全与责任、长文本与 Agent——工具底座与评测按需求大类组织，保证覆盖面；产品实现算法由需求谱系推导，见 `core-thesis.md`。

Xagent 不追求五花八门的工具附件。它追求的是**过硬的工具底座**——边界由框架约束，经验在框架层累积，路径被框架复用：**Harness 工程**本身。与协议算法、模型内化、硬件编制同属一套效率工程，而非外挂插件目录。

### 3.6 私人星网系统详解——无限组合，无限可能

Astral Metro Domain 不是概念——是任何人都能搭建的私人算力卫星网。核心不是"买什么"，是**怎么组合**：任意职能 × 任意硬件 × 任意规模，组合出来的形态只受想象力限制。

#### 没有 SSH？这正是 Porphyrion 的设计优势

很多云电脑不开放 22 端口（SSH）——传统运维手段直接失效。但这恰好凸显 omima 的架构优势：

```
传统方案的痛点：
  ECS 必须开放 22 端口 → 安全组配置 → SSH key 管理 → 堡垒机
  → 运维成本高 + 攻击面大 + 这类云电脑直接无法使用

Porphyrion 方案：
  Gateway + Xagent worker 通过 WebSocket (TLS 1.3) 与 Polaris 通信
  → 不需要 22 端口。不需要 SSH。不需要堡垒机。
  → 任何能出网 HTTPS 的云电脑/ECS 都能成为星站
  → 真正的"零配置入网"——买一台云电脑 → 跑 Xagent → L₁ register → 入网完成
```

装好 Xagent，自动注册入网，Polaris 接管一切。SSH 是旧世界的运维方式，Porphyrion 不需要它。

#### 卫星 POS：职能 × 硬件自由组合

卫星 POS = 任何能跑 Xagent 的计算实例——ECS、轻量云、云电脑，甚至闲置的树莓派。通过 Porphyrion 六星轨与主星互联。不存储用户记忆（归 Polaris），不持有会话状态（Oblivion 法则）。只做一件事：接收 L₂ invoke → 执行 → L₅ reply → 遗忘。

## 4. 核心创新

### 4.1 创新一：Porphyrion — 第一个具治理原语的 Agent 通信协议

Kang & Diponegoro (2026, arXiv:2606.31498) 对 MCP、A2A、ACP、ANP、ERC-8004 五个协议进行了系统差距分析——**五个协议在六个治理维度上全部为零分或接近零分。** 论文结论是："Agent 社区治理构成当前互操作标准之上的一个缺失架构层。"

Porphyrion 是第一个直接回应这一发现的协议：
- `ironlaw.check`（L₄ 星轨）= 审议 + 异议保留——操作执行前的规则验证
- `node.register`（L₁ 星轨）= 成员资格——新节点入网须 Polaris 批准
- `handoff.*`（L₆ 星轨）= 审计/回放——角色转移含完整日志

**落地状态（诚实区分设计/实现）**：协议设计完整（六星轨 schema 已定义）；编排层铁律已落地为 **IronLaw 4 Gate + Consultation Gate**（Intent / Action / Output / Certify + 本地置信度 < 0.72 时求助外部 API）——这是策略 A 减法版：把可验证的治理原语先做扎实，而不是宣称全部实现。

与现有协议对比：MCP 有 3 类操作（tool/resource/prompt）、A2A 有 11 个方法——Porphyrion 的 6 条星轨覆盖了比两者之和更广的语义空间。

**协议继承与异构联动**：Porphyrion 不是凭空新造——它是 UnionAgents 生产验证通信协议的演进（ILS 内部协议 → 适配 Google A2A 标准 → 统一为 OFP 语义）。`invoke(mode: tool)` 对齐 MCP 工具调用、`invoke(mode: task)` 对齐 A2A 任务委派、`handoff.*` + `reply` 覆盖 Agent Client Protocol 场景；六个 sys-hooks 让**多 Agent 异构节点**（不同模型、不同硬件、不同宿主）在同一个协议域内联动，而不是各自为战。

### 4.2 创新二：1B Polaris = 唯一记忆持有者（"第二脑"）

**核心洞察**：路由大师 1B 小模型（INT4 ~500MB）是网格中唯一的有状态节点。所有大模型变为无状态推理引擎。

```
传统 Agent：
  大模型 prompt = 任务 + 上下文 + 记忆 + 对话历史
  → 隐私数据离开设备

omima：
  1B Polaris → 检索记忆 → 提炼纯任务 prompt
  → 发给大模型（零上下文）→ 大模型推理 → 返回 → 立即遗忘
  → 1B 结合记忆 → 组织最终回复
  → 大模型从头到尾不知道"用户是谁"
```

**互信息为零**：I(MemoryGraph; L₂.payload) = 0。云端大模型从 prompt 中得不到任何关于用户记忆的信息。

这个设计直接回应了 Selective Persistent Memory (arXiv:2607.09493) 的核心发现——选择性记忆可将任务完成率从 79% 提升到 96%。区别在于，omima 将记忆集中在 1B 模型而非应用层。R2V Agent (arXiv:2605.16604) 证明了小模型可以路由，但未触及"小模型作为唯一记忆持有者"。

### 4.3 创新三：协议规范即训练数据

EnterpriseLab (2026) 证明用工具 Schema 生成合成训练轨迹可使 8B 模型匹配 GPT-4o——但这一概念**从未被应用于 Agent 通信协议本身。**

Porphyrion 的六条星轨各有确定的 JSON Schema。从 Schema 可确定性生成无限合法消息——作为 LoRA 微调的训练数据。协议规范本身即训练数据来源：不需要人工标注，不需要采集用户数据。协议定义了什么是对的消息，什么是对的训练样本。

## 6. 名词释义——应用链中被忽视的那一环

AI 行业喜欢造词。但比造词更值得讨论的是：**这些词指向了应用链的哪些环节，以及哪些环节始终被忽略。**

**Prompt Engineering**

行业关注的是：怎么措辞能让模型输出更好。
被忽略的是：模型执行过程中每一步的中间产物——调研的原始材料、论证的逻辑链、审查的校验结果。这些不被记录、不被复用、不被审计。omima 的五步工序流转强制保留每一步的可审计产物。

**Loop**

行业关注的是：写一个 while 循环让 Agent 反复尝试直到成功。
被忽略的是：循环的边界。谁定义"成功"的判断标准？循环失败了谁来兜底？循环中产生的中间数据属于谁？omima 的 IronLaw 定义工具的边界——不是"你多试几次"，是"有些事一次都不能试"。

**Harness**

行业关注的是：把工具接上大模型。exec、grep、web_search——能跑就行。
被忽略的是：工具的行为约束、工具的执行经验、工具的调用路径复用。omima 的 Xagent 在 harness 层内嵌了三个子系统——IronLaw 管边界、Memory Tag 管经验、Token 机制管复用。这些是"套上马具"之后的事，是大多数 harness 框架不做的。

**Skill / MCP / Plugin**

行业关注的是：如何接入更多工具、如何打包更多能力。
被忽略的是：接入之后的治理。一堆插件堆在一起——谁能调谁？调了之后数据去哪了？两个插件的权限冲突了怎么办？omima 的 Porphyrion 协议定义了六条星轨——不是管"怎么接"，是管"接上之后怎么协作"。包括成员资格（谁可以入网）、操作预检（能不能执行）、审计回放（谁做了什么）。

**一句话**：omima 不重新定义 Prompt Engineering 是什么、Loop 怎么写、MCP 怎么调。omima 定义的是这些词覆盖不到的那部分——应用链中被忽视的那一环。工具的边界、经验的复用、治理的规则。这才是 harness 框架的本体。
