# omima 核心思想（收敛定稿）

## 一句话

**omima 是一套完整的效率工程设计**：从**六大类应用需求**出发，用算法与系统把需求实现出来，再收敛为**三大要素**——系统化协议与算法、内化大模型的设置、内化的多 Agent 工作方法——最终交付**用户高满意度**的成果。Harness、Loop 工程与硬件编制，是同一套工程里的不同切面，不是外挂配件。

---

## 起点：六大类应用需求

产品不是先画异构图再找场景，而是**需求分类驱动实现算法**：

| # | 大类 | 用户侧要什么 | 系统侧必须长出的能力 |
|---|------|--------------|----------------------|
| 1 | **基础能力** | 可靠调用、读写、检索、执行 | 工具底座、权限边界、可复现路径 |
| 2 | **推理与科学** | 拆解难题、可检验的中间结论 | 军师岗位、论证步、可审计产物 |
| 3 | **对话与创作** | 连续语境下的生成与改写 | 记忆归属、上下文提炼、风格不泄隐私 |
| 4 | **知识与百科** | 查得到、连得上、可沉淀 | 记忆 Tag、知识内化、星站资料职能 |
| 5 | **安全与责任** | 越权不做、可追责 | 铁律 / 预检 / 拒绝可解释 |
| 6 | **长文本与 Agent** | 长程任务不失控、多步不丢线 | Loop 边界、工序串并行、handoff |

在此之上展开为更细的任务谱系（工程上称**六类二十八种**量级），用来组织工具底座与评测，而不是堆插件目录。

**推导关系**：

```text
六大类应用需求
    → 需要哪些协议原语、哪些模型岗位、哪些工序
    → 实现算法与系统落位（星网 / harness / 路由 / 硬件编制）
    → 三大要素收敛
    → 高满意度交付
```

## 系统形态：基于 AMD 算力底座的三层星网

omima 是一个**基于 AMD 算力底座设计的分布式异构星网系统**，分三层，层间用通信协议对接：

```text
┌────────────────────────────────────────────────┐
│ 第三层 · 模型层（按需取用）                     │
│   omima-1B 路由模型（常驻：记忆+路由）          │
│   9B / 35B 作业模型（按需拉起：CPU ECS 常驻 9B，│
│   GPU ECS 按需 35B）                            │
│   三个模型在 AMD MI300X (ROCm) 上调优后训练——  │
│   赛前 AMD 提供的算力准备；非产品运行配置       │
├────────────────────────────────────────────────┤
│ 第二层 · 星网 POS 层（低算力补充配置）          │
│   无状态 ECS / 云电脑节点跑 Xagent worker       │
│   （登记 · 执行 · 回传 · 遗忘）                 │
├────────────────────────────────────────────────┤
│ 第一层 · 工具侧 harness 编排层（DEMO 版）       │
│   Xagent（桌面编排，DEMO）·                     │
│   omima APK（手机端，DEMO）                     │
└────────────────────────────────────────────────┘
         ▲        通信协议（Porphyrion）         ▲
         └─ 稳定长连接 + 事件回调 ─┘
            无视云电脑「无 22 端口 / 无公网 IP」缺陷
```

| 层 | 是什么 | 承担什么 |
|----|--------|----------|
| **工具侧（harness 编排层）** | Xagent（桌面，DEMO）· omima APK（手机，DEMO） | 用户入口与编排：铁律、工具约束、五拍工序、经验复用 |
| **星网 POS 层** | ECS / 云电脑（CPU 级低算力） | 低算力补充配置：无状态执行节点，按能力登记、随取随用 |
| **模型层** | omima-1B 路由 · 9B/35B 作业 | 路由模型常驻，作业模型按需取用；岗位对应硅片。三个模型均在 AMD MI300X (ROCm) 上调优后训练——赛前 AMD 提供的算力准备，**非产品运行配置** |
| **通信协议** | Porphyrion | 稳定长连接 + 事件回调；**无视云电脑无 22 端口 / 无公网 IP 的缺陷** |

三层互补：工具侧管编排、POS 层补算力、模型层按需上岗；协议让异构设备真正组网——不是一台设备对抗超级单体，是**整个私人星网对抗一个超级单体**。

## 收敛：三大要素

### 要素一 · 系统化协议与算法

把「谁能入网、怎么调用、记忆归谁、何时拦截、如何回传、如何移交」收成**类型约束的协议与算法**（Porphyrion 星轨、编排层铁律、Gateway 事件与任务通道、路由与置信度门等）。

- 协作可复制：星站无状态、登记能力、按协议干活  
- 边界可执行：违规在框架层 DENY，不靠模型自觉  
- 状态可回放：事件与线程可审计  

没有这一层，多设备与多 Agent 只是一堆聊天窗口。

### 要素二 · 内化大模型的设置

模型不是买来即用的黑盒，而是**按岗位内化**的设置：

| 岗位 | 体量 | 内化什么 |
|------|------|----------|
| 阵眼 | 1B | 路由、记忆防火墙、任务提炼（无隐私载荷出站） |
| Worker | 9B | 工具协议、sys-hooks 行为、跟手执行 |
| 军师 | 35B 级 | 深拆解、岗位工具链、可服务的精度/吞吐设置（如 FP8 工作点） |

训练、量化、服务参数，都是**内化设置的工程手段**——发生在 AMD MI300X 等底座上，是为了岗位上岗，不是效率工程的终点。

### 要素三 · 内化的工作方法设计

把高质量交付的工序**写进系统默认行为**，而不是依赖用户每次提示「请先想清楚再做」：

| 拍 | 名称 | 要产出什么 |
|----|------|------------|
| 1 | **创意** | 问题空间、素材与方向（含调研与发散） |
| 2 | **论证** | 取舍理由、风险与否证 |
| 3 | **规划** | 可执行步骤、依赖与并行面 |
| 4 | **执行** | 工具调用与中间产物 |
| 5 | **审查** | 对照目标验收、修正或回退 |

多 Agent **串流并行**：工序可串（不跳拍、不黑箱），步骤可并（多星站 / 多工具同时跑）。每一步留下可审计中间产物——这是 **Loop 工程** 的本体：循环有边界、有成功判据、有兜底，而不是 `while true` 碰运气。

**Xagent** 作为 harness：工具前铁律、经验 Tag、路径复用、工序驱动——**Harness 工程**与 Loop、协议同一套效率设计。

## 效率工程全图（三切面）

```text
                    六大类应用需求
                           │
           ┌───────────────┼───────────────┐
           ▼               ▼               ▼
    协议与算法        模型内化设置      工作方法（五拍）
    (系统)            (1B/9B/35B)      (创意→审查 · 串并)
           │               │               │
           └───────────────┼───────────────┘
                           ▼
              ┌────────────────────────┐
              │  效率工程运行时         │
              │  Harness · Loop · 硬件  │
              └────────────────────────┘
                           │
                           ▼
                 用户高满意度交付成果
```

| 切面 | 管什么 | omima 落点 |
|------|--------|------------|
| **Harness** | 工具怎么被约束、经验怎么累积、调用怎么复用 | Xagent + IronLaw + Memory Tag + 缓存命中 |
| **Loop 工程** | 多步如何不失控、串并行如何编排、审查如何闭环 | 五拍工序 · 多 Agent 串流并行 · 铁律与置信度门 |
| **硬件** | 算力与隐私落在哪、岗位落在哪类硅片 | 端侧 + 星罗棋布；1B/9B/35B 编制；MI300X 养模型与验证 |

三者缺一：只有模型没有 harness → 行为靠自觉；只有 loop 没有协议 → 多机协作乱；只有硬件没有方法 → 贵算力空转。

---

## 最终判据

**用户高满意度的交付成果** = 需求被六大类覆盖、路径可审计、边界不越权、重复工作不重复付代价、长程任务能走完五拍。

评分场上的本地推理与 ROCm 数字，是**要素二 + 硬件切面**的可复核切片；应用与 Agent 完整性，由**要素一 + 要素三 + Harness/Loop** 承载。整包叙事以本文件为收敛点。
