Problem

Two Camps, Both Broken

Thin Chat Wrappers
Forward messages to an API, stream tokens back. No real tools, no file system, no memory beyond the context window. Glorified API clients wearing an "Agent" label.

The gap: There's no lightweight, private, truly-capable agent that runs entirely on your desktop — especially one that leverages local AMD Radeon GPU for inference.

Context Management

Triple Safety Net

Reactive Trim
Trigger: API returns context-too-long error.
Action: Halve token budget, trim from head, retry current turn once.
Prevents crashes, not data loss.
History Compaction
Trigger: History exceeds budget.
Action: LLM summarizes early turns into a compact message; tail preserved intact.
Linear context becomes bounded.
Orphan Cleanup
Trigger: After any trim.
Action: Remove tool results whose calling assistant message was trimmed away.
Prevents invalid API calls.
Why this matters: The differentiator between a demo agent and one you can use for hours without crashing. DirectV2 also uses these mechanisms to keep complex multi-step tasks stable.

Security

Defense in Depth

① Three-Tier Sandbox
readOnly (read cwd only) / workspaceWrite (write cwd only) / fullAccess. Configurable per-conversation.
② Shell Confirmation Bridge
Dangerous commands trigger confirmation modal in UI; main process parks resolver in pendingConfirms map until user approves.
③ SSRF Protection
Blocks private IPs (10.x, 172.16-31.x, 169.254.x, 192.168.x), cloud metadata endpoints, DNS rebinding attacks.
④ File Snapshot + Encrypted Secrets
Every write_file/edit_file snapshots original to .kinet-snapshots/. API keys encrypted via safeStorage (Windows DPAPI / macOS Keychain / Linux libsecret).
Local-first security: With AMD Radeon GPU inference, sensitive code never leaves your machine — the strongest security guarantee of all.

Token Efficiency

Less Context = Faster GPU

Per-Need Plugin Injection
Only tools matching keyword patterns get injected each turn. ~60% fewer input tokens vs. injecting all tools every turn. GPU has less to attend to → faster generation.
Hybrid Memory Retrieval
FTS5 + embedding top-K injects only relevant memories. ~80% fewer tokens vs. full injection. Falls back to FTS5-only if embedding model unavailable.
Context Compaction
LLM summarizes old turns when history exceeds budget; tail preserved intact. Linear growth becomes bounded. Prevents the slow-down spiral on long sessions.
Prefix Caching
System prompt + early history stay stable across turns. Ollama/OpenAI auto-cache the prefix. Redundant GPU computation eliminated on long sessions.
Compound effect: These four optimizations together mean a KinetAios agent on a Radeon RX 7800 XT running Qwen2.5-14B delivers near-real-time responsiveness even on hour-long sessions.

Defensive Q&A

Q: How does KinetAios differ from Claude Code / Codex CLI?
KinetAios wraps Claude Code and Codex as engines but also ships its own self-built ReAct engine. The Direct engine uses in-app tools that the CLI engines don't have access to (snapshot rollback, three-tier sandbox, FTS5 memory). Plus you can switch engines mid-project without losing memory.
Q: Why a local Radeon GPU matters for "private AI agent"?
Zero data leaves your machine — code, prompts, memory, tool outputs all stay local. API keys never exposed to third-party infrastructure. Full control over model selection and quantization. Works offline.
Q: Is the DirectV2 4-layer engine overengineered for simple tasks?
No — DirectV2 auto-degrades to single-turn ReAct for simple tasks (skipping planning entirely). The 4-layer overhead only kicks in when the task genuinely benefits from verification.
