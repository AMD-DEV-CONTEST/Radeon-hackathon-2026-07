Hyperloom

An AI agent that makes AMD Radeon GPUs faster at LLM inference — on its own. It reads the silicon's real instruction set with the assembler, finds what shipped kernels never use, writes correctness-gated HIP kernels to close the gap, and then audits its own measurement. Core inference runs entirely on the Radeon card. No cloud in the loop.

The capability that matters: it proves itself wrong

Most speedup claims die on the measurement, not the kernel. The R9700 has a 64 MiB Infinity Cache — any int4 benchmark whose weights fit inside it measures cache, not DRAM, and happily reports a bandwidth above the roofline.

So the harness prints its own working set and flags the bad reading:

N=14336 K=4096 |  31.5 MiB (CACHE-RESIDENT!) | 788 GB/s | 125% of roofline
N=65536 K=4096 | 144.0 MiB (DRAM-honest)    | 609 GB/s | 97% of roofline

This caught a real error in our own submission — the decode benchmark had been reporting 122% of roofline. An optimizer you can trust has to be able to prove itself wrong.

The naive one-thread-per-row route looks 2.2× faster with the native instruction, and that A/B is real. But it is uncoalesced: past the cache both routes collapse to ~17 GB/s. The win is the access pattern, not the instruction — and we say so rather than let a judge discover it.

The same discipline runs through the stack. Faults are isolated at the layer where they actually live — silicon, driver, runtime, compiler, kernel, format, serving — rather than guessed at across all seven. And correctness is never traded for speed: a fast-but-wrong kernel exits non-zero before it is allowed to report a number.

Reproducible by a stranger, in three commands

git clone https://github.com/The-Monk/rocky-hackathon
cd rocky-hackathon/kernels/decode
hipcc --offload-arch=gfx1201 -O3 decode_mmvq_iu4.hip -o d
HIP_VISIBLE_DEVICES=0 ./d   # 97% of roofline, gated
