# Recording the MedGlass demo with physical glasses

A fully automated 91s capture already exists at `demo/medglass_demo.mp4`
(glasses-POV feed → photo + medication OCR → Patient Note → dashboard, with a
ROCm GPU-proof segment). This guide covers re-recording with the **physical
glasses + real camera/mic** on the logged-in GNOME desktop.

## One-time: authorize screen capture (the portal click)

GNOME Wayland requires you to click the screen-share dialog once per OBS launch.

1. `python3 demo/obs_ctl.py --start`
   - OBS starts headless-in-tray on a 1920x1080 "Demo" profile/scene with a
     `pipewire-screen-capture-source` named `Screen`.
   - A **"Select what to share"** dialog appears — click your monitor, then
     **Share**. (If it does not appear, click the OBS tray icon and open
     Settings → Sources → Screen → Properties.)
2. Verify it captured: `demo/obs_ctl.py --status`, or start a 5s test
   (`demo/obs_ctl.py --start`, wait, `--stop`) and open the mp4 in `~/`.

## Record the physical-glasses demo

1. Plug in the glasses; confirm the camera appears in `ls /dev/video*`.
2. Open `https://copilot-unstaffed-smuggling.ngrok-free.dev/live` in a browser
   (login `amdje` / password set via `python3 scripts/add_user.py amdje '<password>' --role admin`).
   Note: the tunnel URL, not localhost — the tunnel is
   already exposing the app.
3. Start a terminal running the GPU VRAM monitor:
   `watch -n 1 "rocm-smi -u --showmeminfo vram --showpids"`.
   (On the R9700 the GPU-use% line is unavailable/unstable — VRAM used and the
   per-process KFD line under it are the live proof: it climbs as weights load.)
4. `python3 demo/obs_ctl.py --start` (recording begins).
5. In the browser: **Start session** (camera + mic), speak a line like
   *"the patient took two hundred milligrams of ibuprofen this morning"*, then
   **Capture** (photo → medication OCR), then **Stop session** (Patient Note
   generated by the LLM on GPU — watch the VRAM climb in the rocm-smi terminal).
6. Open `/dashboard` and click the newest Patient Note card.
7. `python3 demo/obs_ctl.py --stop` (recording ends in `~/2026-*.mp4`).
8. Optionally run the benchmark table on-screen during the GPU segment:
   `.venv/bin/python demo/gpu_summary.py` in a visible terminal.

## Notes

- GPU-use% can read flat on this card even under load (Navi 48 has no
  GPU-busy counter in the kernel driver). The reliable, moving GPU proof is
  **VRAM used** (`rocm-smi -u --showmeminfo vram`: ~1.1 GiB idle → ~17 GiB when
  the 27 B model loads) plus per-process residency (`rocm-smi --showpids` shows
  the llama-cli process holding ~16.8 GiB) and the benchmark speedups:
  whisper **6.3×**, LLM **3.6× wall / ~5.3× tok/s** (`demo/gpu_summary.py`).
  The recorded demo already shows the VRAM line climbing to 18.4 GiB live.
- For the auto-generated capture, `demo/obs_ctl.py` is a websocket controller
  (v5 RPC; two-step SHA-256 auth; password `medglass-demo`, port 4456). It does
  `CreateScene` / `CreateInput` / `StartRecord` / `StopRecord`.
- Assemble intro + capture + outro the same way the auto video was made:
  `ffmpeg -i intro.mp4 -i demo_raw.mp4 -i outro.mp4 -filter_complex
  "[0:v][1:v][2:v]concat=n=3:v=1:a=0[out]" -map "[out]" -c:v libx264
  -preset veryfast -crf 18 -pix_fmt yuv420p final.mp4`.
