# TeaQL KSML Error Fixes

| Rule ID | Explanation & Fix |
|---------|-------------------|
| `KSML-STRUCTURE-001` | **Nested Object Definition**. You placed an object tag INSIDE another object tag (e.g. `<school target="school()"/>` inside `<platform>`). In KSML, object definitions CANNOT be nested. All `<foo>` object definitions must be direct children of `<root>`. To define a relationship, use an attribute like `platform="platform()"` on the child object instead of nesting XML tags. Remove any nested relationship tags. |
| `KSML-LOG-004` | **Missing user field**. A logging object (like `audit_log` or `activity_log`) MUST include a user/operator field. **CRITICAL**: Do NOT use `operator` as it is a reserved keyword in some languages. Use `created_by`, `actor`, or `user` instead. |
| `KSML-KEYWORD-002` | **Reserved keyword**. The field name you used conflicts with language reserved keywords (e.g., `operator`, `type`, `class`). Rename the field to a non-reserved equivalent. For user fields, use `created_by` or `actor`. For types, use `record_type`. |
| `KSML-XML-005` | **Parse Error / Cyclic Dependency**. If you see "Empty Attribute", you left an attribute empty (e.g., `company_name=""`). Provide a valid type definition like `company_name="string()"`. If you see **"find with OD: ... reaches 20"**, it means there is an infinite cyclic dependency between objects. **CRITICAL FIX**: Check constant objects (like `language_type`, `project_status`, etc.) and ensure they DO NOT reference business objects (like `teaql_project`). Remove the business object attributes from your constant objects to break the `business_object -> constant -> business_object` recursion. |
| `KSML-GRAPH-001` | **Cyclic Dependency (DAG Violation)**. KSML requires the object reference graph to be a Directed Acyclic Graph. If you see a chain like `A -> B -> A`, you MUST break it. Find the less critical direction of the relationship and either remove it entirely or replace the reference `b="B()"` with a plain string identifier like `b_id="string()"`. Do NOT keep bidirectional object references. |
