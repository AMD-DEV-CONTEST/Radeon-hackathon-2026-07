# ⚒️ MeshSmith — a local 3D asset foundry

**Text or image in → print-ready & game-ready 3D assets out. Fully local, on AMD Radeon.**

MeshSmith is a multimodal content-creation tool that chains three open models —
SDXL-Turbo (text→image), u2net (subject cutout) and Hunyuan3D-2 (image→3D) — and then
does what generators never do: it makes the result **usable**. Every asset comes out

- **cleaned & repaired** — floaters removed, holes filled, normals fixed, watertight-verified
- **game-ready** — decimated to a target budget, xatlas UV-unwrapped, PBR material, GLB
- **print-ready** — scaled to real millimeters, **auto-oriented to minimize support material**,
  wall-thickness sampled, bed-fit checked, exported as STL with a printability score
- **accountable** — a machine-readable + human-readable report with per-stage GPU timings

No cloud APIs anywhere in the pipeline. Everything runs on your own GPU.

*Inset = the generated concept image, large = the finished mesh. Bottom-left is the

> Built for the **AMD AI DevMaster Hackathon — Track 1 (Multimodal Content Creation)**.
> Shape generation is deliberately *shape-only* Hunyuan3D: pure PyTorch, no custom CUDA
> extensions, so the identical code runs on **ROCm** and CUDA.

## Why

Image→3D models produce impressive meshes that fail the moment you use them: not watertight,
no UVs, floating debris, million-face density, no physical scale, and orientations that
drown an FDM print in support material. MeshSmith is the missing last mile — the difference
between "look at this mesh" and "here is the STL your slicer accepts".

## Pipeline

```
 prompt ──► SDXL-Turbo ──► u2net cutout ──► Hunyuan3D-2 DiT ──► repair ──► ┬─► decimate + xatlas UV + PBR ──► GLB / OBJ (game)
            (skip if an image is supplied ──────────►)                     └─► scale-to-mm + auto-orient + wall check ──► STL (print) + report
```

All GPU stages use the portable `torch.cuda` API — on ROCm builds of PyTorch the HIP
device is exposed through the same API, so there is **zero vendor-specific code**.

## Quickstart — AMD ROCm (Linux / Radeon Cloud)

```bash
# inside any recent rocm/pytorch container (Radeon Cloud: pick a rocm/pytorch image)
git clone <this repo> meshsmith && cd meshsmith
# headless/slim images only: opencv (a Hunyuan3D dependency) needs system OpenGL
apt-get update && apt-get install -y libgl1 libglib2.0-0
pip install -r requirements.txt        # torch + torchvision come from the container
python app.py --host 0.0.0.0 --port 7860
```

Or let `scripts/radeon_cloud_setup.sh` do all of the above in one command.

Or with Docker:

```bash
docker build -f docker/Dockerfile.rocm -t meshsmith:rocm .
docker run -it --device=/dev/kfd --device=/dev/dri --group-add video \
  -p 7860:7860 -v hf-cache:/root/.cache/huggingface meshsmith:rocm
```

First run downloads open weights from Hugging Face (~9 GB total: SDXL-Turbo fp16,
Hunyuan3D-2 fp16, u2net ONNX). The header banner reports the backend it actually
detected — on a ROCm box it reads `AMD ROCm <version>` with your Radeon's name, which
is also what the per-run `report.json` records.

## Quickstart — NVIDIA (dev box)

```bash
python -m venv .venv && .venv/Scripts/activate   # or source .venv/bin/activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
pip install -r requirements.txt
python app.py
```

`torchvision` is required as well as `torch` — Hunyuan3D imports it at load time.
Install both from the same platform index (ROCm users swap `cu124` for `rocm6.2`);
installing `torchvision` from plain PyPI would pull a CUDA/CPU torch over your ROCm build.

## CLI & tooling

```bash
python -m meshsmith.cli "a chess knight piece, ornate baroque style" --quality standard
python -m meshsmith.cli --image photo.jpg --quality high --height-mm 120 --material metal

python scripts/smoke_test.py                      # model-free check of the mesh stack, ~5 s
python scripts/benchmark.py --quality standard    # regenerates docs/benchmark.md
python scripts/build_gallery.py                   # contact sheet of every asset generated
python scripts/render_asset.py outputs/<run>/x.glb --turntable 24 --out frames/
python scripts/record_demo.py --url http://127.0.0.1:7860   # records a 1080p UI session
python scripts/build_pdfs.py                      # docs → project-profile.pdf, poster.pdf
```

`smoke_test.py` needs no GPU and no model weights — it drives the repair, decimation,
UV, orientation-search and export stages on synthetic geometry, so it works as a CI gate.

## Quality presets

| Preset | Image stage | Shape model | Steps / octree | Typical use |
|---|---|---|---|---|
| `draft` | SDXL-Turbo 512·1-step | Hunyuan3D-2 **mini-turbo** (0.6 B) | 8 / 256 | iteration, ~seconds |
| `standard` | SDXL-Turbo 768·4-step | Hunyuan3D-2 (1.1 B) | 30 / 384 | default |
| `high` | SDXL-Turbo 1024·4-step | Hunyuan3D-2 (1.1 B) | 50 / 512 | final assets |

## Outputs

Each run writes `outputs/<timestamp>_<slug>/`:

| File | What it is |
|---|---|
| `concept.png` / `cutout.png` | generated image and the RGBA cutout fed to 3D |
| `<slug>.glb` | game-ready: decimated, UV-unwrapped, PBR material |
| `<slug>.obj` | same mesh, OBJ |
| `<slug>_print.stl` | print-ready: mm scale, support-minimizing orientation |
| `report.md` / `report.json` | printability score, wall stats, bed fit, timings |

`--height-mm` sets the model's own height. Auto-orientation then only *rotates* the
part to whichever face costs the least support, so the physical size is preserved and
the report lists both the requested height and how tall it stands on the bed.

## Dependencies

Python ≥ 3.10 · PyTorch ≥ 2.4 (ROCm or CUDA build) · see [requirements.txt](requirements.txt).

`tencent/Hunyuan3D-2`, `tencent/Hunyuan3D-2mini`, u2net.
