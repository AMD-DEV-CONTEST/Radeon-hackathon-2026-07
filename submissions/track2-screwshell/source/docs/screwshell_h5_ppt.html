Problem

敏感材料，不能上云，但审阅又慢又容易漏

知识工作者积累了大量设计文档、合同、代码库、会议笔记 —— 这些内容不能上传到云端 AI， 人工逐份审阅却耗时且容易遗漏关键风险。

🔒

隐私红线

合同 / 代码 / 会议纪要属敏感资产，上传云端 = 不可接受的泄露风险。

⏱️

人工低效

跨多份文档的多步调查，人工检索、比对、引用，既慢又易漏。

🧩

多技能缺失

一次调查常需「代码 / 安全 / 文档」多种技能，传统方案各开一套模型。

Why ScrewShell

三个与众不同的设计理念

🛡️

默认私有

推理、嵌入、检索、记忆全部本地；六种只读工具全部本地，零远程 API、零遥测。

🎛️

MoL 单基座多技能

一个冻结 27B 基座 + 多个 LoRA 专家，在常驻基座上热切换；社区专家即插即用。

📋

证据型答案

每条结论配证据卡（文件/行引用 + 置信度 + 审计轨迹），可随时复验。

六种只读工具：rag_search · read_file · list_dir · grep · shell_readonly · rocm_smi —— 全部沙箱化、受权限门保护。
