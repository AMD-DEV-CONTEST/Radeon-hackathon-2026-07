1.Problem Statement

Financial quantitative research has traditionally been the exclusive domain of institutional teams with specialized talent and infrastructure. This exclusivity is sustained by three compounding barriers:

  • Domain expertise — Designing effective alpha factors requires deep financial knowledge, an intuition for market microstructure, and years of research experience.
  • Programming skills — Translating a factor hypothesis into correct, performant code demands proficiency in Python, numerical libraries, and backtesting frameworks.
  • Backtesting infrastructure — Validating factor performance requires historical data pipelines, execution simulation, and rigorous statistical evaluation — resources typically out of reach for individual investors.

Beyond the technical barrier, a more fundamental concern exists: financial data is sensitive. Sending proprietary trading strategies, portfolio positions, or bespoke datasets to cloud-hosted LLM APIs raises serious privacy and intellectual-property risks. The data leaves the user's control, traverses third-party infrastructure, and may be retained or observed in ways the user cannot verify.

The gap: Individual investors and small research teams need a way to leverage large-language-model reasoning for quantitative research without surrendering their data to the cloud, without hiring a full quant team, and without standing up complex infrastructure from scratch.

2.Solution

aiQuant is a fully private AI Agent that automates the entire quantitative factor-mining workflow through natural language. A user describes a research intent in plain English or Chinese, and the Agent autonomously drives a complete research-and-development loop.

The pipeline operates as follows: the Agent generates a hypothesis from the user's intent, writes the factor code in Python, runs a Qlib backtest against historical A-share market data, and reviews the results — iterating until the factor meets performance thresholds or the exploration budget is exhausted.

Critically, every LLM inference call executes locally on an AMD Radeon GPU via the ROCm compute platform. No prompt, no factor logic, and no market data ever leaves the host machine. This design directly resolves the privacy tension identified in the problem statement while still delivering the generative reasoning power of an 8-billion-parameter language model.

3.Key Features

  • Natural language → factor mining — Users describe research intent in Chinese or English; the Agent handles the rest. No code required to initiate a study.
  • Automated R&D loop — A closed cycle of hypothesis → code → backtest → review → iterate, orchestrated by Microsoft RD-Agent, requires no manual intervention between stages.
  • Multi-stock-pool support — Dynamic instrument files for CSI 300, CSI 500, SSE 50, and the full A-share universe can be selected at run time.
  • 100% local LLM inference — Qwen3-8B runs on an AMD Radeon GPU via ROCm at approximately 90 tokens/s with zero data egress.
  • SSE real-time streaming — Server-Sent Events push live progress, generated code, and backtest metrics to the frontend as they happen.
  • Qlib backtesting — Full evaluation suite reporting IC, ICIR, annualized return, and maximum drawdown per candidate factor.
  • Hash embedding fallback — A deterministic local embedding scheme ensures the pipeline runs even when no external embedding API is configured.
  • Visual dashboard — A Streamlit interface surfaces factor statistics, equity curves, and research logs for at-a-glance review.

4.Technical Architecture

aiQuant is built as a layered system in which each tier has a clear responsibility. The frontend communicates with a FastAPI backend over HTTP and SSE; the backend delegates research orchestration to RD-Agent, which in turn calls the local LLM and the Qlib backtesting engine.

Frontend
React SPA — Vite + Tailwind CSS. Renders streamed Agent output, factor code, and backtest metrics in real time.
Backend
FastAPI + uvicorn — Python async server on port 8010. Exposes REST endpoints and an SSE stream for live progress.
AI Engine
Microsoft RD-Agent — Drives the automated R&D loop: hypothesis generation, code synthesis, execution, and result review.
Backtesting
Qlib — Microsoft quantitative platform providing factor evaluation, IC/ICIR computation, and return simulation.
LLM
Qwen3-8B via Lemonade SDK / llama-server on AMD Radeon GPU. Quantized to Q4_K_M for efficient VRAM usage.
LLM Routing
LiteLLM — OpenAI-compatible interface that routes completions to the local server with custom Qwen3 thinking-mode patches.
Data
A-share market data — 通达信 (TDX) CSV files imported and converted into Qlib's binary format for high-performance access.
Task Queue
Celery + Redis (optional) — Asynchronous job execution for long-running research loops, decoupled from the request cycle.

5.1  How the pieces fit together

  • ROCm compute platform provides the low-level GPU kernels and HIP runtime that the inference engine compiles against, enabling native AMD hardware acceleration without proprietary vendor lock-in.
  • Lemonade SDK offers a high-level, AMD-first inference server that loads the Qwen3-8B model, manages the KV cache, and serves completions over an OpenAI-compatible HTTP endpoint.
  • Q4_K_M quantization compresses the 8B model to roughly 4.7 GB of VRAM, allowing it to run comfortably on mainstream Radeon cards while preserving generation quality suitable for factor-code synthesis.
  • Zero data egress — Because the inference server binds to localhost, every prompt and every completion remains on the host. No telemetry, no cloud relay, no shared inference pool.
Measured throughput: Approximately 90 tokens/s on the target Radeon GPU — fast enough to sustain an interactive Agent loop where the user sees streamed reasoning and code in real time.

6.Innovation Points

  1. Local-first privacy. All LLM inference runs on the GPU; no data leaves the device. This is the defining differentiator versus cloud-based quant assistants and directly addresses the sensitivity of financial data.
  2. Qwen3 thinking-mode handling. Custom monkey-patches for litellm.acompletion transparently disable Qwen3's thinking mode and fall back reasoning_content into content — ensuring RD-Agent receives clean, parseable completions without leaking internal chain-of-thought tokens.
  3. Hash embedding fallback. When no external embedding API is available, a deterministic hash-based embedding scheme generates consistent vectors locally, keeping the full R&D pipeline operational in a strictly air-gapped environment.
  4. Cross-platform compatibility. The same codebase runs on macOS for local development and on Ubuntu / Radeon Cloud for production inference, so research prototypes graduate to deployment without rewrites.
  5. Multi-stock-pool support. Dynamic instrument-file deployment lets a single backtest run target CSI 300, CSI 500, SSE 50, or the entire A-share universe simply by selecting a pool — no code changes required.

7.Privacy & Security

Privacy is not a feature layered on top of aiQuant — it is the architectural premise. The system is designed so that a privacy-conscious user can verify, by inspection of the network configuration, that no research artifact ever leaves the machine.

  • 100% local LLM inference. The Qwen3-8B model is served from localhost via Lemonade / llama-server. The inference socket never binds to a public interface.
  • No external API calls — except an optional embedding API that the user may configure explicitly. When omitted, the hash embedding fallback is used and the system is fully air-gapped.
  • .gitignore hygiene. All sensitive files — .env, API keys, credentials, and local market data caches — are excluded from version control by default.
  • Local data residency. All market data (TDX CSVs and Qlib binaries), factor code, and backtest results are stored on the host filesystem and never transmitted off-device.

8.Future Work

aiQuant's current scope centers on single-agent, single-stock-pool factor mining with a local 8B model. Several directions extend the platform's depth and breadth:

  • Broader factor taxonomy — Extend beyond the current factor classes to support cross-sectional, time-series, and alternative-data factors (news sentiment, satellite imagery, supply-chain signals).
  • Multi-agent collaboration — Introduce specialized agents — a fundamental analyst, a risk manager, and a portfolio optimizer — that debate and refine factors in concert rather than in isolation.
  • Real-time market data integration — Connect live market feeds so factors can be monitored intraday and re-evaluated as new bars arrive, moving from batch research toward live signal generation.
  • Model evolution — Automate architecture search across LGBM, GRU, and Transformer prediction models, allowing the Agent to select and tune the model best suited to each factor family.
