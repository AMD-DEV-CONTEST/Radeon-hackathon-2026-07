1. Application scenario

People increasingly say, “I gave my whole computer to my AI.” Useful AI needs permission if it is going to take work away from people—but permission must not mean silent control.

Product promise. Broad visibility. Deliberate action. Evidence for every decision. PrivateOps observes supported computer and project state, defaults to read-only behavior, and requires a second exact-action confirmation before any supported side effect.

User problem

Keeping inference local is not enough. Users need to inspect what the Agent saw, which tools ran, what it remembered, and whether a request crossed a permission boundary. “Whole-computer permission” means broad supported observation, never unrestricted administrator access.

Target users

Independent developersRelease audits, competition packaging, repository inspection, and reproducible checks.
Small private teamsLocal knowledge operations where source code, credentials, and internal plans cannot leave the workspace.

Distinctive value

  • Windows exposes seven fixed read-only system collectors; Radeon Cloud exposes private project and runtime observation.
  • `safe`, `confirm`, and `blocked` decisions remain visible with one-use confirmation tokens and audit IDs.
  • All five Track 2 capability categories are demonstrated in one coherent workflow.

Failure behavior

Malformed and oversized requests receive stable errors. Non-loopback competition endpoints, path escape, shell metacharacters, expired or reused confirmation tokens, and unsupported verified benchmark claims are rejected. ROCm mode never silently falls back to development output.

Agent framework

PrivateOps uses LangChain Core `StructuredTool` adapters as its open Agent tool framework. Each adapter delegates to the existing permission-aware registry, so framework integration does not bypass path confinement, exact-action confirmation tokens, allow-listing, structured results, or audit recording.

Interaction design

The Local Trust Console leads with the user task but keeps proof adjacent: permission and runtime posture on the right, evidence and plan below, then the audit ledger and Radeon proof. Its explicit Remote model / Local ROCm selector keeps separate browser-local profiles: remote requires a key, while Local ROCm restores the loopback Qwen defaults and accepts an empty key. The interface is responsive, keyboard-focusable, and honors reduced-motion preferences.

4. Model and local deployment

Competition mode runs an open-weight instruct model through vLLM on a loopback endpoint inside the same Radeon Cloud instance as PrivateOps.

ModePurposeRuntime contract
Remote modelOptional product integration testing on ordinary computers.Absolute HTTP(S) endpoint and API key required.
Local ROCmROCm vLLM on `127.0.0.1` in the same instance.Loopback required; API key optional; verified on Radeon.

Default model profile

`Qwen/Qwen2.5-7B-Instruct` is the shared competition default. vLLM serves it on `127.0.0.1:8000` with an 8,192-token context and 0.85 GPU-memory utilization. The model is Apache-2.0 licensed and remains configurable when the selected cloud image requires another compatible open artifact.

Privacy boundary

  1. The browser talks only to the PrivateOps service.
  2. The service retrieves files only from the configured workspace.
  3. The service calls the model on a validated loopback URL.
  4. API keys are omitted from status, audit, and browser responses.
  5. Core behavior does not call shared public model APIs.

Reproducibility

The repository provides separate commands for the ROCm model server, application, benchmark collector, tests, smoke check, and final material validation. The cloud runbook includes `rocminfo`, HIP, PyTorch, endpoint, tunnel, and evidence commands.

5. Radeon optimization and measurement

A verified same-instance run captured AMD Radeon Graphics (`gfx1100`), ROCm 7.2.1, ROCm vLLM, and Qwen2.5-7B-Instruct. Submission metrics are generated from the immutable machine record.

Implemented optimization

  • 8,192-token context and 0.85 GPU-memory utilization preserve predictable headroom.
  • Loopback transport keeps prompts local and avoids public-network latency.
  • Top-k RAG, environment-directory exclusion, bounded inventory samples, and a 25-item list limit reduce model context.
  • Temperature zero improves repeatability during evidence collection.
