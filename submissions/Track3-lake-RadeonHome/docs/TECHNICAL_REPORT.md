# RadeonHome: Failure-Aware Mobile Manipulation on AMD Radeon GPUs

## 1. Application

RadeonHome studies a household transport task: start from a varying room pose,
navigate to an object, physically grasp it with Franka, carry it to a semantic
destination, and release it safely. The target scenario is small-space home
organization, such as moving a waste package to a bin or keys to a tray.

## 2. System architecture

```text
Local Qwen task explanation
          ↓ (non-executable text)
Deterministic task schema + safety constraints
          ↓
A* room planner + docking transform
          ↓
Genesis mobile Franka physical controller
          ↓
Contact / slip / placement verification → regrip or failure record
          ↓
RGB + depth + MP4 + JSON evidence dashboard
```

## 3. Methods and technical contributions

1. **Safe fixed-to-mobile asset migration.** The fixed tabletop-mount
   `link0_c` shell is replaced by a ground-level chassis proxy aligned to the
   navigation footprint. Seven arm links, the hand, and official fingertip
   collisions remain active. Three failed geometries are retained as evidence.
2. **Room-to-arm coordinate bridge.** A planar root is generated around the
   official Franka MJCF and semantic docking poses are transformed into the
   MJCF world frame.
3. **Physical-contact evaluation.** The project does not use a weld, latch,
   teleport, or programmatic payload attachment for its physical-contact
   claims. Official fingertip geometry, friction, contact force, lift height,
   payload distance, and bowl placement are measured.
4. **Failure-aware carrying.** Continuous hand-relative drift monitoring can
   stop transport, regrip while stationary, and record a failure reason.
   Heavy/tall profiles may use a retractable collision-based support tray.
5. **Auditable interaction.** A local Qwen3-4B service interprets language,
   while a deterministic task schema remains the safety boundary. The web
   dashboard exposes live Genesis RGB/depth previews and the exact artifacts
   generated by each experiment.

## 4. Data and evaluation

No proprietary dataset is used. Evaluation scenes, package geometry, mass,
friction, task seeds, RGB/depth frames, contact measurements, and JSON results
are generated by Genesis. Controlled profiles range from 25 g to 200 g.

The collision-corrected smoke test reports 5/5 successful tasks across five
profiles from 25 g to 200 g, with 12.14 mm mean horizontal placement error.
This is one seed per profile and is reported as an engineering regression, not
a population estimate. The final corrected video run also passed grasp,
retention, and placement, with 15.52 mm placement error and near-zero docking
error. The earlier 15/17 campaign predates the mobile-collision correction and
is retained separately as historical evidence.

The asset-migration regression retained three failed layouts: the fixed
`link0_c` shell produced 0.514 m and 0.420 m delivery docking errors, while a
root-height proxy stopped 1.224 m early. Moving the chassis proxy to ground
level and separating the tabletop from the root restored complete success.

A matched two-seed ablation on the 200 g heavy package compared (A) suspended
gripper-only carry, (B) body-centered support carry with slip monitoring, and
(C) the same support carry with monitoring disabled. A completed 2/2 tasks;
B and C each completed 0/2. All four support failures occurred during support
unloading after a successful initial grasp. Because disabling monitoring did
not change the outcome, the current bottleneck is the support unloading
geometry/controller, not the monitoring switch. The complete negative result
and raw trials are retained in [the ablation report](ablation_20260802.md).

## 5. AMD Radeon / ROCm utilization

Genesis runs using the AMD GPU backend and ROCm/HIP PyTorch. `rocm-smi` samples
are captured every 0.5 seconds. In the final physical benchmark, the no-video
run achieved 48.68 control steps/s and the video-recording run achieved 38.26
control steps/s, with raw samples committed under `results/`.

## 7. Limitations and next steps

The present semantic layer uses simulator ground truth, not a learned RGB-D
detector. Physical execution in the dashboard currently supports one task at a
time. The base uses collision-aware planar position control rather than a
wheel-dynamics claim. The two-seed ablation is a controlled engineering check,
not a population estimate, and shows that the support unloading branch still
needs redesign. Pending work and current experiment status are tracked in
[SUBMISSION_STATUS.md](SUBMISSION_STATUS.md).
