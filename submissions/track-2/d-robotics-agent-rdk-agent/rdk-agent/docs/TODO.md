# RDK Agent TODO

本文记录已经确认但当前阶段明确不实现的编排能力。当前实现范围是串行的机器人开发模式、单 Agent 机器人应用模式，以及遇阻时的 Human-in-the-loop。

## DAG 并行

- 允许互不依赖的测试、文档或交付任务并行执行。
- 工作流配置从线性 `loops` 演进为 `nodes + dependsOn`。
- 需要解决并发写工作区、事件排序和失败收敛。

## 条件分支

- 根据需求类型、硬件能力或上游结果选择不同节点。
- 条件必须是可审计的结构化表达式，不能只依赖模型自由文本判断。

## Supervisor 规划

- 增加规划 Agent，动态选择 Agent、顺序和工具。
- 规划结果必须先转换为受领域模型约束的工作流定义，再执行。
- 在可观测性、成本上限和权限边界成熟前不启用。

## 人工审批

- 当前正常阶段默认自动通过，不设置审批门。
- 未来可在写代码、安装插件、连接真实机器人、执行不可逆动作前增加审批节点。
- 人工审批与现有 Human-in-the-loop 不同：前者是策略门禁，后者只在流程遇阻时请求信息。

## 多方案竞争

- 允许多个 Coding Agent 独立生成方案，再由评审 Agent 或测试结果选优。
- 需要隔离工作树、统一评分标准和成本控制。

## 其他后续项

- 工作流运行持久化、断点恢复和单阶段重试。
- 结构化 artifact manifest，替代仅传递文本摘要。
- 为各验证 Agent 配置确定性的 `verificationCommand`，生成带退出码和摘要的持久化测试证据。
- 保护已经跑绿的上游交付物：保存内容摘要，在后续阶段意外变化时立即中止而不是等到最终回归。
- 在现有只读 Podman 测试沙箱之上，增加一次性工作区副本和验证通过后的显式 artifact promotion，使 `edit/write` 也不直接修改持久托管工程。
- 增加可选的 `workspace.kind: git`、板端快照和 SDK 包源；必须锁定 commit/digest、校验内容并缓存，不能在运行中使用不固定的 GitHub 主分支。
- TUI 中止当前 Pi Session，而不仅是终止 Human-in-the-loop。
- WebUI、桌面端和远程 API 适配器。
- 真实设备验收的目标白名单、审计日志和安全回滚。
