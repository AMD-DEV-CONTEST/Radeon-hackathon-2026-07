## 1. 项目摘要

个人经历里包含决策、约束、证据和经验，但普通笔记和一次性 AI 写作
通常会把它们压成一段难以验证、纠正、续做和复用的文字。

Experience Asset 是一个本地私有 Agent。它把一段第一人称经历转化为
有版本、有证据边界的经验资产。用户经过五个可见中间产物，在下游复用
之前纠正事实，再从同一规范版本生成面向不同受众的交付物。

React 与 FastAPI 提供产品界面，LangGraph 维护持久的多步骤工作流；
确定性 Runtime 负责工具权限、参数校验、分阶段检索、隐私、批准、重试、
持久化与验证。模型只能提出结构化建议，不能自行授权执行或披露。核心
推理路径设计为 loopback vLLM、ROCm 与 Radeon PRO W7900。

## 2. 应用场景、目标用户与非目标

目标用户有一段值得保存的真实经历、实践、专业认识或产品探索，但难以
区分“发生了什么”“自己如何判断”“Agent 做了什么推断”和“哪些信息仍
未确认”。核心任务不是“帮我写一篇文章”，而是“帮我形成一份可检查、
可继续、可负责地复用的经验资产”。

工程演示使用公开、匿名化的办公椅试用、退货与替换案例。P0 不包括自动
发布、平台增长策略、流量预测、医疗/法律/金融建议、未经审核的网络研究、
原始多模态理解和多人协作。

产品不声称个人经验普遍适用，也不声称消除幻觉；它通过显示来源、不确定
性、适用边界和权限决定，让无依据内容更容易被发现与阻断。

## 3. 产品流程与产出

| 里程碑 | 用户可见产物 | 回答的问题 |
|---|---|---|
| M1 | Experience Brief（经历简报） | 发生了什么、来源边界是什么、用户想得到什么？ |
| M2 | Critical Moment Map（关键时刻图） | 哪些线索与转折改变了经历？ |
| M3 | Decision and Evidence Ledger（决策与证据账本） | 做了什么决定、为什么、采取了什么行动、结果证据是什么？ |
| M4 | Insight and Boundary Map（经验与边界图） | 学到了什么、反事实是什么、经验在何处失效？ |
| M5 | Route Readiness Matrix（交付路线准备度矩阵） | 哪些受众路线合格、隐私安全并已批准？ |

每个里程碑都可编辑、保存、恢复并形成版本。重要纠正会建立新的规范身份，
使依赖旧身份的评估、批准或导出失效。规范资产支持应用内预览以及 HTML、
Markdown、JSON 一致导出。用户选择路线不能绕过确定性的资格、隐私或批准
规则。

在 PR #52 head `427d74f`，集成路径已经包含生产 M5 LangGraph、重启恢复、
路线/语言身份、隐私处理、精确绑定批准，以及保存→预览→导出交付界面。
这是本地集成验证，不是完整产品 W7900 A0。

## 4. Agent 架构与赛道二能力

```text
React UI
  -> FastAPI
  -> LangGraph + 确定性 Runtime
       规划与检查点
       Tool allowlist 与参数校验
       分阶段 RAG 与证据身份
       隐私、批准、重试与终态
       SQLite 版本与审计
  -> localhost OpenAI-compatible vLLM
  -> ROCm
  -> Radeon PRO W7900
```

可观察的 Agent 闭环是：检查状态、选择受限步骤、检索已授权证据、提出
结构化动作、验证策略、执行允许的效果、校验结果，然后持久化或安全停止。

这对应赛道二的多步骤规划、本地 RAG、受治理的 Tool Calling、持久多轮
记忆、权限与隐私控制。Agent 应用与 vLLM 使用独立环境，私有服务默认只
绑定 `127.0.0.1`。

## 5. 证据约束、分阶段 RAG、隐私与批准

材料中的陈述保持“来源事实、用户判断、Agent 推断、待确认信息”分型。
Schema、来源片段身份、确定性重算和版本失效用于约束无依据或过期输出。

```text
M1–M4：只读取当前来源与同一资产的历史版本
  -> M4 Knowledge Card 明确达到 readiness
  -> 只做跨资产摘要级候选发现
  -> 用户确认一条关系
  -> 只读取这条关系对应的历史详情
```

无匹配、拒绝关联和拒绝权限都是正常结果。面向外部的交付物必须通过隐私
检查，并把批准精确绑定到规范版本、关系证据、路线、语言、策略和渲染输入。
重要变化会使批准过期。当前路线草稿路径会校验 statement 身份与路线允许的
证据关联，但尚未证明每一句可编辑草稿文字都与所引 statement 完成文本级
含意校验，因此最终文字仍需用户或编辑复核。

## 6. 本地模型部署与 Radeon 优化

计划提交的推理路径通过 W7900 上的 vLLM/ROCm 本地运行并提供
OpenAI-compatible 接口。最终应用模型仍是 A0 证据槽位，必须记录精确模型
名、revision、hash、精度、上下文窗口和 Runtime manifest。

当前有两条范围受限的实机证据：

- 精确提交 `60503eb` 保留了 M1/M2 在 W7900 与本地
  Qwen2.5-14B-Instruct 上的早期产品证据；它不是完整 M1–M5 产品；
- PR #39 当前 head `1be582c` 保留了 Qwen3.5-9B BF16/8K 的 W7900 Stage 1
  服务层结果；它不等于选择最终应用模型或证明完整产品性能收益。

PR #44 当前 head `700412e` 记录了 S0/P1/P4/P3 的 20K 服务可用性 PASS。原始严格
业务语义失败仍保留为建议项。该叠加验证不改变冻结排名、不推广产品默认配置，
也不证明完整应用已在 20K 运行。

优化遵循“正确性优先”。A0 必须先冻结完整应用、模型、工作负载、环境与
质量/隐私门禁；之后 Stage 2 Candidate 才能用 TTFT、输出吞吐、端到端任务
耗时、峰值显存、完成率和失败恢复做可比结论。本初稿不声称完整产品已有
性能提升。
