# E5 边界记录 — 迁移、失效、隐私、回滚、证据追加

票 01 冻结的合同带着五条边界。它们写在这里而不是散在代码注释里，是因为后面每一票都要
依赖它们，而实现者在票 04 或票 09 才发现某条边界没定义时，最省事的做法是就地自己决定
——那会产生一个没有任何人评审过的边界，并且要到 E6 集成时才被发现。

## 一、迁移边界

**编号从 `0008` 起。** 基线是 `0007_m3_policy_decisions.sql`，`MIGRATION_VERSION = 7`。
E5 的全部 DDL 落在 `0008` 这一个迁移里。

让每票各加一个迁移会这样失败：Wave-1 四条分支并行，各自选下一个可用编号，合并时出现两个
`0009`。冲突表现为文件名相同而内容不同，Git 只报文本冲突，解决者无从知道两个迁移是否
需要都跑、以什么顺序跑。由票 01 一次交付全部 DDL，编号不存在竞争。

**已接受的历史绝不改写。** 迁移只新增表。它不重写 `asset_versions.content_json`，因为
`content_hash` 由快照内容算出：改写要么让每个版本的哈希变化，要么让存储的哈希与内容不
符。旧快照通过读路径的 before-validator 兼容——它丢弃四个已退休的键，空值静默丢弃（没有
任何代码写过它们），非空值大声报错并点名字段。

**升级必须可复验。** `tests/integration/test_e5_migration_upgrade.py` 建一个 migration 7
的库、插入按旧形状序列化的快照、升级，再断言行仍可读、存储 JSON 与哈希逐字节不变、账本
表已建、升级幂等。此前整套测试都用当前模型现建资产，没有一条读过更早形状写下的行——正是
那个盲区让退休字段一度让所有历史不可读而测试全绿。

**方向是 forward-only。** 没有 down migration。回滚走的是「反向修正迁移」而不是回退
脚本，因为回退脚本要删表，而表里可能已经有用户的决定记录。

## 二、失效边界

**失效与删除是两回事，规则也不同。**

| 情形 | 行为 | 为什么 |
|---|---|---|
| 修正、隐私范围收窄导致的**失效** | 生命周期迁到 `STALE`/`INVALIDATED`，行保留 | 决定是「当时发生过什么」的事实，复核者靠它重建系统为何那样表现；删掉会让被作废的关系与从未存在的关系无法区分 |
| 用户发起的**物理隐私删除** | 级联删除该资产的全部账本行与索引行 | 这是 append-only 的**明确例外**。保留审计行等于保留用户要求移除的内容，删除请求就没有真正完成——而一个完成不了的删除请求，比丢失一条审计记录更严重 |

例外只覆盖用户主动发起的删除。任何其他路径都不得删行。

**失效撤销访问，而不是删除事件。** 决定与 attempt 是 append-only；生命周期迁移到
`STALE` 或 `INVALIDATED`，行仍在。删掉行会让一条被作废的关系与一条从未存在的关系无法
区分，而复核者需要能重建系统当时为何那样表现。

**撤销发生在仓储与策略层，不是界面层。** 只在 UI 隐藏会把权限原封不动留在下面，重放的
请求、另一个标签页、之后的一次 run 照样拿得到详情。

**投影失效与索引移除必须同一事务。** 拆成两个事务时，中间崩溃会留下一行索引，它仍然为
已经不存在的 canonical 状态授予可用性。

**触发失效的事件**（完整矩阵由票 09 拥有并在那里落地）：

| 事件 | 影响 |
|---|---|
| 当前资产修正或重开 | 新 canonical 版本；就绪、活跃投影、指纹结果、待决候选、已确认关系访问、证据卡全部失效 |
| 相关资产变更 | 绑定其旧版本的投影与关系失效；当前资产不变，但其候选或已确认详情变为过期 |
| 删除 | 立即撤销可用性与已确认详情访问 |
| 隐私范围收窄 | 同上 |
| 投影 schema 变更 | 产生新投影版本；旧投影仅供审计，不与新合同混用于同一次发现 |
| 模型/prompt/配置变更 | 产生新指纹；旧结果不复用 |

**过期是可见状态，不是静默刷新。** 自动重跑会在用户没有选择的时刻，用另一个答案替换他们
已经推敲过的那个，而他们拿不到任何变更信号。

## 三、隐私边界

**核心推理只走已批准的本地回环 vLLM 路径。** 替代方案是把用户对自己工作、决定与失误的
记述发给闭源远程 API。本地路径是这个产品隐私主张为真而非仅为愿望的原因。

**只有 canonical 已确认字段进入投影。** 原始对话、导入的指令、未确认的语句和来源细节都
按不可信数据处理。索引原始聊天会让用户从未确认的材料变成跨资产记忆，并在之后某次发现里
进入模型。

**发现只送摘要级角色数据。** 发现决策不需要详情，而送详情等于在用户尚未同意查看那段历史
之前，就把历史内容放进了 prompt。

**prompt 与响应正文不进入日志、trace、证据包或关系记录。** 保留的是结构化的已校验输出、
哈希、模型身份、token 计数、时延与安全原因码。持久化正文会建起第二个私密内容存储——正是
本地推理边界要避免的东西。

**私有来源文本、凭据、模型权重与原始敏感 trace 不进 Git。** 公共 QA 只用 sanitized 的
确定性 fixture。

## 四、回滚边界

E5 的回滚是：停用显式关系发现、移除活跃投影可用性、通过评审过的 revert 或前向修正迁移
撤下应用与合同集成。

**不可变的 Experience Asset 快照保持有效**，因为投影与关系状态是 sidecar 记录，不是对
历史内容的改写。这正是把关系状态放进账本而非快照换来的性质：回滚不需要动任何一条已接受
的版本。

**绝不删除或改写已接受的历史，绝不 force-push 共享分支，绝不留下仍可用的过期关系访问。**
前两条是审计前提；第三条是因为一次不完整的回滚里，最可能被漏掉的恰是权限，而漏掉的权限
不会有任何症状，直到有人用它读到不该读的东西。

## 五、证据追加边界

**证据包是 append-only。** 已合并的包不重写，新的 head 产生新的包。

**三个状态不可互换**，混用会让读者无法判断某条主张究竟是「做了没过」「能做还没做」还是
「根本做不了」：

| 状态 | 含义 |
|---|---|
| `PASS` | 在本包记录的 commit 与环境上实际执行且通过 |
| `NOT_VERIFIED` | 环境具备、可以执行，但本包尚未执行 |
| `BLOCKED` | 环境或依赖缺失，本包无法执行；须写明缺什么 |

W7900/ROCm/vLLM 不可用时一律 `BLOCKED` 并注明缺失环境，不写 `NOT_VERIFIED`（那会暗示
只是没排上），更不写 `PASS`。

**失败与回滚必须留在包里。** 只含成功的证据包让复核者无法区分「没有失败」与「失败被省略」，
它的那些 `PASS` 因此更不可信，而不是更可信。

**一条不可复现的 `PASS` 会让整包归零。** 复核者一旦发现其中一条无法复现，就必须把其余每
一条也当作未经验证——损失不是那一行。
