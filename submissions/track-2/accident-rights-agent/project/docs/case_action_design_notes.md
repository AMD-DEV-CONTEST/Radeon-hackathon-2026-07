# 脱敏办案过程对事故权益助手的设计输入

## 数据边界

本说明只整理车主本人陈述的实际动作、取得的材料和程序结果。姓名、电话、
车牌、具体机构、地址及精确身份信息不进入项目。

第三方对话中由模型生成的法院判例、法条、法律分析和文书结论一律不采用。
法律规则必须另行回到全国人大、国务院、公安部、司法部、最高人民法院、
国家邮政局等官方原文，核对标题、条号、版本、生效时间和适用阶段。

以下时间线属于“用户陈述的经验过程”，不是系统独立查明的案件事实，也
不能替代正式案卷、鉴定意见、事故认定书或复核结论。

## 脱敏时间线

1. 事故发生后，办案人员曾口头表达对机动车驾驶人明显不利的责任倾向。
2. 车主在正式认定前书面提交车辆属性和技术参数鉴定申请，并要求确认
   委托事项、承办人员和收件情况。
3. 原鉴定范围不足时，车主继续提交补充鉴定事项；对超出机构能力范围的
   问题，改为分别通过监控、现场图、道路标志、车型备案和其他原始材料固定。
4. 当面递交难以取得签收时，车主使用同版本文件进行 EMS 邮寄，并保存
   留存副本、邮件详情、物流和签收记录，再持续确认是否入卷。
5. 车主取得路口监控、车辆车型备案、车辆属性和速度/安全状况等鉴定材料，
   将“口头争议”转化为可核验的证据问题。
6. 车主要求保险公司提供调查、材料整理、期限提醒和沟通协助，并保存保险
   公司的答复与后续处理记录。
7. 初次事故认定仍不利时，车主在期限内申请复核；复核机关撤销原认定并
   要求重新调查，重新作出的认定最终将机动车驾驶人确定为次要责任。

## 对产品的直接要求

- 阶段性分析结束后，首页必须立即回答“现在做什么”，不能停在概率图表。
- 对外交管申请不写系统的责任方向或比例，只写事故经过、证据出处、待核实
  事项和明确的鉴定问题。
- 车辆鉴定入口要区分首次检验鉴定、原范围遗漏后的补充申请、对已送达
  鉴定意见的重新检验鉴定，以及进入法院后的鉴定申请。
- 每项行动不仅要有截止时间，还要有“完成证据”：收件留存件、EMS 运单、
  文件清单、物流轨迹、签收/拒收记录、沟通记录和入卷确认。
- 保险公司的角色是协助车主补件、核对、提醒和升级，不代替车主作出意思
  表示，也不自动向任何机关或相对方发送材料。
- 认定书送达后的复核不是一个文件下载按钮，而是一条包含送达日期确认、
  事实/证据核对、草稿审核、人工递交和结果跟踪的连续行动线。

## 法律措辞红线

- 不从第三方模型回答复制判例、案号、法院观点或法条。
- 不把“超标”自动写成“机动车”。
- 不把“当面 + EMS”写成法定必须同时完成；它是增强收件证明的实践建议。
- 不把“补充鉴定书”当作车主提交文件；车主通常提交补充鉴定申请，鉴定
  机构完成补充鉴定后出具相应鉴定文书。
- 不用系统预测替代交管机关事故认定、复核结论或法院裁判。
