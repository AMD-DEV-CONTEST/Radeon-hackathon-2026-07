# Frontend premium redesign

## Purpose

Phase 5 turns the functional BrandPilot Local prototype into a coherent,
demo-ready creative workspace without changing its API contracts or inference
claims. Mock mode remains the default. Experimental Radeon mode remains a
temporary, authenticated opt-in and does not imply that a Radeon worker is
currently connected.

## Visual direction

The interface uses a deep charcoal canvas, layered dark surfaces, restrained
BrandPilot red and coral accents, and small amounts of violet and cool blue for
informational state. Subtle grid texture, inset highlights, perspective, edge
lighting, and layered shadows create dimensionality without video, large image
assets, mouse tracking, or continuous decorative animation.

Poppins is loaded through `next/font` for headings, key labels, and buttons.
Montserrat is loaded the same way for body copy, form content, descriptions,
metadata, and status rows. Responsive `clamp()` scales keep display type
readable without overflowing narrow layouts.

## Token and component system

Global CSS variables define:

- background, surface, elevated-surface, text, and border colors;
- red, coral, violet, success, warning, error, and information accents;
- small through extra-large radii;
- layered shadows and inset edge highlights;
- a shared interaction curve and focus-ring treatment.

Reusable React components now provide:

- `Button`, `IconButton`, `Surface`, and `AnimatedSection`;
- `FormField` and numbered `FormSection`;
- custom segmented inference-mode controls;
- accessible selectable style and format tiles;
- a validated upload dropzone and selected-file preview;
- status, connection, workflow, system, result, review, loading, empty, error,
  and confirmation surfaces;
- an active desktop navigation and keyboard-operable mobile drawer.

Native radio, checkbox, and file semantics are retained. Visual selection
tiles expose strong selected, focus, disabled, and pressed states without
depending on hover or color alone.

## Responsive behavior

The desktop Studio uses a main creation canvas and sticky status sidebar.
Intermediate layouts narrow the sidebar, then move it below the form. Fields,
choice grids, results, architecture nodes, and footer columns progressively
collapse. Mobile CTAs become full width, the navigation becomes a 44-pixel
menu control, and the drawer provides a backdrop, Escape handling, scroll
locking, and session-status context.

CSS breakpoints cover large desktop, laptop, tablet, and narrow mobile
layouts. The browser host used for Chrome QA enforces a 520-pixel minimum
inner viewport even when 430, 390, or 360 pixels are requested; narrow styles
below that value remain implemented and were checked statically in the
production stylesheet.

## Accessibility and motion

- Semantic headings, lists, definition lists, form labels, and fieldsets are
  preserved.
- Active navigation uses `aria-current`.
- The mobile trigger uses `aria-expanded` and a named controlled region.
- Focus-visible rings are consistent and high contrast.
- Statuses include text as well as color.
- Custom selectors preserve native checked state for assistive technology.
- Dialog, progress, loading, alert, and review controls retain appropriate
  semantics.
- `prefers-reduced-motion: reduce` removes entrance translations and shortens
  all transitions while retaining immediate state feedback.

Motion is limited to short entrance, selection, progress, spinner, drawer, and
tactile button interactions. There are no unbounded decorative loops.

## Status honesty

Visible copy follows these rules:

- standalone Radeon generation is verified;
- authenticated FastAPI loopback generation is verified;
- the public browser edge is blocked by official tunnel DNS;
- mock mode is the default and mock concepts are labelled;
- the experimental connection is temporary and opt-in;
- product identity, logo, and packaging-text preservation are not claimed;
- production and commercial clearance are not claimed.

## Browser QA and development indicator

Production pages were exercised in Chrome for navigation, responsive layout,
mock results, review confirmation, review refresh persistence, system status,
experimental disclosure, custom 404 handling, and horizontal overflow.
Screenshots are stored in
`evidence/frontend-premium-redesign/screenshots/`.

The development issue indicator was traced to a hydration warning caused by a
Chrome extension adding `cz-shortcut-listen="true"` to `<body>` before React
hydrated. It was not generated by application code. Framework internals were
not suppressed or modified. The optimized production build has no Next.js
development indicator.

## Known limitations

- Chrome file-chooser automation was blocked by the connected extension's
  file-access permission; the upload component was verified through its native
  input semantics, existing automated validation, and local API-backed result
  state. Manual file selection remains available in the browser.
- The controlled Chrome host clamps requested mobile viewport widths to a
  520-pixel inner viewport.
- The public browser-to-Radeon edge remains blocked by official tunnel DNS.
- Export and production deployment are outside this phase.
