# V10 double-standard acceptance

“200%” is implemented as two non-substitutable gates, not as an invented
numeric score:

1. **Official floor:** every applicable competition requirement must pass.
2. **Overdelivery gate:** the applicable source, test, falsifier, data-rights,
   training, multimodal-retention, Radeon, 4K, blind 4A, human-approval, and
   rollback evidence must also pass.

The compiler assigns a machine-readable requirement profile to every one of
the 1,500 canonical TODOs. Universal requirements prevent administrative or
engineering tasks from escaping provenance, positive/negative tests, stop
rules, rollback, and truth boundaries. Research, training, multimodal-product,
4K, and submission workstreams receive stricter profiles.

All 1,500 TODOs bind to `official_program_compliance`. The 100 atomic TODOs in
the official-rules and submission workstreams additionally bind to the direct
eligibility, English-material, deliverable, fork/PR, local-Radeon, and output
quality facets. All 1,500 also receive a non-empty overdelivery gate. The
generated manifest publishes both counts so program-level compliance cannot be
mistaken for direct task-level applicability.

All 1,500 TODOs additionally bind to the program-wide multi-GPU execution
contract. The 1,100 compute-bearing training, evaluation, and media TODOs
require real multi-GPU runtime, frozen single-GPU equivalence, and measured
parallel-efficiency evidence. The other 400 remain inside the same supervisor,
dependency barriers, and atomic commits without inventing GPU work.

No profile treats API spend, teacher prose, self-scoring, a plan, a simulated
business metric, or a local proxy as external proof. Required Radeon,
multimodal, human, 4A, eligibility, deliverable, and PR observations reject
proxy evidence by construction.
