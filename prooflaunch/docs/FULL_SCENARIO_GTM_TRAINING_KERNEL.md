# ProofLaunch Cortex-X V10：全场景 GTM 训练内核

## 结论

Agent 的编排只是最后一公里。当前项目真正的上限取决于：是否用同一坐标贯通语料、环境、轨迹、SFT、在线 RL、评测与失败回流；是否能在真实 Radeon 多卡上把该闭环训练成权重；是否能用盲测和业务证据证明泛化，而不是增加角色数量。

当前已落地统一坐标、Step-level MDP、失败归因、RCRL 准入、失败驱动课程冻结、PRD 演进门禁和八赛道产品能力比较集。另已生成 32 个分区隔离的本地环境、152 个任务和 152 条可重放可见黄金轨迹，覆盖十九类失败。匹配轨迹层进一步生成 456 条正例/负例/恢复结果轨迹、1,824 条 Planner/Worker/Critic/Supervisor 独立可见轨迹、192 条停止/重试/回退/人工升级策略样本、1,640 条步骤奖励和 456 条轨迹奖励。信用层保存 456 份四角色分层信用，强制非终局步骤证据并阻止错误无依据向上游传播；时间课程按短 936、中 104、长 208 条训练分区角色轨迹冻结，验证与评测集保持隔离；KL、复合错误、工具噪声和循环监控已用受控机械 fixture 验证。它们仍是项目自有的合成机械种子，不是 4A 多模态生产语料或已训练策略。真实权重、在线 RL、Radeon 关键推理、至少两卡训练、4A 盲测和业务提升仍然阻塞。

2026-07-31 的第二轮研究已进一步冻结为 `ProofLaunchFrontierTrainingKernelV2`：十项一手研究机制、八条赛道的统一六阶段生命周期目标、十二类命名失败模式，以及 checkpoint、幂等键、精确恢复、有界重试、不可逆动作人工批准和哈希事件链组成的耐久执行合约。每项研究机制都带明确反证条件；局部实现或测试通过仍不等于论文复现或训练效果。

## 研究边界

- AgentOmnia 论文公开了方法、规模和实验结果，但没有公开完整的 52K 训练任务、完整训练代码或模型权重。
- OmniaBench 公开了评测代码和 644 条挑战集；代码是 Apache-2.0，数据集标为 research-only，不能自动升级为产品训练语料。
- 本项目吸收方法，不声称复现论文成绩。所有论文数字均是外部参考值。

主要一手来源：

## 单一训练坐标

每个环境、任务、轨迹、验证器、奖励和失败记录都必须共享：

`应用对象 × 一级领域 × 二级场景 × 多能力标签 × 多原子难度 × 主难度 × 推理路线`

能力固定为十类：任务理解、信息收集、规划决策、状态管理、工具使用、代码操作、数据分析、办公文档、交互协作、可靠性与安全。

原子难度固定为八类：目标歧义、工具参数落地、结构化信息复杂度、长上下文多工件、动态多步规划、多源冲突、渐进披露与状态演化、风险可靠性与澄清。

GTM 不另造一套分类。视频、音频、文案、数据分析、GEO、SEO、员工 Agent、广告投放是一级产品赛道；品牌策略、受众研究、创意开发、资产生产、媒体激活、实验、归因和复盘是跨赛道生命周期。

## 训练闭环

1. 先冻结权利、时间和环境版本。评测环境的内容哈希不得进入 SFT/RL。
2. 环境必须可执行、有状态、健康检查通过、可重置、金轨迹可重复回放。
3. 教师只提供可见的行动—观察轨迹；程序、求解器、状态转移和 rubric 决定是否录取。隐藏思维链不进入语料。
4. SFT 学会跨赛道共同协议和长链行为，不为每个基准训练独立 adapter。
5. 在线 RL 使用规则奖励与经过人类校准的 rubric 奖励；环境故障、异常终止和不明截断不得当成策略负样本。
6. 只有整组 rollout 都是干净的策略失败时，RCRL 才能注入已复放验证的部分金前缀；必须保留未解决后缀给策略探索。
7. 每条失败标出首错、传播、漏检、修复和停止步骤，同时区分策略失败、环境失败、judge 失败和 reward hacking。
8. 失败密集坐标生成下一轮 PRD、环境和任务；新样本先过健康、权利和泄漏门禁，再进入冻结课程。
9. 每轮必须同时报告目标坐标、全局回归和未参与 PRD 构造的外部迁移集。至少三轮后才能讨论自演进稳定性。

## 八赛道“万米蒸馏”定义

每条赛道采用十产品非排名比较集。蒸馏对象是公开可观察的产品能力、工作流协议、质量 rubric、错误模式、延迟/成本/可控性和人机边界，不是未经许可复制产品输出或广告作品。

- 视频：脚本到分镜、多镜头一致性、运动与镜头控制、原生音画、可编辑性、身份保持、4K 母版。
- 音频：品牌声音、语音/音乐/音效、时间线编辑、情绪与多语言、授权与溯源。
- 文案：证据到主张、品牌语气、长上下文、多版本约束、事实与合规。
- 数据分析：自然语言到可复算分析、语义层、代码/SQL、可视化、决策备忘录。
- GEO：问题宇宙、模型/地域/角色分层、品牌提及、引用来源、错误表述、可验证增量。
- SEO：抓取与技术健康、搜索意图、主题权威、内容差距、排名与自然转化。
- 员工 Agent：目标到工作流、多工具状态、审批、恢复、审计、跨轮持续执行。
- 广告投放：策略到建案、素材变体、预算/出价、频控、实验、增量归因和止损。

## 不能降级的晋级标准

- 一个共享策略在密封环境上泛化；禁止“每个 benchmark 一套 adapter”。
- 语料只接受自有、宽松许可、公有领域或明确授权；每条样本保留来源、许可和哈希。
- 奖励模型必须分别通过高级 rubric、组内排序、优势方向、优势幅值和重复评分一致性，不能只看平均准确率。
- 多模态必须分别验证语义、身份、时间一致性、音画同步、可编辑性、4K 交付和人工偏好。
- 4A 质量必须由独立盲测、明确人群和原始计数证明；内部 judge 不可替代。
- 至少一个关键推理必须真实运行在 AMD Radeon；正式训练晋级需要真实两卡及以上 DDP/FSDP2 记录，单卡只做等价基线。
- 任何模拟成绩、教师建议、合约通过或本地单测都不得声称为训练效果、全球 Top 1 或业务提升。

## 跨赛道训练内核递进

第一层不是把八十个产品输出抓进训练集，而是把公开可观察能力拆为可反证机制。产品页面只用于定义对照工作流和失败样式；训练字节必须经过 Supply Chain V3 的许可、修订、哈希、退出请求和隔离门禁。

第二层统一六段生命周期：Discover → Strategize → Create → Activate → Measure → Learn。视频、音频、文案、数据、GEO、SEO、员工 Agent 和广告投放都使用这条主链，但各自拥有不同的机械指标和盲测维度。训练目标是跨工件状态迁移和闭环结果，不是单次生成的“好看/好听/像人”。

第三层建立交错多模态 CPT、分阶段 SFT/DFT、可见轨迹蒸馏和在线 RL。长链任务必须来自可执行的无环工具依赖图；策略在执行前预测短期状态轨迹；步骤奖励同时保留局部行动信用和受控未来信用。每种新增方法都要与 SFT-only、final-answer-only、静态任务、无预测、无过程信用和不稳定环境对照。

第四层只在低一阶方案的密封评测通过率达到 90% 后提升自治。默认是确定性的 L2 工作流；研究、宽域审计等可并行阶段才使用有界 L3 Supervisor—Worker，深度连续创作和代码/资产修改保持单状态所有者。不可逆发布、投放和预算动作必须人工批准。

第五层是耐久执行：每次状态变化后 checkpoint，每个副作用有幂等键；429、5xx、工具超时分类有界重试，权限、schema、权利失败不重试；恢复不得重复已成功活动；事件日志形成哈希链。十二类失败模式进入机械断言、经人类校准的二元 judge 和独立盲测三层评测。
