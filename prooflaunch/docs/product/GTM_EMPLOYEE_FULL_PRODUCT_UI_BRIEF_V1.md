# ProofLaunch GTM Employee — Full Product UI Brief V1

## Product object and audience

ProofLaunch is a B2B AI-native campaign operating system for campaign operators, owner-reviewers, governance administrators, and platform operators. The persistent product objects are Mission, Evidence Source, Claim, Strategy Spine, Audience, Channel Asset, Experiment, Approval, Run, Evaluation, and Release Pack. Chat history is never the sole asset.

## AI necessity and measurable outcome hypothesis

The product must transform heterogeneous evidence into a governed nine-channel campaign system while maintaining one strategy/audience/claim spine, distinct channel expression, experiment design, visual generation, traceability, and human release gates. Deterministic CRUD alone cannot perform the required multimodal synthesis, constrained generation, cross-channel adaptation, or iterative repair.

Order-of-magnitude target: reduce a complete evidence-to-reviewed-campaign-pack cycle from multi-day manual handoffs to a same-session governed workflow, while preserving claim provenance and human approval. This is a target hypothesis to validate, not an observed productivity or performance claim. The product must show cycle time, review burden, accepted-output rate, rework, cost, and error evidence before any improvement claim is made.

## Experience architecture

### Front office — operator workspace

1. Mission command center: prioritized jobs, outcome target, risk, owner, next action, checkpoints.
2. Evidence studio: source intake, rights status, claim extraction, citation spans, conflicts, approval.
3. Strategy studio: business objective, audience hypothesis, proposition, claim spine, channel constraints.
4. Creative studio: GPT image direction, text and visual variants, channel previews, version compare, repair.
5. Activation plan: nine-channel matrix for Amazon, Shopify, Meta, TikTok, LinkedIn, YouTube, Performance Max, email, and landing page.
6. Experiment lab: hypothesis, changed variable, arms, traffic, sample size, duration, metrics, SRM gate.
7. Learning room: performance observations, fatigue signals, audience learning, protected holdout, decisions.
8. Release center: factual audit, provenance, accessibility, brand, policy, approval, export package.

### Middle office — AI and campaign operations

1. Orchestration: mission graph, agent/tool topology, checkpoints, retry, rollback, escalation.
2. Model and tool routing: capability, cost, latency, data boundary, fallback, version, availability.
3. Approval operations: queues, SLA, role separation, impact preview, exception handling.
4. Evaluation: outcome, trajectory, tool, artifact, safety, channel and visual quality graders.
5. Memory and knowledge: source-bound memory, retention, conflicts, freshness, correction and deletion.
6. Asset operations: lineage, derivatives, usage rights, crops, formats, channel readiness.
7. FinOps: token, model, image, retry, rework and accepted-output cost attribution.

### Back office — governance and platform administration

1. Tenants and principals: organization, workspace, user, service identity, RBAC and ABAC policies.
2. Policy center: claim, channel, region, brand, model, tool, data, retention and approval policies.
3. Audit ledger: principal, action, decision, object, before/after version, hash, timestamp, evidence.
4. Connectors: credential boundary, scopes, health, rate limits, read/write mode, revocation.
5. Runtime health: queues, workers, model gateways, latency, error class, circuit breaker, recovery.
6. Model registry: model cards, evaluations, allowed tasks, limitations, region and version locks.
7. Data governance: residency, classification, retention, export, deletion, incident and legal hold.

## Visual system

Direction: executive-grade mission control, not a generic SaaS card wall. Use a near-black mineral canvas, graphite and ink surfaces, restrained electric cyan for intelligence, iris violet for synthesis, warm amber for human decisions, mint for verified state, and coral only for failure. Typography is editorial and compact: expressive display serif for product moments, legible grotesk for operations, monospace for evidence identifiers. Use luminous topology lines, deep-space atmospheric imagery, fine 1px borders, quiet glass only at focus areas, and generous negative space around the active work object.

The generated raster visual is a brand atmosphere and hero/support asset, never the source of UI text or interaction. UI, icons, charts, states, and data remain native HTML/CSS/JS for accessibility, responsiveness, and 8K-display fidelity.

## State completeness

Every primary object supports ready, loading, empty, error, offline, conflict, permission, and recovery states. High-impact actions show actor, permission, impact, evidence, reversible boundary, and next step. Mobile recomposes to priority queue → impact → approve/recover; it does not merely shrink the desktop grid.

## Quality and truth boundary

- Responsive evidence widths: 320, 390, 768, 1440, 2560, 3840, and 7680 pixels.
- Visible keyboard focus, semantic landmarks, native controls, 200% text resilience, reduced motion.
- No live model, connector, publisher, production telemetry, campaign lift, or legal compliance is implied by the static prototype.
- A generated 8K delivery master may be upscaled from the model output when the built-in generator does not emit native 7680×4320 pixels; native model resolution and delivery canvas must be reported separately.
