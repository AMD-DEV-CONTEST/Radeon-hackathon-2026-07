# ProofLaunch 跨时代 4A GTM 员工：效果优先执行契约 V1

日期：2026-08-01  
截止：2026-08-03  
状态：生产闭环执行中；4A 效果尚未获人工盲评证明

## 1. 唯一产品承诺

用户提交企业阶段、受众问题、证据、品牌约束、目标与素材后，ProofLaunch 交付一套可直接由人审阅和发布的零媒体预算 GTM 决策包，而不是聊天记录、Agent 编排图或待办清单。

交付必须回答六件事：

1. 此刻最应解决的增长问题是什么，原目标是否合理；
2. 为什么选择唯一主渠道和唯一辅助渠道；
3. 基于哪些获授权证据形成单一创意主张；
4. 七天内每一天生产、发布、观察和停止什么；
5. 文案、图像、视频、音频、SEO/GEO 与分析如何围绕同一策略表达而非复制粘贴；
6. 哪些结论是计划、机器检查、人工判断或真实业务观察。

“零预算”只代表零媒体采买，不代表零人力、零模型或零计算成本；“任意行业”只代表同一受治理输入契约可适配，不代表系统已在所有行业获得效果证明。

## 2. 从领先产品吸收的产品契约

以下是代表性能力参照，不构成未经证据支持的“全球前十”排名。

| 能力域 | 吸收的成熟产品契约 | ProofLaunch 的实现边界 |
|---|---|---|
| 桌面 AI 员工 | OpenWorker 的 outcome-first 成品、行动前审批、无人值守 approval inbox、完整 transcript、模型/连接器可替换 | 不整体 fork；复用交互和安全契约，保留既有 durable runtime |
| 企业 Agent | Workspace Agents 的可预览、可发布版本、定时/API 触发、RBAC、工具约束 | prepare 与 release 分离；发布权限不交给模型 |
| 跨端记忆 | 来源可见、自动处理过期或冲突记忆、项目范围隔离 | org/project/campaign 分层；只有批准事实和带来源观察可晋级 |
| 数据策略 | 语义层、评估集、可追溯答案、面向业务问题的分析 | 指标和停止规则预注册；归因不自动改写为因果 |
| 内容排程 | 内容 idea、draft、schedule、channel-native adaptation | 先输出可审阅排程包；默认不自动发布 |
| 文案/品牌 | 品牌知识、语调约束、工作流化批量生产 | 证据主张和创意表达分层；禁止虚构事实与效果保证 |
| 图像/视频/音频 | 可控生成、参考资产保持、分镜/声音/剪辑一体化、生成来源标记 | 本地 Diffusers/外部 adapter 可替换；无 GPU 时降级必须显式标记，不能伪装 AI 生成 |
| SEO/GEO | 技术可抓取性、问题意图、品牌可见性、引用与来源正确性 | 交付问题集、FAQ 草案与确定性技术审计；不伪造搜索排名或答案份额 |
| 广告与增长 | 单变量实验、自动化建议、保护性预算/政策边界 | 截止日前只产生 dry-run 计划；零预算模式禁止付费与自动投放 |
| 分析与学习 | 产品事件、来源、窗口、基线、分群和版本关联 | 只接纳带 experiment id、样本、窗口与来源的观察；不足样本不更新长期策略 |

## 3. 不允许用功能数量替代效果

每个候选交付物必须同时通过四层门：

1. **关键零容忍门**：权利、事实、品牌禁用项、隐私、渠道政策、可访问性、人工发布边界全部通过；
2. **可执行门**：渠道规格、CTA、链接、排程、UTM、停止规则、回滚和 owner 均完整；
3. **盲测效果门**：与强基线随机左右盲比，每个场景至少 30 对；候选胜率点估计不低于 0.60 且 95% Wilson 下界严格高于 0.50；
4. **业务学习门**：真实发布后保留样本、窗口、基线、来源和实验身份；只有观察性结论，除非实验设计支持因果解释。

未完成盲评时，证据等级只能是 `planned` 或 `mechanically_verified`，不得标记 `4A`、`top1`、`production_effect_proven`。LLM judge 在至少 100 条独立人工标注且 TPR/TNR 均大于 0.80 前，只能用于排序草案，不能作为晋级证据。

## 4. 交付物必须是一套策略，不是素材拼盘

最终生产包至少包含：

- `gtm-strategy.json`：问题诊断、生命周期、预算、受众、主次渠道、单一主张、证据与反对理由；
- `campaign-pack.zip`：审计通过的创意资产与来源账本；
- `seven-day-schedule.json`：每天的原生渠道表达、负责人、人工发布方式、学习问题和停止条件；
- `breakout-growth-loop.json`：按 2B/2C 与生命周期选择的 sense→make→seed→convert→learn 获得式增长回路，包含价值先行、种子角色、单变量实验、容量前置条件、停止条件与人工晋级边界；
- `text-creative-challenger-plan.json`：把确定性文案降为基线，编译 decision x-ray、proof-before-promise、voluntary-relay 三条官方优先挑战路线；严格绑定证据、CTA 与渠道格式，未真实调用时只标记 planned，禁止自动选优或发布；
- `seo-geo-questions.json`：可回答、可引用、含“不适用场景”的问题意图；
- `experiment.json`：唯一变化变量、UTM、基线、最小样本、观察窗口和禁止因果越界；
- `effect-observations.json`：与预注册实验和批准策略哈希绑定的聚合结果、样本门、保护指标与下一轮人工决策；
- `revenue-economics.json`：与效果观察哈希绑定的净收入、退款/拒付、六类可变成本、贡献利润和人工收益复核状态；qualified pipeline 明确不计收入；
- `approved-learning-context.json`：第二次人工晋级后的项目级聚合学习快照；新运行冻结读取，旧运行不受后续写入影响；
- `approval.json`：与预览摘要绑定的真实人工决定；
- `events.jsonl` 与 `campaign-evidence-ledger.jsonl`：可验证哈希链；
- `bundle-manifest.json`：所有成员 SHA-256、运行身份、真相边界与外部发布状态。

视频和音频在没有真实生成器、模型版本、许可证、输出文件与质量证据时，只能作为 production brief/shot list/audio direction 交付，不能宣称成片已生成。

## 6. 开源复用决定

- 保留现有 Supervisor + SQLite WAL/CAS/lease/idempotency/hash-chain，不迁移 LangGraph、Temporal、Restate 或 Inngest；
- 继续使用 Apache-2.0 Diffusers adapter；
- MCP、Buffer、PostHog、Lighthouse、ComfyUI 只允许隔离薄适配，默认关闭、超时可恢复、带幂等键和权限清单；
- ComfyUI 作为 GPL 独立进程，不把其源码嵌入 MIT 核心；
- 不把公开 4A 全案直接变成训练数据；只在权利允许时做训练，在评价与方法研究中保留来源和使用边界；
- 不因“只训练、不商业化”假设复制权利不明素材。
- 有成交或收入的效果观察在缺少单位经济证据时不得晋升为学习；毛收入、pipeline 和相关性归因不能自动触发预算或策略变更。

## 7. 当前真相边界

工程闭环和机械质量门可以通过自动测试证明；创意、策略与业务效果必须由盲评和真实观察证明。当前系统不得用 1,500 条 TODO、模型调用量、Agent 数量、分辨率或测试数量替代最终效果证据。
