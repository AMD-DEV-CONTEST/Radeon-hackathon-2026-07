## 一、项目概述

本项目基于 ComfyUI 开源架构二次适配优化，专为本次 AMD AI DevMaster 黑客松 ROCm 环境打造。针对普通开发者在 AMD 云服务器部署 AI 绘图环境普遍遇到的「环境适配复杂、显存适配困难、端口映射繁琐、ROCm 兼容报错」等痛点，本项目提供 **完整服务器部署流程 \+ 一键自动化部署脚本 \+ AMD 显存自适应优化工具 \+ 三套预调优工业级创作工作流**。

项目不依赖任何外网API，全部推理、加载、渲染在本地 AMD GPU 完成，充分验证 ROCm 生态在多模态生成领域的落地能力，完全贴合赛道1多模态创新与 AMD 平台优化双重评分标准。

## 二、云端服务器完整部署实操流程（核心亮点·体现工程能力）

本项目所有部署操作均在 AMD 官方赛事云服务器完成，依托**全新重装、最新正式版 OpenCode AI 终端助手**辅助落地，完整经历「服务器环境清理兜底→OpenCode 重装迭代升级→实例初始化→网络调试→端口隧道穿透→ROCm环境排错→AI项目适配部署」全流程，完整实操记录如下：

### 1\. 服务器环境清理与 OpenCode 全新重装升级（专属实操亮点）

初始服务器存在旧版 OpenCode 残留缓存、版本漏洞及环境冗余问题，为保障后续AI项目部署稳定、规避旧版工具调用报错缺陷，我自主完成全套环境清理与工具迭代工作：

- 彻底卸载服务器旧版 OpenCode，清理全局缓存、配置文件及残留依赖，根除旧版本 `missing field name` 工具调用BUG

- 摒弃废弃私有包源，采用官方最新合规命令 `npm i -g opencode-ai` 重装 OpenCode，同步更新至当前最终稳定版本

- 完成新版OpenCode初始化配置，优化工具自动调用、终端指令适配能力，依托AI终端助手辅助完成后续服务器环境核验、依赖安装、报错排查全流程

- 重装完成后核验工具可用性，确保终端指令交互、自动化部署、日志查询功能正常，为ComfyUI项目部署筑牢环境基础

该步骤解决了赛事服务器旧工具版本兼容差、自动化部署报错、环境冗余冲突的核心问题，依托新版OpenCode的高效辅助能力，大幅提升AMD ROCm环境下AI项目部署的稳定性与效率。

- 执行 `rocm-smi` 核验 AMD 显卡状态、显存大小、ROCm 驱动版本

- 核对系统环境变量，确认 `ROCM_PATH` 路径完整性

- 排查系统 Python 版本、CUDA 冗余依赖，清理冲突环境，保证纯 ROCm 推理环境

该步骤解决了多数开发者直接部署导致的「显卡识别失败、框架调用 CUDA 而非 ROCm」的底层问题。

### 2\. 服务器远程连接与端口穿透实战

赛事服务器采用**非标准SSH端口 \+ 外网防火墙策略**，无法直接使用默认22端口直连，本次项目完整完成自定义端口穿透配置：

- 识别服务器真实连接信息：自定义 SSH 端口，修正初始默认22端口连接超时问题

- 本地完成 SSH 密钥权限配置、Windows 私钥权限收紧、安全策略配置

- 成功搭建 **本地端口转发隧道**，将服务器 8188/7860 端口映射至本地浏览器，实现远程可视化操作

全程依托新版OpenCode辅助排查网络问题，自主解决 Connection timed out、SSH端口不匹配、私钥权限过宽、文件无法访问等典型服务器运维问题，熟练掌握云端服务器端口映射、网络排错、安全配置能力，完整落地AI服务远程可视化部署链路。

### 3\. ROCm 专属环境适配与报错解决

AMD 平台区别于英伟达 CUDA 环境，部署存在大量专属适配坑点，本项目逐一解决：

- 手动配置 `HSA_OVERRIDE_GFX_VERSION` 显卡架构兼容变量，规避架构不识别报错

- 卸载通用 CUDA 版 PyTorch，重装 **ROCm 专属版本 PyTorch**，保证 GPU 硬件加速生效

- 针对 AMD 显存调度逻辑，规避原生项目显存溢出、推理卡顿、模型加载失败问题

所有适配逻辑全部封装进一键部署脚本，解决新手在 AMD 平台部署门槛高、报错多、环境混乱的痛点。

### 4\. 服务持久化与后台运行配置

依托新版OpenCode终端工具辅助配置服务后台常驻运行模式，优化进程守护逻辑，避免终端关闭、会话中断导致的服务停止问题，保障ComfyUI创作服务在AMD云服务器长期稳定运行，适配赛事项目长期调试、测试、演示需求。
