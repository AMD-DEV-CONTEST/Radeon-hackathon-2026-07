### What this submission is

This is not a cloud-wrapper demo.  
It is a private manufacturing agent that runs end-to-end on a local AMD Radeon GPU via ROCm, with no mandatory external API calls.

The agent does two things that separate it from generic RAG shells:

1. **Geometry-first STEP interpretation** — parses STEP geometry, extracts machining-relevant features, and uses that structure to drive process planning discussion.
2. **Local manufacturing discussion** — answers manufacturing questions (fixturing, tolerance, 5-axis feasibility, toolpath strategy) using the parsed geometry plus a local knowledge base, without sending CAD data to a cloud LLM.

### Why AMD Radeon / ROCm matters here

CNC manufacturing workflows involve sensitive CAD geometry, process IP, and customer quotes.  
Running the agent locally means:

- CAD data never leaves the machine
- Quotes can be generated offline in a shop-floor or field environment
- Inference cost is fixed hardware cost, not per-API token

### Core capability: STEP → process discussion

This is the submission’s differentiator.

A user uploads a STEP file. The agent:

1. Parses geometry and extracts manufacturing-relevant features
2. Discusses machining strategy, fixturing, tolerance, and 5-axis feasibility
3. Generates a structured quote with material, surface treatment, machining time, and risk flags

### Example conversation (real run)

> **User:** Uploads `bracket_7075.step`  
> **Agent:** Detected features: 3x M6 threaded holes, 2x planar datum surfaces, thin-wall rib 2.5 mm. Recommended fixture: zero-point clamp on datum A, support rib with soft jaw. Toolpath risk: thin-wall deflection likely with >0.5 mm axial depth.  
> **User:** Can this run on 4-axis?  
> **Agent:** Yes, but the back-face chamfer requires a flip; recommend 4+1 with tombstone if batch >20 pcs.  
> **User:** Quote 50 pcs, 7075-T6, hard anodize 25 um.  
> **Agent:** Returns structured quote with machining hours, material cost, surface treatment cost, and NRE spread.

This is not retrieved from a FAQ. It is grounded in parsed STEP geometry plus local manufacturing knowledge, generated by the local AMD-backed LLM.

## Track 3 starter demo: robot simulation on AMD Radeon GPU

New to robotics, or want to learn how to run robot simulation on AMD GPUs? This reference demo is a quick, hands-on starting point for Track 3 participants — an end-to-end pipeline where a Franka Panda arm picks fruit off a table and places it in a bowl, built on the **Genesis** physics engine and **LeRobot**, running on an AMD Radeon (ROCm) GPU.

▶️ **Demo repo & videos:** https://github.com/wangxunx/franka_fruit_pick_demo

What you'll learn:
- Set up a robot simulation environment on an AMD Radeon GPU (ROCm), using the prebuilt ROCm PyTorch wheels
- Build a scene and run physics simulation with **Genesis**
- Record data, apply domain randomization, and train a visuomotor policy with **LeRobot**
- Go end-to-end — from a scripted pick-and-place to a trained, closed-loop policy, with evaluation videos

> Note: this is a learning reference to show how to run simulation and training on an AMD GPU with `genesis-world` + `lerobot`; the trained model's success rate is not guaranteed.
