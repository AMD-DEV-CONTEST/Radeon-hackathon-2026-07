# ColorGraph：基于时空调色图的本地风景视频 AI 调色工具

> 文档类型：项目产品与技术规格  
> 参赛赛道：赛道一——多模态内容创作工具开发  
> 保存日期：2026-07-26  
> 实现状态请参阅 [IMPLEMENTATION_AUDIT.md](IMPLEMENTATION_AUDIT.md)。

## 1. 项目概述

**一句话定位：**

> ColorGraph 是一款运行于 AMD Radeon GPU + ROCm 的本地风景视频调色工具。它通过多模态 Agent 理解视频内容和用户审美意图，自动生成由场景级风格、镜头级校正、镜内关键帧和局部语义蒙版组成的可编辑调色方案。

项目定位在 **赛道一：多模态内容创作工具开发**。

Agent 是系统内部的决策与交互方式，但核心产物是经过调色的视频以及可复用、可编辑的创作资产，因此不应把项目包装成通用 Agent。更合适的参赛叙事是：

> 不用生成模型逐帧重绘视频，而是让 AI 像调色师一样理解画面、编排调色节点，并由 Radeon GPU 高效、稳定地执行。

## 2. 灵感与核心问题

目前常见 AI 调色方案主要有三类：

- 整段视频套用一份固定 LUT；
- 每个镜头独立做自动校色；
- 使用生成模型逐帧重新生成风格化视频。

它们分别存在明显问题：

| 方案 | 主要问题 |
| --- | --- |
| 整段单 LUT | 无法适应室内外、明暗、天气和镜头内容变化 |
| 每镜头独立处理 | 容易失去全片统一风格，镜头之间可能跳色 |
| 逐帧生成 | 成本高、不可编辑，可能改变云层、树叶、水面等结构并产生闪烁 |

真正的专业调色并不是“找到一个好看的滤镜”，而是同时处理：

- 整个场景需要什么视觉风格；
- 每个镜头的曝光和白平衡是否一致；
- 一个镜头内部的光照是否随时间变化；
- 天空、植被、水面、山体是否需要不同处理；
- 调整后是否产生过曝、色带、光晕和闪烁。

因此，本项目的核心不是“生成一份 LUT”，而是生成一个 **Temporal-Spatial Grade Graph，时空调色图**。

## 3. 目标用户与需求

目标用户是有短视频制作需求、但缺少专业调色经验的：

- 风景摄影师和无人机创作者；
- 旅行 Vlog 和户外视频作者；
- 新媒体内容团队；
- 独立摄影和剪辑人员；
- 摄影、影视和新媒体教学用户。

用户的核心需求不是获得一个完全不可修改的结果，而是：

1. 快速获得质量可靠的第一版调色；
2. 不同镜头保持统一视觉风格；
3. 自动处理镜头内部的光照变化；
4. 能用自然语言修改具体区域和时间段；
5. 输出 LUT、参数和蒙版，后续仍可编辑；
6. 原始视频完全在本地处理。

典型交互：

> “整体做成清冷、自然的纪录片风格，天空保留层次，植被不要荧光绿，远山可以稍微偏冷。”

系统应将这句话转化为具体节点，而不是直接重新生成视频。

## 4. 核心设计：时空调色图

### 4.1 时间结构

视频按五级结构组织：

```text
项目 Project
  └── 场景 Scene
       └── 镜头 Shot
            └── 镜内光照段 Sub-shot
                 └── 参数关键帧 Keyframe
```

| 层级 | 负责的问题 | 典型参数 |
| --- | --- | --- |
| 项目级 | 色彩管理和最终输出标准 | 输入空间、工作空间、输出空间 |
| 场景级 | 多个镜头共享的视觉身份 | LUT、色彩风格、整体对比关系 |
| 镜头级 | 单个镜头的技术校正 | 曝光、白平衡、CDL、基础曲线 |
| 镜内段 | 镜头内持续发生的光照变化 | 动态曝光、动态色温、LUT 强度 |
| 关键帧 | 参数随时间的具体变化 | 时间点、参数值、插值方式 |

例如，无人机从森林飞向天空时：

- 森林、山体和天空仍属于同一镜头；
- 不应该切成多个硬片段；
- 应在天空占比和画面亮度发生变化的位置建立关键帧；
- Exposure 和高光压制强度随时间平滑变化。

### 4.2 空间结构

每个调色节点还需要明确作用区域：

- 全画面；
- 天空；
- 云层；
- 水面；
- 植被；
- 山体；
- 雪地；
- 前景、中景、远景；
- 用户指定区域。

因此，一个节点的完整定义是：

```text
节点类型 + 时间范围 + 空间范围 + 参数 + 参数变化轨道
```

例如：

```json
{
  "type": "masked_grade",
  "time_scope": "shot_03",
  "spatial_scope": "sky",
  "operations": {
    "highlight": -0.18,
    "saturation": 0.06
  },
  "keyframes": [
    {"time": 0.0, "strength": 0.4},
    {"time": 4.2, "strength": 0.7}
  ]
}
```

## 5. 建议的调色节点语法

MVP 不应允许 Agent 随意创建任何节点，而应限定一套稳定的 **Landscape Grade Grammar，风景调色语法**。

推荐节点顺序：

```text
输入色彩转换
      ↓
基础曝光与白平衡
      ↓
动态范围与高光处理
      ↓
局部语义区域调色
      ↓
场景级创作 Look / LUT
      ↓
Look 后微调
      ↓
输出色彩转换
```

### 节点与问题的对应关系

| 画面问题 | 推荐节点 |
| --- | --- |
| 整体过亮或过暗 | Exposure、Offset、CDL |
| 整体偏冷、偏暖或偏绿 | Temperature、Tint、色轮 |
| 反差过大 | 亮度曲线、阴影/高光轮 |
| 云层高光过亮 | 高光曲线，必要时叠加天空蒙版 |
| 天空过亮但地面正常 | 天空蒙版或渐变蒙版 + Exposure |
| 植被荧光绿 | 植被蒙版 + Hue-vs-Hue/Saturation |
| 天空和海水需要不同颜色 | 天空、水面两个语义蒙版 |
| 雪地偏蓝 | 白平衡 + 雪地蒙版保护 |
| 雾景缺少空间层次 | 深度蒙版 + 局部对比度和饱和度 |
| 多镜头需要统一电影感 | 场景级 LUT |
| 镜头从阴影移动到阳光 | Exposure/WB 参数关键帧 |
| 延时摄影亮度闪烁 | Deflicker 工具 + 平滑曝光轨道 |

基本原则：

- **LUT 负责创作风格；**
- **色轮、CDL 和曲线负责技术校正；**
- **关键帧负责时间变化；**
- **蒙版负责空间差异。**

不能使用 LUT 修复所有问题，因为固定 LUT 不知道当前是什么镜头、什么时间，也不知道同一种蓝色来自天空还是水面。

## 6. Agent 与工具的职责分工

系统的关键原则是：

> Agent 做语义决策，工具做精确计算。

### 6.1 多模态 Agent 负责

| 能力 | 输出 |
| --- | --- |
| 理解用户意图 | 风格方向、保护对象、禁止项 |
| 理解代表帧 | 天气、时间、地形、主要区域、画面风险 |
| 场景归组 | 哪些镜头应该共享 Look |
| 选择节点模板 | 应使用色轮、曲线、LUT 还是蒙版 |
| 确定节点作用域 | 项目、场景、镜头、时间段或区域 |
| 判断是否需要蒙版 | 天空、水面、植被、远山等 |
| 生成分割提示 | 语义描述、框、点、正负提示 |
| 确定参数搜索范围 | 曝光、饱和度、LUT 强度等合理范围 |
| 比较候选结果 | 使用固定规则进行 A/B 判断 |
| 多轮修改 | 将自然语言修改映射到已有节点 |
| 解释方案 | 说明为什么创建某个节点 |

Agent 不直接输出像素级蒙版，也不直接负责视频编码或精确计算每一帧参数。

### 6.2 确定性工具负责

| 工具能力 | 任务 |
| --- | --- |
| 视频解码与编码 | FFmpeg |
| 镜头边界检测 | 精确得到起止帧 |
| 代表帧抽取 | 避免让大模型分析所有帧 |
| 直方图和示波器 | 曝光、RGB、色度、饱和度分析 |
| 变化点检测 | 发现镜内光照和色温变化 |
| 语义分割 | 生成天空、植被、水面等逐像素蒙版 |
| 深度估计 | 区分近景、中景和远景 |
| 蒙版跟踪 | 保持视频中区域连续稳定 |
| 参数插值 | 样条曲线、平滑和变化速度限制 |
| 参数优化 | 网格搜索、贝叶斯优化或候选采样 |
| GPU 调色渲染 | 色轮、曲线、LUT、蒙版合成 |
| 技术质检 | 剪裁、色域、色带、闪烁、光晕 |
| 导出资产 | 视频、LUT、CDL、JSON、蒙版 |

Agent 调用的应该是高层工具，例如：

```text
detect_shots()
analyze_shot()
segment_region("sky")
detect_lighting_changes()
render_preview()
score_technical_quality()
compare_previews()
export_grade_package()
```

而不是让 Agent 直接操作底层 OpenCV 或视频编码命令。

## 7. 蒙版系统设计

风景场景至少需要五类蒙版。

### 7.1 几何蒙版

包括线性渐变、圆形、多边形和手绘区域。

适合：

- 天空渐变；
- 地平线以上区域；
- 局部压暗；
- 暗角。

它们速度快、稳定，很多画面不必调用复杂 AI 分割。

### 7.2 颜色限定蒙版

根据 Hue、Saturation 和 Luminance 选择区域。

适合：

- 某种绿色植被；
- 暖色日落；
- 高亮云层。

缺点是不能区分相同颜色的不同语义对象。

### 7.3 语义分割蒙版

MVP 建议支持：

```text
天空、云、水面、植被、山体、雪地、道路、建筑、雾
```

Agent 决定目标类别，分割模型负责生成真实 mask。

### 7.4 提示式蒙版

当用户说：

> “只压暗左侧被阳光照亮的云层。”

多模态模型负责提供框、点或文字目标，分割模型负责输出精确区域。

### 7.5 深度蒙版

用于区分：

- 前景；
- 中景；
- 远景；
- 天空。

适合处理：

- 大气透视；
- 雾景层次；
- 远山偏冷；
- 近景增强对比度。

多个蒙版需要支持逻辑组合，例如：

```text
需要调色的天空
=
语义天空
AND 高亮区域
AND NOT 太阳
AND NOT 山体
```

即建立一个 **Mask Graph**，由 Agent 编排逻辑，工具执行像素运算。

## 8. 镜内时间变化处理

镜头内部不应逐帧独立预测完整 LUT，否则容易闪烁，也难以编辑。

推荐流程：

1. 工具计算亮度、色温、RGB 分布和语义占比时间序列；
2. 检测明显变化点；
3. 选择少量代表性锚点；
4. Agent 判断哪些参数需要随时间变化；
5. 参数预测器只在锚点上给出值；
6. 工具进行平滑插值；
7. 限制参数最大变化速度和加速度。

例如：

```json
{
  "parameter": "exposure",
  "keyframes": [
    {"frame": 0, "value": 0.15},
    {"frame": 96, "value": 0.32},
    {"frame": 182, "value": -0.06}
  ],
  "interpolation": "pchip"
}
```

处理原则：

- 硬切：建立新镜头；
- 缓慢光照变化：建立关键帧；
- 持续进入新光照环境：建立 Sub-shot；
- 闪光、遮挡和快速摇镜：视为瞬态，不自动修改长期调色；
- 叠化转场：两侧调色状态随转场权重混合。

## 9. 怎样判断结果“好不好”

工程上不需要定义绝对审美，而是建立两级评价体系。

### 9.1 硬质检

出现严重问题的候选直接淘汰：

| 检查项 | 典型问题 |
| --- | --- |
| 高光剪裁 | 云层和太阳附近变成大片纯白 |
| 阴影压死 | 树林和山体失去细节 |
| 超出色域 | 颜色失真、断层 |
| 过饱和 | 天空塑料蓝、植被荧光绿 |
| 色带 | 天空渐变出现阶梯 |
| 时间闪烁 | 相邻帧亮度和色彩跳动 |
| 蒙版抖动 | 地平线和树梢边缘闪动 |
| 蒙版光晕 | 山体边缘出现亮边或暗边 |
| 结构损失 | 云、树叶、水面纹理被破坏 |
| LUT 异常 | 色相折叠或不连续 |

这些全部由数值工具完成。

### 9.2 软评分

通过硬质检的结果，再比较：

- 是否符合用户意图；
- 是否自然；
- 多镜头是否属于同一视觉风格；
- 风景层次是否清晰；
- 时间变化是否稳定；
- 是否具有足够的视觉吸引力。

推荐采用：

```text
候选生成
→ 硬质检淘汰
→ 技术质量评分
→ 意图匹配评分
→ 多模态 Agent 按固定规则进行 A/B 比较
→ 输出 2～3 个候选供用户选择
```

不要让一个模型直接给所有结果打绝对分数。成对比较通常更容易解释，也更不容易出现“为了高分不断增加饱和度和对比度”的指标投机。

Agent 的风景评价规则应明确关注：

- 天空是否保留云层；
- 植被是否自然；
- 水面是否保留反光和纹理；
- 山体是否有空间层次；
- 雾景是否被过度去雾；
- 雪地是否偏蓝或过曝；
- 地平线是否产生光晕。

## 10. 模型需要学习什么

不建议训练一个端到端“视频输入—成片输出”的大型模型，而应拆成四种能力。

### 场景理解

识别：

- 山景、海岸、森林、雪景、雾景；
- 日出、日落、阴天、蓝调时刻；
- 前景、中景、远景；
- 天空、植被、水面等关键区域；
- 画面当前的主要技术问题。

MVP 可由本地多模态模型完成。

### 节点策略

输入场景分析和用户意图，输出：

- 节点模板；
- 节点顺序；
- 时间和空间作用域；
- 需要哪些蒙版；
- 参数搜索范围。

第一版采用规则库 + 多模态模型，不急于训练专用策略模型。

### 参数预测

输入镜头特征、色彩统计和目标风格，输出：

- Exposure；
- Temperature/Tint；
- CDL；
- 曲线控制点；
- LUT basis 权重；
- 局部调整值。

这部分更适合小型 CNN、MLP 或 Transformer，而不是语言模型。

### 偏好评审

输入原始画面、候选 A/B 和用户意图，输出：

- 更符合要求的候选；
- 选择原因；
- 是否存在技术硬伤。

这是后续最值得积累用户数据的部分。

## 11. 数据与 Look 模板建设

比赛阶段不需要大规模训练集，更适合建立一个小而高质量的 **Landscape Gold Set**。

建议准备 30～50 个短镜头：

| 场景 | 建议数量 |
| --- | ---: |
| 阴天山景 | 5–8 |
| 日出、日落 | 5–8 |
| 海岸和湖泊 | 5–8 |
| 森林 | 5–8 |
| 雪景 | 4–6 |
| 雾景 | 4–6 |
| 镜内光照变化 | 6–10 |

素材优先级：

1. 自己拍摄并保留原始文件；
2. 授权明确、允许修改和展示的开放素材；
3. 学术数据集仅用于研究和验证，并单独核查许可证；
4. 不直接使用来源不明的电影片段和商业 LUT 包。

每个镜头应保存：

- 中性校正版本；
- 1～3 个创作版本；
- 节点图；
- 调色参数；
- 参数关键帧；
- 蒙版；
- 自然语言意图；
- 失败候选及原因；
- 调色人员的选择结果。

此外，建立 8～12 个原创 Look Recipe，例如：

- Natural Travel；
- Cool Documentary；
- Warm Sunset；
- Foggy Cinematic；
- Premium Landscape；
- Muted Forest；
- Clean Coast；
- Blue Hour；
- Vintage Nature。

每个 Look 包含基础 LUT、适用场景、建议强度、禁用条件和参考缩略图。Look 是初始方案，不是直接应用到所有镜头的最终结果。

## 12. 推荐技术架构

```text
视频 / 参考图 / 自然语言
              ↓
媒体解析与色彩空间确认
              ↓
镜头检测与场景归组
              ↓
代表帧、色彩统计和时间序列分析
              ↓
多模态 Agent 生成 Typed Grade Graph
              ↓
语义分割、深度估计、蒙版跟踪
              ↓
参数预测与候选搜索
              ↓
ROCm GPU 调色渲染
              ↓
技术质检与多模态候选比较
              ↓
用户自然语言修改
              ↓
局部节点重算和增量渲染
              ↓
视频 + LUT + 参数 + 蒙版 + 报告
```

候选技术组件：

| 模块 | 候选方案 |
| --- | --- |
| GPU 推理 | PyTorch + ROCm |
| 视频处理 | FFmpeg、OpenCV |
| 色彩管理 | OpenColorIO |
| 镜头检测 | PySceneDetect 或轻量镜头检测模型 |
| 语义分割 | SegFormer、Mask2Former 等 |
| 提示式分割与传播 | SAM 2 类模型 |
| 深度估计 | Depth Anything 类模型 |
| 多模态 Agent | 本地部署的 7B/8B 视觉语言模型 |
| 节点渲染 | PyTorch GPU 算子或自定义 ROCm 调色管线 |
| 前端 | Gradio MVP，后续 React 时间线 UI |

所有候选模型都需要先在指定 Radeon 环境做兼容性验证，尤其避免依赖强绑定 CUDA 的自定义算子。

## 15. 建议的开发路径

### 阶段一：证明核心假设

先完成最小闭环：

```text
镜头检测
→ 每镜头曝光/白平衡
→ 镜内曝光关键帧
→ LUT 场景共享
→ GPU 渲染
→ 与整段单 LUT 对比
```

只有当动态方案明显优于单 LUT 时，才继续扩展 Agent 和蒙版能力。

### 阶段二：建立确定性调色引擎

实现：

- Typed Grade Graph；
- 色轮、曲线、LUT；
- 时间关键帧；
- 参数平滑；
- 视频渲染；
- JSON 导入导出。

这部分是系统地基，应先于复杂 Agent。

### 阶段三：加入空间调色

按优先级实现：

1. 天空；
2. 植被；
3. 水面；
4. 山体；
5. 深度近、中、远景。

同时加入蒙版时序稳定和光晕检测。

### 阶段四：加入多模态 Agent

Agent 负责：

- 场景分析；
- 节点模板选择；
- 参数范围规划；
- 蒙版目标生成；
- 多轮自然语言修改；
- 候选解释。

### 阶段五：建立验收闭环

加入：

- 剪裁和色域检测；
- 时间闪烁；
- 蒙版抖动；
- 天空色带；
- 候选生成；
- A/B 偏好比较；
- 自动局部修复。

### 阶段六：完成比赛演示

重点完成：

- 清晰的时间线 UI；
- 单 LUT、逐镜头校色、ColorGraph 三方对比；
- Radeon GPU 性能数据；
- 多种 Look；
- 可编辑资产导出；
- 完整英文 README 和演示视频。

| 完整输入—处理—输出，40 分 | 视频、提示词输入；自动分析、规划、渲染、验证；输出视频和调色资产 |

- CPU 与 Radeon GPU 的速度对比；
- 输出画面的稳定性和多样性。

## 17. 核心创新点

最终可以凝练为三个贡献。

### Landscape Grade Grammar

将风景调色知识结构化为：

> 场景问题 → 节点类型 → 时间作用域 → 空间作用域 → 参数约束 → 验收标准。

### Temporal-Spatial Grade Graph

不是一份固定 LUT，而是同时包含：

- 场景级创作 Look；
- 镜头级基础校正；
- 镜头内部关键帧；
- 天空、植被、水面和深度蒙版。

### Verifier-driven Agent Loop

系统不是生成一次就结束，而是：

```text
理解 → 规划 → 渲染 → 硬质检
→ 候选比较 → 定位问题
→ 只修改相关节点 → 增量渲染
```

## 18. 最终项目主张

可以用下面这段作为项目介绍的基础：

> 现有自动调色工具通常对整段视频应用固定 LUT，或逐镜头、逐帧独立处理，难以同时保证风格统一、时间稳定和局部可控。ColorGraph 在 AMD Radeon GPU 和 ROCm 平台上，将用户的自然语言意图与视频内容编译为一个可编辑的时空调色图：场景级 LUT 建立统一视觉风格，镜头级参数完成曝光与白平衡匹配，时间关键帧适应镜内光照变化，语义和深度蒙版分别处理天空、植被、水面和远景。确定性 GPU 调色引擎负责稳定执行，多级质量评估负责发现过曝、色带、闪烁和蒙版光晕，最终输出视频以及可复用的 LUT、参数和蒙版资产。

项目最重要的验证目标不是“AI 能不能生成好看的颜色”，而是：

> **在同一段包含不同镜头和镜内光照变化的风景视频上，ColorGraph 能否比整段单 LUT 更统一，比逐帧自动校色更稳定，并且允许用户精确修改某个时间段或某个画面区域。**
