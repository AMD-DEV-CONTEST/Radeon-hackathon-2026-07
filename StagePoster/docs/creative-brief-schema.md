# StagePoster Creative Brief Schema v1.0

## Goal

Define what the frontend submits, and how the backend interprets it.

**MVP output:** vertical music event poster

**Core principle:** The frontend submits creative intent. Prompts and model
parameters are generated by the backend.

## 1. Creative Brief Positioning

The frontend **must not** submit a "final model prompt" as the only input.

The frontend submits structured requirements:

- Event facts
- Performer info
- Exact copy
- Visual style
- Asset bindings
- Output specifications

The backend converts this into an internal **Generation Plan**, which contains:

- Workflow ID and version
- Positive prompt
- Negative prompt
- Asset preprocessing plan
- Image conditioning method
- Model parameters
- Composition template
- Post-processing plan
- Output specifications

The Generation Plan is an internal backend object. The frontend does not need
to know its format.

## 2. Generation and Composition Layers

**Model handles:**
- Background
- Lighting and shadow
- Atmosphere
- Composition
- Texture
- Style
- Character integration

**Deterministic composition handles:**
- Logo
- Event name
- Date
- Time
- Venue
- Ticket info
- Lyric excerpts
- Footer text

**Final pipeline:**

```
Creative Brief (frontend)
        ↓
Brief Validator
        ↓
Style Interpreter (Qwen LLM)
        ↓
Generation Plan (backend internal)
        ↓
ComfyUI + Z-Image Turbo
        ↓
Raw candidate images
        ↓
Deterministic Composition (Go)
        ↓
Final poster PNG
        ↓
Qwen Vision Review
        ↓
Optimized final poster
```

## 3. Brief Schema

```json
{
  "brief": {
    "event": {
      "title": "Abyssal Kingdom Festival",
      "artist": "Maverick",
      "date": "2026-08-21",
      "time": "20:00",
      "venue": "Void Arena",
      "presalePrice": "$45",
      "doorPrice": "$60"
    },
    "branding": {
      "artistLogoAssetId": "asset_01K...",
      "eventLogoAssetId": "asset_01K...",
      "sponsorLogoAssetIds": ["asset_01K..."]
    },
    "visual": {
      "style": "dark fantasy editorial",
      "theme": "abyssal gothic kingdom",
      "musicGenre": "gothic metal",
      "mood": ["epic", "mysterious", "ritualistic"],
      "preferredColors": ["black", "aged ivory", "deep red"]
    }
  },
  "assets": ["asset_01K...", "asset_01K..."]

```

## 4. Required Fields

| Field | Description |
|---|---|
| `event.title` | Event title (required) |
| `event.artist` | Artist or band name (required) |
| `event.date` | Date in `YYYY-MM-DD` format (required) |
| `event.time` | Time in `HH:MM` format (required) |
| `event.venue` | Venue name (required) |
| `visual.style` | Visual style descriptor (required) |
| `visual.theme` | Theme descriptor (required) |
| `visual.musicGenre` | Music genre (required) |
| `visual.mood` | Array of mood keywords (required, 1-5 items) |
| `visual.preferredColors` | Color palette (optional) |

## 5. Validation Rules

- `event.title`: non-empty, max 100 characters
- `event.date`: valid `YYYY-MM-DD`
- `event.time`: valid `HH:MM` (24h)
- `visual.mood`: 1 to 5 items, each max 50 characters
- `visual.preferredColors`: max 5 items
- `assets`: max 10 items

The backend uses strict JSON decoding. Unknown fields are rejected.

## 6. Brief to Prompt Translation

The backend does NOT pass the brief directly to the model. Instead:

1. **Style Interpreter** (Qwen LLM) reads the brief and generates 3 distinct
   design direction specs.
2. Each spec contains:
   - `variant_key`: machine-readable identifier
   - `variant_name`: human-readable name
   - `positive_prompt`: detailed image description
   - `negative_prompt`: what to avoid
   - `style_modifiers`: additional style parameters
3. The selected spec is filled into the ComfyUI workflow template.

The frontend never sees or manipulates the actual prompts sent to ComfyUI.

## 7. Output Specifications

Default output format:

| Property | Value |
|---|---|
| Format | PNG |
| Resolution | 1024 × 1536 (2:3 portrait) |
| Color space | sRGB |
| Max file size | ~2 MB |
| Thumbnail | 256 × 384 |
