## 0. 一页结论（先看这里）

| 维度 | 现状评级 | 最大差距 |
|---|---|---|
| 推理后端 | C（无流式、无重试） | `deepseek_backend.py` 用 `urllib` + `"stream": False`，整段生成后才回传；`app.js` 的 `answer` 事件承载整段文本 → **没有 token 级流式** |

| 多 Agent 协作 | D | 画布仅绘制 SVG 连线，`runCanvasWorkflow` 把节点名拼成字符串丢给 `/task`，而 `/task` **只返回静态计划不执行** |

### 1.1 MemOS —— 记忆操作系统（对标：memory_adapter.py）

**① 真正提供的能力（来自 `MemOS/src/memos/mem_os/core.py` 的 `MOSCore` 类）**
- 统一记忆 API：`add()` / `search()` / `get()` / `get_all()` / `update()` / `delete()` / `delete_all()`，以及 Cube 管理 `create_cube_for_user()` / `register_mem_cube()` / `share_cube_with_user()` / `dump()` / `load()`。
- 多模态 + 图（Neo4j）+ 向量（Qdrant）统一存储；`chat()` 自带检索增强对话。
- **异步摄取**：`mem_scheduler`（`GeneralScheduler`）毫秒级延迟、生产级高并发；`mem_reorganizer` 记忆整理。
- **记忆反馈与校正**：自然语言反馈纠正/补充/替换记忆（README News 2026-05-09）。
- **MemScheduler**：任务异步化（`mem_scheduler.py`）。
- 多种集成入口：Cloud API（托管）、Self-Host（`uvicorn memos.api.server_api:app --port 8000`，Neo4j+Qdrant）、OpenClaw Cloud Plugin、Local Plugin（`@memtensor/memos-local-plugin`，**100% on-device**，SQLite + FTS5+向量混合检索 + 智能去重 + 分层技能进化 + 多 Agent 协作 + Memory Viewer 仪表盘）。

**② 我们的桥接方式是否合理？真实项目推荐什么？**
- 现状：`memory_adapter.py` 用 **SQLite 直连自研 schema**（`memories` 表 + `memory_index` keyword 表），与 MemOS 真实 SDK/API 完全脱钩，仅借用了「7 层」概念命名。
- 评价：自研 schema 在「离线可用、零依赖」上合理，但**放弃了 MemOS 的核心价值**——混合检索（FTS5 关键词 + 向量）、去重、异步调度、跨 Cube 隔离共享、记忆反馈环路。
- 真实推荐（按我们「本地私有」定位，最贴合 `memos-local-plugin`）：直接**复用其 SQLite schema 与 FTS5+向量混合检索**，而不是自研 keyword 正则表。若想保留「不依赖 MemOS 进程」的诉求，至少应把检索从「LIKE + keyword IN」升级为 **FTS5 + 向量双路召回 + Rerank**。

**③ 我们没借鉴但应借鉴的生产级特性**
- 混合检索（FTS5 + 向量）+ Rerank；智能去重（`smart dedup`）。
- 异步摄取调度（避免同步写阻塞主链路——见 `engine_xai.py:172` 每次对话后**同步** `memory.write`）。
- 记忆反馈校正环路（`/recall` 之后应有「纠正这条记忆」的闭环）。
- 跨 Cube 隔离/共享（`share_cube_with_user`）→ 对应我们多引擎（openclaw/hermes）记忆隔离诉求。
- MCP Server 暴露记忆（`mem_mcp`）。

**③ 我们应借鉴的生产级特性**

- **cron prompt 隐形 unicode 注入扫描** → 我们完全无。
- **线程级中断 / gateway 优雅重启 drain** → 我们 `server_xai.py` 用 `SIGINT` 直接关。

### 1.5 openclaw —— 个人 AI 助手 / 执行网关（对标：openclaw_adapter）

**① 真正提供的能力**
- **Local-first Gateway 单一控制面**：sessions / channels / tools / events 统一管理。
- 20+ 消息渠道；**多 Agent 路由**（workspace + per-agent session 隔离）。
- Voice Wake + Talk Mode；Live Canvas（A2UI）；first-class tools（browser/canvas/nodes/cron/sessions/Discord/Slack 动作）。
- **沙箱**：`agents.defaults.sandbox.mode: "non-main"` → 非 main session 跑 Docker 沙箱；默认 deny `browser/canvas/nodes/cron/discord/gateway`。
- **DM pairing**（`dmPolicy="pairing"` + 本地 allowlist）、operator 命令（`/status /new /compact /trace /usage`）、**模型 failover**。

**② 我们的桥接方式是否合理？真实项目推荐什么？**
- 现状：`openclaw_adapter.py` 关键决策——**本地工具（exec/file_read/file_write/…）用 Python 原生 `subprocess` 直连**（注释明言「不依赖 OpenClaw CLI 的确切参数格式，可靠性最高，避免功能没反应/空错误」）；而 MCP/skill/cron/channel 走 `subprocess` 调 `openclaw` CLI。
- 评价：**「本地高频工具直连 + CLI 兜底低频操作」在可靠性维度是正确取舍**（规避 CLI 版本/参数漂移），比盲目全量 subprocess 更稳。
- 真实推荐：OpenClaw 把 Gateway 当作 **control plane**，应通过 **Gateway HTTP / WebSocket / RPC 协议**（`docs.openclaw.ai/reference/rpc`）或 CLI 子命令或插件接入。我们当前缺的是**没有消费 Gateway 的事件总线/长连接流式**。

**③ 我们应借鉴的生产级特性**
- **Gateway 作为统一控制面/事件总线**：我们应有统一 Gateway 暴露 SSE 事件（而非 `engine.chat` 各自 yield）。
- **沙箱隔离**（`sandbox.mode`）：我们 exec 直接 host 跑，无隔离。
- **per-agent session 隔离 + 工具作用域 deny 列表**。
- **DM pairing / 审批** 对接我们 Guardian。
- **模型 failover**（多 provider 回退）→ 我们单一 DeepSeek，失败即崩。
- **graceful 重启**（对比 hermes 的 drain）。

- **CrewAI**（44k+★）：**角色驱动**（Agent 有 role/goal/backstory + Task + Process 顺序/层级），最直观、最快原型。
- **AutoGen**（36k+★，微软）：**对话驱动 group chat**，GroupChatManager 决定下一发言者，易加人类参与者，内置沙箱代码执行。
- 对标：我们 OCTO_VEC 参考应吸收 **LangGraph 的 Shared State + Checkpointer（断点恢复）+ 条件边**，而非仅抄 OCTO_VEC 的「PM 拆任务」表层。

## 4. 落地路线建议（按优先级串起来）

**P0（体验与安全底线，建议第一批）**
1. 推理后端改 **token 级流式**（`deepseek_backend.py` 改 `stream:true` + SSE 逐 token）+ 前端 `app.js` 逐字追加。
2. 代码块 **语法高亮 + 复制**（引入 highlight.js，替换 `appendCodeBlock` 的 `textContent`）。
3. **停止生成** 按钮 + 服务端生成器取消传播（`engine.chat` 支持 cancel）。
4. **画布真正执行**：建执行引擎（参考 OllamaFlow `ExecutionManager` + `WorkerPoolManager`），节点带变量传递，替换「拼字符串丢 /task」。
5. **Guardian 完整接入**：`engine_xai.chat` 所有工具调用前置 `before_tool_call`（接 `ApprovalQueue` + `PermissionTier`）。
6. **沙箱隔离** + **全路径穿越校验** + **external secrets vault**（替换明文 `DEEPSEEK_API_KEY`）。

**P1（显著价值，第二批）**
7. 推理/工具调用 **指数退避重试**（参考 OllamaFlow `retry-handler.ts`）。
8. 记忆 **混合检索（FTS5+向量）+ 异步写入**（解 `engine_xai.py:172` 同步瓶颈）。
9. **per-agent token/成本追踪** + **结构化日志 + 审计落盘** + **基础 metrics**。
10. **会话管理**（列表/切换）+ **Markdown 渲染** + 规范化错误/加载态。
11. **任务表 + FIFO 队列 + watchdog 超时**（OCTO_VEC ATP）。
12. **审批队列打通前端**（批准/拒绝）+ **P1 留痕** + **注入扫描**。
13. **任务后真实安全扫描**（Semgrep/Gitleaks/Trivy via Docker）。
14. 模型 **failover** 多 provider 回退。

**P2（增强，远期）**
15. 真实 **GEPA 进化**（变异→评估→约束门→复审）。
16. **LangGraph 式状态机 + Checkpointer 断点恢复** + 人工 in-loop。
17. **插件/MCP 市场**、workflow **版本化/DSL 导出**。
18. **SIEM/OpenTelemetry 导出**、移动端 PWA、A/B prompt 版本。
