▸ 第 1 层 Sub Agent 层 — 专业执行器 领域分工 · 独立上下文 · 可并行
file-agent
文件搜索/读写/整理/格式转换/内容问答。操作本地文件系统，最常用但也最常卡。
最常用 熔断: 3次/5分钟
app-agent
应用操作：安装/卸载/打开/界面交互。Android 通过 adb，mac 通过 open 命令。
平台操作 熔断: 2次/3分钟
browser-agent
网页交互：打开URL、搜索、点击、表单、截图。需浏览器驱动。
网页交互 熔断: 2次/3分钟
search-agent
深度检索总结：多轮RAG，输出质量高但慢（~10s）。单次任务限 1-2 次调用。
搜索总结 熔断: 3次/2分钟
computer-agent
macOS 系统操作：设置/窗口管理/进程/系统命令。替代 shell_executor 处理系统级任务。
系统操作 熔断: 2次/3分钟
inherit_agent_id
延续任务：新 Sub Agent 继承同名历史 Sub Agent 的完整对话记忆，实现上下文连续性。
记忆延续
▸ 第 2 层 引擎层 — XAI Engine 核心 状态管理 · 请求路由 · 工具执行
server_xai.py
HTTP 服务器入口。路由所有 /api/* 端点，管理 LATEST_STATUS 心跳，事件推送。
core/engine.py
引擎核心。初始化 MemoryCore、模型后端、ActionBus；seed_agents 预置数字员工；启动看门狗和熔断器。
core/execution/action_bus.py
统一执行闸门。所有文件写/删/命令执行必须经过 ActionBus → Guardian → Executor。每次执行自动注册到看门狗。
core/memory_core.py
记忆系统。SQLite 持久化，支持上下文注入、关键词召回、时间衰减排序。
core/guardian.py
安全守护。P0/P1/P2 三级风险定级，P0 拒绝执行，P1 需审批。
core/observability.py
Tracing pipeline。deque(1000) 存 span，stats() 返回成功率/平均延迟/P95。
▸ 第 3 层 容错机制层 — 自愈与降级 看门狗 · 熔断器 · 降级链
core/task_watchdog.py ★
任务看门狗。后台线程每 3s 扫描超时任务（45s 阈值），超时触发降级回调并记录日志。所有对话共享单例，进程级长期有效。
新增
core/circuit_breaker.py ★
熔断器。CLOSED→OPEN→HALF_OPEN 三态机。file-agent 连续 3 次失败熔断 5 分钟，自动降级到直接工具链。
新增
降级链（手动规则）
dispatch 取消 → 重试 1 次 → 仍失败 → 立即降级 shell_executor/edit_file/write_file 直接完成。两步失败即停。
ResilientBackend
模型后端容错。DeepSeek 主模型失败自动回退本地 Stub 模型，离线可用。
sandbox 四级回退
nsjail → firejail → sandbox-exec → setrlimit，自动检测可用沙箱，逐级软退。

关键约束总览（本架构中生效的硬限制）：
(1) 路由优先级：Sub Agent → Skill → Tool → 生成代码。禁止越级。
(2) 并行上限：单轮 dispatch_task ≤ 5 个。同 Agent 禁止同时接多个任务。
(3) 重试上限：同一工具/Agent 同方向失败 ≤ 2 次，第 3 次必须降级。
(4) 熔断阈值：file-agent 连续 3 次失败 → 熔断 5 分钟；其他 Agent 2 次 → 熔断 3 分钟。
(5) 看门狗周期：后台线程每 3 秒扫描，超时阈值 45 秒。
(6) 所有对话共享：看门狗和熔断器是进程级单例，跨对话有效，不随轮次重建。
(7) 安全闸门：ActionBus → Guardian（P0 拒绝/P1 审批）→ Executor，不可绕过。
