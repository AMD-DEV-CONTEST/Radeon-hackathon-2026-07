# XAI 控制台前端重构能力蓝图（Route A · 90% 对标 Coze / WorkBuddy / OllamaFlow）

> 底座：`xai-frontend/`（OllamaFlow liquid-glass 风格，已扶正为官方控制台）
> 目标：主流 Agent 产品 **90%+ 功能使用体验 + 小细节还原度**，再叠加我们双核架构的独有增项。
> 两条"前端调后台"路径：① 前端设置页直接改后端配置 ② 画布拖拽确认即编译执行后端工作流。

## 0. 竞品调研结论：这 6 项能力别人到底怎么做

|---|---|---|---|---|

| **2. 定时** | 定时触发器节点：id/用户id/名称/时区/触发时间/绑定工作流/参数；**间隔不可少于 1 分钟**；Cron 或预设档（每天18点…） | `FREQ=DAILY;BYHOUR=9;BYMINUTE=0`；失败重试；超时处理 | — | last_run / next_run 可视化、间隔下限校验、时区、重试策略 |

## 2. 两条"前端调后台"路径（用户明确要求）

### 2.1 前端设置页 → 后端配置
- 新增后端：`app_store` 增加 `settings` 表 + `settings_get/set`；`server_xai.py` 增加 `GET/PUT /api/settings`。
- 设置域（每个域映射后端真实字段）：
  - `engine`：default_model / temperature / top_p / system_prompt / max_tokens
  - `governance`：P0/P1/P2 阈值与是否强制二次确认
  - `memory`：分层策略、自动蒸馏开关、保留天数
  - `scheduler`：默认时区、重试次数、超时秒
  - `forward`：启用渠道（feishu/dingtalk/wecom）、webhook 占位
  - `features`：能力开关（thinking 可视化 / 迭代分支 / 画布执行 等）
- 前端：统一 `SettingsPage` 分 Tab，改完"保存即 PUT"，带"恢复默认 / 对比改动"细节（还原专业产品质感）。

### 2.2 画布拖拽 → 后端工作流
- 画布节点 `type` 映射后端可执行 ops：`llm` / `tool` / `code` / `condition` / `loop` / `variable` / `human_review` / `end`。
- "确认应用"流程：`save`(草稿) → `compile`(校验连线/必填) → `run`(调引擎执行，SSE 回传各节点状态) → `publish`(落库为可复用工作流)。
- 后端新增：`POST /api/canvas/compile`、`POST /api/canvas/run`、`GET /api/canvas/templates`。

## 3. 亮 / 暗双主题策略
- 现状：`ThemeContext` 已把 `data-theme=light|dark` + `light/dark` class 写到 `<html>`，且支持 system 跟随。
- 缺口：组件目前多用 liquid-glass.css 固定色，未全量消费 CSS 变量。
- 动作：① 在 `index.css` 定义 `:root[data-theme=light]` 与 `:root[data-theme=dark]` 两套 CSS 变量（背景/面板/文字/边框/玻璃模糊/强调色）；② 审计 Sidebar/TopBar/Placeholder/Chat 等组件改读变量；③ 顶栏主题切换已就位，补"跟随系统"指示。

## 4. 我们架构独有的增项（差异化，不是照搬）
- **双核路由可视化**：对话/任务流标注经 Intent Router 分发到 Hermes（推理）或 Grok Build（工程）。

- **本地闭环隐私指示**：明确"无云上传、隐私 100% 本地"。

## 5. 实施切片路线（纵向切片，复用任务 #127–#131 并扩展）
- **Slice A（地基）**：亮/暗全站贯穿 + 后端 `/api/settings` + Settings 页骨架（打通路径 2.1）。
- **Slice B（自动化+定时 深做）**：Phase 4+5，含 Cron+AI 生成、触发器类型、任务记忆、时区、推送、last/next run（打通路径 2.1 的配置形态）。【用户首要强调】

- **Slice E（对话增强）**：思考可视化 + 多模型 + 快捷指令 + 转发导出 + 迭代分支。

> 每条 Slice 仍保持"后端接口 + 前端页 + 验证"闭环，与前序 Phase 0/1 一致。
