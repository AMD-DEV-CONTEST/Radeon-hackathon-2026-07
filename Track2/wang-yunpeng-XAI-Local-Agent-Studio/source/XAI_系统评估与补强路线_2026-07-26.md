## 一、核心结论

**XAI 已是一个"核心能力真实可跑"的本地 AI 工作台，不是 PPT 原型**：对话/记忆/知识库/Grok Build 编程/画布/审批/进化/备忘录全部真实接后端并验证；工程侧有测试套件、CI、日志、备份、自检。

**与顶流的核心差距不在"能不能跑"，而在三道硬伤**：
1. **没有真"计算机使用 / 浏览器操作"能力**（OpenClaw 适配器全是 Stub 且未接线）；
2. **没有真"工具调用闭环"**（能力注册表是静态展示，chat 不能调度 search/kb/grok 等工具）；
3. **没有真"联网"与"多模态生成"**（知识库纯离线 BM25，无 web search / 文生图视频）。

补强优先级：**先把 Stub 接真 + 建工具调度总线 + 加联网**，这三件落地后，XAI 在操作完整度上即可追平 80% 的市面通用 agent。

## 六、补强路线图（MVP 优先）

### 阶段 0：补真实性硬伤（最优先，1–2 周）
1. **OpenClaw 适配器接真**：先接 `ego-browser` 技能 + 本地文件操作，让桌面/浏览器控制从 Stub 变可用；逐级补 Desktop/Doc/Office。
2. **能力注册表 → 真工具调度总线**：统一 `Tool` 接口，ChatConsole 可通过 `@工具` 或模型驱动调用 search / kb / grok / web；这是追平顶流"工具闭环"的关键。
3. **加 web search 工具**：真实联网，弥补知识库离线短板（可接 SearXNG / Tavily / 自股 API）。

### 阶段 1：追平顶流交互（2–4 周）
4. **真 function calling 框架**：模型输出 tool_call → 调度总线执行 → 回灌结果，形成闭环。
5. **六智能体真并发运行时**：基于 `orchestrator.run_collaborative` 让角色真消息传递。
6. **多模态生成**：文生图 / 文生视频（接云端或本地多模态模型）。
7. **主动记忆提炼**：LLM 驱动用户画像自动演化（弥补规则存储短板）。

### 阶段 2：工程与生态（持续）
8. **eval harness**：量化 agent 任务完成率/质量。
9. **可观测性**：traces + metrics dashboard。
10. **插件/连接器市场**：让能力可扩展。
11. （可选）移动端 / 协作——视商业模式，当前单机私有定位合理。

## 七、最优先的 3 件事（建议立即开干）

1. **把 OpenClaw 的浏览器/桌面适配器从 Stub 接真**（先 ego-browser），解锁"真操作"能力——这是与顶流差距最大的单点。
2. **建工具调度总线**，让 chat 能真调 search/kb/grok/web——从"展示型"变"执行型"。
3. **加 web search**——最低成本补上"联网"短板，立刻提升实用性。
