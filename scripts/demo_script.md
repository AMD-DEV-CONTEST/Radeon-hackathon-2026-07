# InventoryDoc Agent — 3 分钟 Demo 脚本（审计级可信版）

> 定位升级：从"库存分析工具"到"审计级可信的本地私有库存差异 Agent"

---

## 时间线

### 0:00-0:20 — 痛点（20 秒）

**画面**：Excel 表格 + ERP 截图 + 焦头烂额的仓储经理

**台词**：
> 每次循环盘点结束，仓储管理层开调账专题会时，手里只有一堆散乱的 Excel——10 份数据、528 个 SKU。
> 人工分析 2-3 天，还经常算错——基准选错、成本用售价、数字前后不一致。
> 这不是报表问题，是**审计可信问题**——结论能不能追责、能不能上会、能不能经得起追问？

---

### 0:20-0:40 — 方案定位（20 秒）

**画面**：InventoryDoc Agent 架构图或 Web 界面

**台词**：
> 我们做了 InventoryDoc Agent——一个本地私有部署的**库存差异审计 Agent**。
> 它不是普通的报表工具，它有确定性工作流保障计算可信，有质量门禁防止关键错误，有证据链满足审计追溯。
> 所有数据本地处理，LLM 只做报告表达，不做事实计算。

---

### 0:40-1:10 — Part 1：输入治理与 10 步工作流（30 秒）

**画面**：Web UI 操作录屏 + 展示输入验证结果

**台词**：
> 第一步不是分析，是**输入治理**。Agent 启动前用数据契约检查 10 份文件是否完整，就像企业的安全检查。
> 然后进入 10 步确定性工作流，每步都有状态和耗时，像审计日志一样可追溯。

**操作**：
1. 输入 `data/input`，点击开始分析
2. 展示**输入验证通过**的结果
3. 展示**10 步工作流 timeline**，强调每步可追踪

**关键台词**：
> 每一步都在前端展示——不是黑盒，是白盒。哪个步骤失败了一目了然。

---

### 1:10-1:40 — Part 2：三大创新 + 质量门禁（30 秒）

**画面**：展示噪音识别 / 基准选择 / 日志关联的结果表格

**台词**：
> 再说三个核心创新。
>
> 第一，**噪音自动识别**：扫描日志 344 条记录，Agent 3 秒找出 68 条 NOISE 干扰，还排除了月报和历史库存这两个噪音文件。
>
> 第二，**基准选择三维论证**：两个库存快照，Agent 按编码体系、时间窗口、数据粒度三维对比，自动选型号编码的那个——和盘点表一致。
>
> 第三，**日志关联三分类**：关键创新——按净变动量比对，不是简单的"有没有操作"。
> 14 个完全可解释、21 个部分可解释、**124 个无日志关联——这才是需要实物复核的重点**。

**强调**：
> 而且，所有这些工作都经过 7 条质量校验——关键指标不符合 Ground Truth 就直接阻断，不会生成错误的管理层报告。

---

### 1:40-2:20 — Part 3：GPU 真实推理管理层报告（40 秒）

**画面**：终端运行 benchmark + 生成报告

**台词**：
> 10 步工作流完成后，我们进入 GPU 环节——使用 AMD Radeon GPU + ROCm 运行本地 LLM 生成管理层报告。

**操作**：
1. 运行 `python3 scripts/benchmark_llm.py`
2. 展示：模型列表、推理延迟、chars/sec
3. 运行 `python3 scripts/generate_report.py`
4. 展示生成的报告：核心发现、风险分级、Top-5 SKU、行动建议

**关键台词**：
> 报告由本地 LLM 生成，所有事实数字来源于确定性工作流。LLM 只负责表达——管理层摘要、风险分级、行动建议。
> 而且我们做了 fallback——即使 GPU 不可用，也能用 mock 或 demo 模式降级，不影响工作流主产出。

---

### 2:20-2:40 — Part 4：对话追问与证据引用（20 秒）

**画面**：Web UI 对话 tab，提问 + 带证据引用的回答

**台词**：
> 分析完成后，可以在对话区追问——差异率是多少、哪个品类异常、Top SKU 是什么。
> 每个回答都带有证据引用——依据哪个 Step、哪份输出文件。
> 这不是给技术人员用的 CUI，是给管理层和审计用的对话式查询。

---

### 2:40-3:00 — 收尾（20 秒）

**画面**：质量校验 7/7 通过 + 输出文件列表 + 架构图

**台词**：
> 总结三个关键词：
>
> **审计级可信**：每步可追溯，质量门禁阻断错误，证据链支持追责。
>
> **本地私有**：数据不出设备，GPU 本地推理，零云端依赖。
>
> **业务 ROI**：2-3 天到分钟级，近百万差异精准定位，管理层直接上会。

> InventoryDoc Agent——把盘点差异分析从"2-3 天的手工猜测"变成"分钟级的审计级闭环"。

## 无 Dify 闭环说明

> 当前演示不依赖 Dify、n8n 或企业系统。
> CLI + Gradio + 本地 LLM 即可完成端到端闭环。
> Dify Agent Workbench 是二期企业化路线预告，不在当前 MVP 范围内。

## GPU 现场证据（三类）

1. **rocm-smi**：展示 AMD GPU 型号、显存、温度
2. **LLM Benchmark**：`python3 scripts/benchmark_llm.py` 展示模型列表、推理耗时、chars/sec、estimated tokens/sec
3. **报告生成元数据**：`cat data/output/report_generation_metadata.json` 展示 model、base_url、耗时、started_at/finished_at

## 录制注意事项

1. **Demo 数据**：使用 `data/input/` 中的真实某品牌数据
2. **Core 数字必须正确**：21144 / -971 / 4.6% / -989,900.97 / 68 / 14/21/124 / 7/7
3. **录屏工具**：OBS（免费）或 Loom
4. **分辨率**：1080p，字体放大到 120%
5. **语速**：中等偏快，3 分钟内讲完
6. **备份录制**：如果 demo 可能失败，提前录制一份备份
7. **字幕**：建议加中文字幕，方便评委理解
8. **GPU 展示**：如果有真实 GPU 环境，展示 `rocm-smi`、`python3 scripts/benchmark_llm.py`、LLM 推理耗时
9. **Fallback**：如果 LLM 不可用，用 `--mock` 或 `--demo` 演示报告生成
10. **事前准备**：确保 benchmark 有数据、metadata 能展示、端口没冲突
