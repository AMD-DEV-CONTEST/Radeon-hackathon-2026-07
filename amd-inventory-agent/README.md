# InventoryDoc Agent

**一句话**：上传 10 份盘点数据，10 分钟生成可直接上会的调账材料。

## 痛点

仓储管理层开库存调账专题会，需要一套能讲清差异、据以追责的材料。但现实是：

- 10 份数据分散在 CSV/XLSX/TXT，编码不统一
- 人工分析 2-3 天，还容易算错（基准选错、成本用售价、数字不一致）
- 管理层拿到报告时，差异原因已经说不清了

## 我们做了什么

**InventoryDoc Agent** 是一个完全本地部署的 AI Agent，上传盘点数据后自动完成：

1. **智能噪音识别** — 自动排除 68 条 NOISE 干扰、2 份不适用文件，无需人工筛选
2. **智能基准选择** — 自动判断哪份库存数据可以用、哪份不能用，选错基准会导致整个分析白做
3. **日志关联三分类** — 按实际出入库变动量比对（不是简单的"有没有操作"），精准区分"可解释/部分可解释/无关联"
4. **7 条质量校验** — 内置企业级规则，防止基准选错、成本用错等常见错误
5. **一键生成交付物** — Excel（4 sheets）+ 分析报告（4 章 + 附录），管理层直接上会使用

## 竞争优势

| 能力 | 人工分析 | 其他 AI 方案 | InventoryDoc Agent |
|---|---|---|---|
| 噪音自动识别 | ❌ 需手动排除 | ❌ 无此能力 | ✅ 自动识别 3 类噪音 |
| 智能基准选择 | ⚠️ 依赖经验 | ❌ 无此能力 | ✅ 自动判断可用数据 |
| 日志关联三分类 | ⚠️ 容易误判 | ❌ 简单匹配 | ✅ 按变动量精准比对 |
| 质量校验 | ❌ 无 | ❌ 无 | ✅ 7 条自动校验 |
| 分析耗时 | 2-3 天 | 30 分钟 | **10 分钟** |
| 部署方式 | N/A | 云端 API | **本地 GPU，数据不出设备** |

## 为什么选 AMD ROCm

- **数据安全**：盘点数据涉及库存金额、供应商信息，不能上传云端。本地 GPU 部署，数据全程不出设备
- **零 API 费用**：一次部署，无持续的 Token 费用。企业高频使用场景下成本优势明显
- **离线可用**：仓库网络环境差也能用，不依赖外部服务
- **开源生态**：ROCm 完全开源，无供应商锁定，可深度定制优化

## 快速开始

```bash
cd amd-inventory-agent
pip install -r requirements.txt
python run_full_workflow.py
```

## 技术栈

- **LLM 推理**：vLLM + ROCm（AMD Radeon GPU 加速）
- **Agent 框架**：LangChain + 10 步标准化工作流
- **数据处理**：Pandas + 多格式文件加载
- **UI**：Gradio Web 界面
- **平台**：AMD Radeon GPU + ROCm 6.x

## 项目结构
