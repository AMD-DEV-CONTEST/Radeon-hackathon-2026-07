# 算法设计与演化

**从「跟踪关节角」到「全身三维跟踪」—— 一次推倒重来的完整记录**

> English version: [`ALGORITHM.md`](../ALGORITHM.md)

---

## 一、问题的本质

重定向出来的动作是**运动学动画** —— 它逐帧规定了关节角度，但**不含任何物理**。

人维持一个姿势靠的是持续的主动平衡：小腿肌肉不断微调、重心不断修正。
参考轨迹只记录了姿态的**结果**，没记录维持姿态的**控制过程**。

所以直接把关节角喂给物理仿真，机器人会立刻倒下 —— 这不是重定向的问题，
是信息本身就缺失。强化学习要补的正是这块：**在满足物理定律的前提下，
既贴近参考动作、又不摔倒**。

## 二、第一版：跟踪上肢关节角（失败）

### 2.1 设计

继承 MuJoCo Playground 的 G1 Joystick 环境 —— 它经过 sim2real 验证，
自带一整套精调的平衡/接触/姿态奖励。把速度指令固定为零，
它学到的就是「站着别动」；在此基础上叠加上肢跟踪奖励：

```python
UPPER_START = 15                    # 0-11 腿, 12-14 腰, 15-28 手臂
r_track = exp(-5.0 * mean((q[15:] - ref[15:])**2))      # 权重 2.0
r_leg   = exp(-2.0 * mean((q[:15] - default[:15])**2))  # 权重 0.5
```

关掉与「做指定动作」冲突的官方奖励项（`stand_still`、`pose`、
`feet_air_time`、`feet_phase`）。

### 2.2 指标很漂亮

| | 敬礼 | 网球 |
|---|---|---|
| MJX 评估（20 episode） | 20/20 · 1000 步 · 9.08° | 20/20 · 1000 步 · 24.98° |
| 原生 MuJoCo | 500/500 · 5.64° | 500/500 · 16.94° |

### 2.3 但视频里机器人一直踉跄，手臂做不出动作

**两个成功标准都是坏的：**

| 指标 | 为什么坏 |
|---|---|
| 「500/500 步不摔」 | **站着不动也满分** |
| 「关节角误差 19.66°」 | 和视觉上「像不像」相关性弱；摔倒后手臂仍在动，误差照样小 |

**更根本的问题在奖励结构**：环境只在摔倒时终止，所以

```
不摔倒 → episode 跑满 → 累计奖励高
跟踪项只占单步奖励的一部分，不跟踪的代价远小于摔倒的代价
```

策略于是理性地收敛到「站稳 + 手臂随便挥挥」。

### 2.4 还有一个独立的致命问题

位置执行器稳态下 `q ≈ ctrl`，而 `ctrl = default_pose + action × action_scale`。
brax 的 `NormalTanhDistribution` 把 action 压在 **[−1, 1]**，
所以关节可达范围就是 `default_pose ± 0.5 rad`（±28.6°）。

实测参考轨迹要求的峰值偏移：

| 动作 | 最大需求 | 能给 | 缺口 |
|---|---|---|---|
| 敬礼 | 右肘 **1.709 rad (98°)** | 0.5 rad | **3.4×** |
| 网球 | 肩滚 **2.051 rad (118°)** | 0.5 rad | **4.1×** |

网球有 **24% 的上肢目标物理上够不到**。手臂根本抬不起来，
和奖励设计无关，训多久都没用。

**两个错误互相掩盖**：即使修好奖励让策略想跟踪，它也够不到；
即使加大 action_scale 让它够得到，它也没动力去跟踪。
单修任何一个都看不到改善 —— 这是它藏了很久的原因。

## 三、第二版：BeyondMimic 配方

### 3.1 参照对象

[BeyondMimic](https://github.com/HybridRobotics/whole_body_tracking)
（UC Berkeley Hybrid Robotics）能做跳跃转体、冲刺、侧手翻，
而且**每条动作一个策略、所有动作共用一套超参**——
正是我们要的产品形态。

**但它在 AMD 上跑不了**：

| 实现 | 依赖 | AMD |
|---|---|---|
| 官方 `whole_body_tracking` | Isaac Lab 2.1.0 + Isaac Sim 4.5.0 | ❌ CUDA 独占 |
| mjlab 复现版 | MuJoCo-**Warp** | ❌ CUDA 独占 |
| **本项目** | MuJoCo **MJX**（JAX-ROCm） | ✅ |

所以只能照着源码把 MDP 在 MJX 上重新实现，逐项对齐。

### 3.2 关键差异

| | 第一版 | BeyondMimic 配方 |
|---|---|---|
| 跟踪对象 | 上肢 14 个**关节角** | 全身 14 个 **body link 的三维位置/朝向/线速度/角速度** + 根节点 anchor |
| 下肢 | 只有姿态正则 | 一起跟踪 |
| **终止** | 只在摔倒时终止 | **跟踪误差超阈值即终止** |
| **reset** | 永远从站姿、第 0 帧 | **RSI**：参考轨迹随机时刻的完整状态（根位姿+根速度+关节角+关节速度） |
| 奖励 | joystick 遗留项 + 2 项自定义 | 6 项跟踪 + 3 项惩罚，干净 |
| 采样 | 均匀 | 自适应（对失败率高的时间段加权，本项目未实现） |

**为什么在三维空间里跟踪而不是跟踪关节角**：关节角误差和视觉相似度的
相关性很弱 —— 肩部差 5° 和腕部差 5° 对「像不像」的影响完全不同，
但在关节角空间里权重一样。三维位置误差直接对应人眼看到的差异。

**为什么早停是关键**：它让「不跟踪」直接导致 episode 被砍断，
策略没法靠站着混分。这是 DeepMimic 最重要的一招。

### 3.3 奖励（逐项对齐 `tracking_env_cfg.py`）

统一形式 `exp(−误差/std²)`：

| 项 | 权重 | std | 说明 |
|---|---|---|---|
| `motion_global_anchor_pos` | 0.5 | 0.30 | 根节点高度 |
| `motion_global_anchor_ori` | 0.5 | 0.40 | 根节点朝向 |
| `motion_body_pos` | 1.0 | 0.30 | 14 个 body 的三维位置 |
| `motion_body_ori` | 1.0 | 0.40 | 14 个 body 的朝向 |
| `motion_body_lin_vel` | 1.0 | 1.00 | 线速度 |
| `motion_body_ang_vel` | 1.0 | 3.14 | 角速度 |
| `action_rate_l2` | −0.1 | — | 动作平滑 |
| `joint_limit` | −10.0 | — | 关节限位 |

**终止条件**：`anchor_z > 0.25 m`、anchor 朝向误差 > 0.8、
四个末端（双踝、双腕）`z > 0.25 m`、超时。

### 3.4 参考轨迹的「相对对齐」

跟踪之前先把参考平移旋转到机器人当前 anchor 的水平位置和 yaw 上：

```python
delta_pos = [robot_anchor_x, robot_anchor_y, ref_anchor_z]   # z 用参考的
delta_ori = yaw(robot_anchor_quat · ref_anchor_quat⁻¹)       # 只取 yaw
body_pos_rel = delta_pos + delta_ori · (ref_body_pos − ref_anchor_pos)
```

这样**水平漂移和整体朝向不计入误差**（只考核动作形状），
但**高度和俯仰/横滚仍然要考核** —— 站不稳照样扣分。

## 四、为部署做的观测设计

这一节是我们相对 BeyondMimic 做得更靠前的地方：
**部署约束必须在训练前就体现进观测，训完再裁维度就得重训。**

宇树 SDK 的 `LowState` 只提供：

```
motor_state[i].q / .dq      29 个关节角、关节速度
imu_state.quaternion        骨盆姿态
imu_state.gyroscope         骨盆角速度
```

**没有躯干线速度**、**没有世界位置**（机器人没有全局定位）。

| 观测项 | 为什么去掉 | 代价 |
|---|---|---|
| 躯干线速度 | IMU 不提供 | 控制变量实测：同策略同仿真，仅把它置零，存活从 500/500 掉到 190/500 |
| `anchor_pos_b` | 需要躯干世界位置 | 重训一次 |

两项都挪进 critic —— **非对称 actor-critic**，价值网络训练时可以用特权信息。
BeyondMimic 官方也提供了同思路的 `Wo-State-Estimation` 配置。

**最终策略观测 154 维**：

| 分量 | 维度 | 来源 |
|---|---|---|
| 参考关节角 + 关节速度 | 58 | 动作文件 |
| `anchor_ori_b`（姿态误差，6D 表示） | 6 | IMU 四元数 |
| 陀螺仪 | 3 | IMU |
| 关节角（相对默认姿态） | 29 | `motor_state.q` |
| 关节速度 | 29 | `motor_state.dq` |
| 上一步动作 | 29 | 内部 |

**动作**：`motor_targets = ref_joint_pos[t] + action × 0.5`
—— 相对**参考姿态**而非默认姿态，可达性由构造保证（见 2.4 节）。

### 坐标系传递

策略在 **torso_link** 系训练，G1 的 IMU 在 **pelvis**，中间隔三个腰关节。
用已测到的关节角做一次正运动学传递即可，**不需要额外传感器**：

```python
qpos[3:7] = pelvis_quat;  qpos[7:] = measured_q
qvel[3:6] = pelvis_gyro;  qvel[6:] = measured_dq
mj_forward()  →  xquat[torso_link],  mj_objectVelocity(torso, local)
```

实测：姿态误差 **0.0000 度**，角速度误差 0.031 rad/s。

## 五、与 BeyondMimic 的差异汇总

### 5.1 有意偏离（都是平台/框架限制，不是随意改的）

| 项 | BeyondMimic | 本项目 | 原因 |
|---|---|---|---|
| 仿真后端 | Isaac Sim / MuJoCo-Warp | **MuJoCo MJX** | 前两者 CUDA 独占 |
| RL 框架 | rsl_rl | **brax PPO** | MJX 生态 |
| 学习率 | 1e-3 + 自适应 KL | **3e-4 固定** | brax 没有自适应 KL 调度；少了调度就不该照抄它的上限值 |
| minibatch | 4 × 5 epochs | **16 × 2** | gfx1100 的 XLA 编译图上限，乘积必须 ≤ 32 |
| `entropy_cost` | 0.005 | **0.001** | brax 的熵项不归一化，5e-3 会让熵奖励压过任务奖励（实测 0.205 vs 0.044/步） |
| 动作参考系 | `default_pose + a` | **`ref[t] + a`** | brax 的 tanh 截断动作，必须保证可达性 |
| `sim_dt` | 0.005 | **0.002** | Playground 的 G1 刚度高得多，0.005 会积分发散 |
| 软限位系数 | 1.0 | **1.0** | 一致（曾误用 0.9，导致参考本身被罚 −2.09/步） |
| 训练步数 | 30000 iter ≈ 2.95B | **371M** | 单卡 6 小时预算 |
| 自适应采样 | 按失败率加权 | **未实现** | 先验证主干 |

### 5.2 我们额外做的

| 项 | 说明 |
|---|---|
| **可部署观测设计** | 训练前就去掉 SDK 拿不到的两项，训完直接能过层 3 |
| **躯干坐标系传递** | 解决 IMU 在骨盆、策略在躯干的错配 |
| **三层递进验证** | 每层只换一样，出问题能定位 |
| **纯 NumPy 推理** | 251,066 参数，零 JAX 依赖，同一份权重跑遍三层和真机 |

## 六、移植过程中的 8 个 bug

按发现顺序。**前 7 个都是真 bug，但只要第 8 个还在，修任何一个都看不到改善。**

| # | bug | 后果 | 单独修有效？ |
|---|---|---|---|
| 1 | `mjx_env` 的 API 是 `make_data` 不是 `init` | 报错 | 必修 |
| 2 | `data.cvel` 的线速度在 **subtree_com** 那点，不是 body 原点 | 手腕速度差 1.0 m/s | 否 |
| 3 | 自由关节 `qvel[3:6]` 是**机体系**角速度 | 速度奖励恒为 0（指数下溢） | 否 |
| 4 | `sim_dt=0.005` 积分发散 | `base_z` 飞到 −165911 | 否 |
| 5 | `action_scale` 太小，动作够不到 | 手臂物理上抬不起来 | 否 |
| 6 | 软限位 0.9 与参考冲突 | 参考本身 269/298 帧被罚 −2.09/步 | 否 |
| 7 | 奖励量级 / 熵配比 | 熵奖励是任务奖励的 3.4 倍 | 否 |
| 8 | **auto-reset 不还原 `info`** | **训练数据全废** | **是** |

### 第 8 个的定位过程

三轮训练全部单调劣化（未训练的网络最好）。**消融实验给出了决定性线索**：

| 组 | 配置 | `ep_len` 走势 |
|---|---|---|
| 基线 | 有惩罚 + entropy 1e-3 | 36 → 19.4 |
| A | 关掉两个惩罚 | 36 → 22.4 |
| B | 关惩罚 + 零熵 | 36 → 20.9 |
| C | 有惩罚 + 零熵 | 36 → 22.5 |

**三组差异很大的配置给出几乎重合的曲线** —— 劣化与奖励构成无关，
问题在所有组**共享**的东西上。

Playground 的 `BraxAutoResetWrapper` 文档字符串写着：

> only data and obs are reset, **not the environment info**.

参考帧索引存在 `info["motion_idx"]` 里，于是第一个 episode 结束后
物理状态回到起点、参考索引继续往前 —— 永久错位。加上终止条件里的
`motion_idx >= T−1`，之后全是 1 步的垃圾样本。

改一个布尔值 `full_reset=True`，训练立刻从「越训越差」变成稳定收敛。

> 这个 bug 也解释了第一版的「手臂乱挥」：旧环境的索引是**取模循环**的，
> 错位不会让 episode 崩掉，但会让策略在**错误的相位**上被要求跟踪。
> 它从第一天就在，只是在旧环境里表现得不那么致命。

## 七、验收方式的演化

**旧标准（都是坏指标）：**

| 指标 | 为什么坏 |
|---|---|
| 「500/500 步不摔」 | 站着不动也满分 |
| 「上肢关节角误差 19°」 | 和视觉相似度相关性弱 |

**新标准：**

1. **完美跟踪者检验** —— 把状态精确设成参考轨迹某一帧，
   六项跟踪奖励必须全部 **= 1.0000**。任何一项偏离就说明坐标系/参考点/
   单位约定还有 bug。**这个检验应该在写完奖励函数当天就做。**
2. **完成度** —— 走完参考动作的百分比（不是「活了多少步」）
3. **body 位置误差**（米）—— 在三维空间里量，与视觉直接对应
4. **并排视频** —— 左参考、右策略，人眼判断

第 4 条才是最终标准。前三条只用来筛掉明显不行的，不用来宣布成功。

## 八、最终结果

| 层 | 引擎 | 机器人模型 | 推理 | 接口 | 完成度 | body 位置误差 |
|---|---|---|---|---|---|---|
| 零动作基线 | — | — | — | — | 44/156 (28.2%) | 0.0772 m |
| 1 | MJX (JAX/GPU) | Playground G1 | brax | 直接读内存 | **156/156** | **0.0269 m** |
| 2 | MuJoCo 原生 C | Playground G1 | **纯 NumPy** | 直接读内存 | **156/156** | **0.0273 m** |
| 3 | MuJoCo 原生 C | **宇树官方 G1** | 纯 NumPy | **DDS** | **156/156** | 关节误差 4~5° |

层 1 与层 2 误差相差 **0.0004 m** —— 换掉物理引擎和整个推理栈，
结果几乎不变，说明策略本身是干净的。

训练：371M 步 / 357.5 分钟 / 17,326 env-steps/s。
**100% 完成度在约 112M 步（2 小时）就达到了**，后续时间买的是平滑度。

## 九、方法论教训

| 教训 | 这次的体现 |
|---|---|
| **消融里多组差异很大的配置给出相同曲线 → 去查所有组共享的东西** | 关惩罚/关熵/都关三组重合，真因是包装器 |
| **两个不同的输入失败在同一个点 → 不是输入的问题** | 两个策略都恰好第 18 步摔 → 单位 bug |
| **说「A 修好了 B」之前确认对比里只变了 A** | 「域随机化关上了 sim2sim 缺口」是错的，那次 `kd` 也变了 |
| **不要用「没摔倒」当动作质量的证据** | 500/500 不摔的策略手臂根本没动 |
| **写完奖励函数当天做完美跟踪者检验** | 六项必须全 = 1.0000 |
| **第三方仿真器 ≠ 真机** | 桥接层的 50 Hz 零阶保持是实现限制 |
| **失败先怀疑自己的新代码** | 层 3 摔倒时先验了自己写的躯干 FK（0.0000 度）才往下查 |
