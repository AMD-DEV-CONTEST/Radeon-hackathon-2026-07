## 0. 准备清单（10 分钟）

- [ ] Chrome 或 Edge（≥ 89；`chrome://version` 可查）
- [ ] SO-101 机械臂 + USB 线（**数据线**，非充电线）
- [ ] 电机供电（STS3215 需独立电源；单 USB 供电不足是头号故障）
- [ ] 无其它程序占用串口（关 Local Agent、串口助手）
- [ ] 电机 ID 已唯一化（1–6；沿用 `lerobot-setup-motors` 或 MotorBridge Studio，若之前装过）
- [ ] 本地：`bash scripts/linux/botversex-restart-local.sh` 后打开 `http://127.0.0.1:5173/robots/so101?mode=browser`

## 1. 验收步骤（每步记录：通过 ✅ / 失败 ❌ + 现象）

### ① 授权与扫描
1. 点「授权串口并扫描」→ Chrome 弹出设备选择框（预期：出现 USB 串口设备）
2. 选口后 → 步骤条「扫描舵机」点亮，约 1–2 秒后提示「扫到 6 个舵机：1, 2, 3, 4, 5, 6」
   - **通过标准**：6 个全在线；3D 孪生立起并显示当前姿态
   - 失败映射：见第 2 节

### ② 第一次挥手
3. 点「挥手」→ 臂约 3 秒完成 2 轮挥手 → 回到基准 → 🎉 横幅出现
   - **通过标准**：真机动作与 3D 孪生同步；动作幅度温和（≈±11°）；结束时无异常抖动
   - 若真机不动但 3D 动：扭矩没开或供电不足（看第 2 节）

### ③ 手动关节（高级层）
4. 展开「高级：手动关节与扭矩」→ 开扭矩 → 拖 shoulder_lift 滑条 → 关节缓慢跟随
   - **通过标准**：滑条值 ↔ 真机位置一致（±2%）；松手后保持

### ④ 3 秒首录
5. 点「把这段存成我的第一条数据」→ 3 秒后提示「第一条数据已入库（N 帧）」
6. `curl http://127.0.0.1:8002/api/datasets | python3 -m json.tool | grep -A2 webserial`（或页面实验室看）
   - **通过标准**：列表出现 `recording_ws_*`，`frame_count` ≈ 60（20Hz × 3s），`source: webserial_record`

### ⑤ 故障演练（主动制造一次故障，验证诊断）
7. 拔掉电机电源（保留 USB）→ 重新授权 → 扫描 → 预期出现「没扫到舵机」卡片 + 4 条排查指引
8. 点「一键诊断」→ 20 秒后日志显示「波特率 1000000: 无舵机响应」
9. 点「导出日志」→ 下载 `botversex-serial-diag-*.txt`
   - **通过标准**：诊断日志完整、可读、可发送

### ⑥ 断线复位
10. 拔 USB → 预期「已断开」提示、3D 孪生复位、按钮回到「授权串口并扫描」

## 2. 失败映射（现象 → 动作）

| 现象 | 最可能原因 | 动作 |
|------|-----------|------|
| 设备选择框里什么都没有 | 线/口问题 | 换 USB 口、换数据线；`SerialDiagnostics` 看端口枚举 |
| 授权成功但扫到 0 个 | **供电不足**（头号） | 接独立电源；再不行看 ID 是否唯一化（issue #526 教训） |
| 扫到部分（<6） | 个别电机供电/线序/ID 冲突 | 记下缺失 ID；检查总线接线；诊断日志逐 ID 看 |
| 挥手时真机不动、3D 动 | 扭矩未生效 / 供电崩溃 | 查电源电流；手动层单独开扭矩验证 |
| 关节反向或角度不对 | 标定（零点/方向）未做 | 用 MotorBridge Studio 或 lerobot-calibrate 标定；孪生是视觉跟动，方向以真机为准 |
| 录制帧数远小于 60 | 串口速率跟不上（读超时） | 检查 USB 口/线质量；`fps` 实报为实际值，不造假 |
| 页面无「一键诊断」 | 部署旧版本 | 确认前端构建包含 M39（`SerialDiagnostics.tsx` 在包内） |
