# Crypto Trading Strategy DSL Specification

**Version 1.0** — AMD AI DevMaster Hackathon 2026, Track 2

## 1. Overview

The Strategy DSL is a YAML-based intermediate representation that bridges
natural language trading ideas (generated by LLM) and executable trading
code (Freqtrade IStrategy). It is designed to be:

- **LLM-friendly** — YAML structure is reliably generated by 7B-class LLMs
- **Validatable** — JSON Schema enforces structural correctness before execution
- **Transpilable** — Automatically converts to Freqtrade IStrategy Python classes
- **Human-readable** — Traders can review and modify the DSL before execution

## 2. DSL Structure

```yaml
strategy:
  name: <string>              # Python identifier (^[A-Za-z][A-Za-z0-9_]*$)
  market:
    exchange: <enum>           # binance | okx | bybit | kraken | gate
    pair: <string>             # e.g. BTC/USDT (^[A-Z]+/[A-Z]+$)
    timeframe: <enum>          # 1m | 5m | 15m | 30m | 1h | 4h | 1d | 1w
  indicators:                  # Array, min 1 item
    - name: <string>           # snake_case variable name
      type: <enum>             # See §3
      params: <object>         # See §3
  entry:
    long: <expr|null>          # Boolean expression for long entry
    short: <expr|null>         # Boolean expression for short entry
  exit:
    long: <expr|null>          # Boolean expression for long exit
    short: <expr|null>         # Boolean expression for short exit
  risk:
    stop_loss: <number>        # Negative ratio, e.g. -0.03 = 3% loss
    take_profit: <number?>     # Positive ratio, e.g. 0.06 = 6% gain
    trailing_stop: <bool>     # Enable trailing stop (default: false)
    trailing_stop_positive: <number?>   # Trailing offset when in profit
    trailing_stop_positive_offset: <number?>
    max_open_trades: <int>    # Max concurrent positions (1-20)
    stake_amount: <number|str> # Position size (e.g. 0.1) or "unlimited"
    time_in_trade?:           # Max holding time
      max_minutes: <int?>
      max_hours: <int?>
      max_days: <int?>
```

| ATR | period | — | `{name}` |
| BollingerBands | period, std_dev | — | `{name}_upper`, `{name}_middle`, `{name}_lower` |
| Stochastic | period | — | `{name}_k`, `{name}_d` |

| VWAP | — | — | `{name}` |

**`field`** can be: `open`, `high`, `low`, `close`, `volume` (default: `close`)

## 4. Expression Grammar

Entry/exit conditions use a restricted boolean expression language:

### 4.1 Operators (by precedence, lowest to highest)

| Priority | Operator | Description |
|----------|----------|-------------|
| 1 | `OR` | Logical OR |
| 2 | `AND` | Logical AND |
| 3 | `NOT` | Logical NOT (unary) |
| 4 | `>`, `<`, `>=`, `<=`, `==`, `!=` | Comparison |
| 5 | `+`, `-` | Arithmetic add/subtract |
| 6 | `*`, `/` | Arithmetic multiply/divide |

### 4.2 Operands

- **Indicator references**: any `name` defined in the `indicators` array
- **Built-in columns**: `open`, `high`, `low`, `close`, `volume`
- **Numeric literals**: `20`, `0.03`, `1.5e-3`
- **Parentheses**: `(` and `)` for grouping

### 4.3 Examples

```
# Simple crossover
ema_fast > ema_slow

# Volume-confirmed entry
ema_fast > ema_slow AND volume > vol_ma * 1.5 AND rsi < 70

# Bollinger Bands mean reversion
close < bb_lower

# Multi-indicator confluence
ema_fast > ema_slow AND rsi < 35 AND volume > vol_ma * 1.5

# Short entry
ema_fast < ema_slow AND rsi > 70

# Negation
NOT (rsi > 70 OR close < ema_slow)
```

### 4.4 Parser Implementation

The expression parser (`src/dsl/expr_parser.py`) uses Python's `ast` module:

1. **Translation**: DSL operators (`AND`/`OR`/`NOT`) → Python keywords (`and`/`or`/`not`)
2. **AST Parsing**: `ast.parse(expr, mode="eval")`
3. **Node Whitelist**: Only `BoolOp`, `BinOp`, `Compare`, `Name`, `Constant`,
   `UnaryOp`, and arithmetic/comparison operator nodes are allowed
4. **AST Transformation**: `and`/`or`/`not` → `&`/`|`/`~` for pandas Series
   element-wise evaluation via `_ElementWiseTransformer`
5. **Safe Evaluation**: `eval()` with `{"__builtins__": {}}` — no builtins,
   only DataFrame columns and `numpy` in namespace

**Security**: Attribute access (`__class__`, `__import__`) and function calls
are blocked at the AST node level.

## 5. Validation Rules

### 5.1 Schema Validation (JSON Schema)

- All required fields present (`name`, `market`, `indicators`, `entry`, `exit`, `risk`)
- Enum values within allowed sets (exchange, timeframe, indicator type)
- Numeric ranges enforced (stop_loss: -0.5 to 0, period: 1-500)
- `additionalProperties: false` on all objects (no extra fields)

### 5.2 Semantic Validation

| Rule | Description |
|------|-------------|
| Indicator references | All identifiers in entry/exit expressions must be defined in `indicators` or be built-in columns |
| Expression syntax | AST parsing must succeed — malformed expressions are rejected |
| MACD params | `MACD` type requires `fast_period` and `slow_period` |
| Stop loss sign | `stop_loss` must be negative |
| Trailing stop consistency | If `trailing_stop` is true, `trailing_stop_positive` must be > 0 |

## 6. Transpilation

The transpiler (`src/dsl/transpiler.py`) converts a validated DSL dict into a
Freqtrade `IStrategy` Python class:

| DSL Section | → Freqtrade Method |
|-------------|-------------------|
| `indicators` | `populate_indicators()` |
| `entry` | `populate_entry_trend()` |
| `exit` | `populate_exit_trend()` |
| `risk` | Class attributes (`stoploss`, `max_open_trades`, etc.) |
| `market.timeframe` | `timeframe` class attribute |
| `entry.short` (non-null) | `can_short = True` |

All 16 indicator types generate valid Python code using `talipp` indicators.

## 7. Backtest Execution

The backtest runner (`src/backtest/runner.py`) executes strategies directly
(without Freqtrade) for faster iteration:

- **Multi-position**: Supports up to `max_open_trades` concurrent positions
- **Long & Short**: Both directions supported with proper PnL calculation
- **Slippage model**: Configurable slippage applied to entry/exit prices
- **Risk management**: Stop-loss, take-profit, time-in-trade limits enforced
- **Benchmark**: Buy-and-hold equity curve computed for alpha comparison
- **Metrics**: Sharpe, Sortino, Calmar, max drawdown, max consecutive losses,
  volatility (annualized), alpha, profit factor, win rate, avg trade duration

## 8. Complete Example

```yaml
strategy:
  name: Confluence_EMA_RSI_Vol
  market:
    exchange: binance
    pair: BTC/USDT
    timeframe: 1h
  indicators:
    - {name: ema_fast, type: EMA, params: {period: 20, field: close}}
    - {name: ema_slow, type: EMA, params: {period: 50, field: close}}
    - {name: rsi, type: RSI, params: {period: 14}}
    - {name: vol_ma, type: SMA, params: {period: 20, field: volume}}
    - {name: atr, type: ATR, params: {period: 14}}
  entry:
    long: "ema_fast > ema_slow AND rsi < 35 AND volume > vol_ma * 1.5"
    short: "ema_fast < ema_slow AND rsi > 65 AND volume > vol_ma * 1.5"
  exit:
    long: "ema_fast < ema_slow OR rsi > 70"
    short: "ema_fast > ema_slow OR rsi < 30"
  risk:
    stop_loss: -0.03
    take_profit: 0.06
    trailing_stop: true
    trailing_stop_positive: 0.02
    trailing_stop_positive_offset: 0.04
    max_open_trades: 3
    stake_amount: 0.1
    time_in_trade:
      max_hours: 48
```
