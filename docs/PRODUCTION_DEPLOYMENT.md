# Production Deployment Guide

This guide deploys the competition build with a static GitHub Pages frontend and all core AI
services on one user-controlled AMD Radeon/ROCm machine.

This is a single-GPU competition deployment, not a high-availability multi-tenant SaaS design. It
prioritizes a reproducible judging environment, a small public attack surface, and quick recovery.

## 1. Target Topology

```text
GitHub Pages
https://ld0574.github.io/Radeon-hackathon-2026-07/
    |
    | HTTPS + short-lived Bearer token
    v
Radeon Cloud rc-tunnel (the only public backend endpoint)
    |
    v
XiangLens FastAPI          127.0.0.1:8080
    |-- LangGraph
    |-- Milvus Lite        runtime/xianglens_milvus.db
    |-- SQLite             runtime/xianglens.sqlite3
    |-- Private Lens Tool  /opt/xianglens-private/avatarKnowledge.ts
    `-- llama-server       127.0.0.1:8000/v1
            `-- AMD Radeon PRO W7900 through ROCm
```

The deployment has three strict boundaries:

1. Expose **FastAPI port 8080 only**.
2. Keep `llama-server`, Milvus Lite, SQLite, uploads, private Lens material, and secrets private to
   the Radeon machine.
3. Put only the public FastAPI base URL in GitHub Actions variable `XIANGLENS_API_BASE`.

Never point GitHub Pages directly at `llama-server` and never put `XIANG_APP_API_KEY` in GitHub
Pages, repository variables, frontend environment variables, screenshots, or video captions.

## 2. Deployment Modes

### Recommended competition deployment

- Nuxt is statically generated by GitHub Actions and hosted on GitHub Pages.
- FastAPI and `llama-server` run inside the same Radeon Cloud Notebook.
- FastAPI calls `http://127.0.0.1:8000/v1`.
- `rc-tunnel` publishes FastAPI port 8080 over HTTPS.

This is the documented `submission-local` topology and keeps core inference on the submitted Radeon
environment.

### Optional Cloudflare Worker edge

A Worker may sit between GitHub Pages and the Radeon tunnel to add rate limits and a stable public
hostname. In the current implementation, FastAPI still owns `POST /api/v1/session` and signs the
short-lived token. The Worker should proxy requests, preserve streaming and uploads, and never
embed the permanent application key.

The Worker is optional for a controlled hackathon demonstration. It is not required for the first
production deployment.

## 3. Prerequisites

- A Radeon Cloud Notebook with the W7900 visible to ROCm.
- The competition repository checked out on branch `submission/track2-dale`.
- A HIP-enabled `llama.cpp` build.
- Python 3.11, 3.12, or 3.13 and `uv`.
- The Radeon Cloud `rc-tunnel` utility.
- GitHub administrator access for repository Actions variables and Pages workflows.

Model installation and compilation are covered by [REPRODUCE.md](REPRODUCE.md). For production,
use the private host and port shown in this guide even if a development command in that document
uses a public model port.

## 4. Prepare the Repository on Radeon Cloud

From the Notebook terminal:

```bash
cd /workspace
git clone --branch submission/track2-dale --single-branch \
  https://github.com/ld0574/Radeon-hackathon-2026-07.git
cd Radeon-hackathon-2026-07
git status --short
```

The status output should be empty before deployment.

Install the locked Python environment, including semantic retrieval and the validation tools:

```bash
uv sync --frozen --extra semantic --extra dev
```

After final validation, a lean runtime can omit the development extra:

```bash
uv sync --frozen --extra semantic
```

The Radeon host does not need Node.js or pnpm because GitHub Actions builds the static frontend.

## 5. Configure Production Secrets

Create the environment file from the tracked example:

```bash
cp .env.example .env
chmod 600 .env
openssl rand -hex 32
```

Paste the generated 64-character value into `XIANG_APP_API_KEY`. A production `.env` should contain
these values:

```env
# Application
XIANG_APP_ENV=production
XIANG_DEPLOYMENT_MODE=submission-local
XIANG_HOST=127.0.0.1
XIANG_PORT=8080
XIANG_LOG_LEVEL=INFO

# Browser authentication. The permanent key never leaves this machine.
XIANG_AUTH_ENABLED=true
XIANG_APP_API_KEY=PASTE_64_RANDOM_HEX_CHARACTERS_HERE
XIANG_PUBLIC_SESSIONS_ENABLED=true
XIANG_ACCESS_TOKEN_TTL_MINUTES=20
XIANG_SESSION_ISSUE_LIMIT_PER_MINUTE=10

# Private llama.cpp connection on the same Radeon host.
XIANG_LLM_BASE_URL=http://127.0.0.1:8000/v1
XIANG_LLM_API_KEY=
XIANG_LLM_MODEL=mradermacher/Qwen3.6-35B-A3B-Fable-5-Distill-i1-GGUF:Q6_K
XIANG_LLM_TIMEOUT_SECONDS=180
XIANG_LLM_PROBE_ON_START=false
XIANG_LLM_ENABLE_THINKING=true
XIANG_LLM_REASONING_BUDGET=2048

# Local state
XIANG_SQLITE_PATH=./runtime/xianglens.sqlite3
XIANG_MILVUS_URI=./runtime/xianglens_milvus.db
XIANG_UPLOAD_DIR=./runtime/uploads
XIANG_EXPORT_DIR=./runtime/exports
XIANG_IMAGE_RETENTION=session
XIANG_SESSION_TTL_MINUTES=60

# Semantic retrieval
XIANG_EMBEDDING_PROVIDER=fastembed
XIANG_EMBEDDING_MODEL=BAAI/bge-small-en-v1.5
XIANG_EMBEDDING_DIMENSION=384
XIANG_RAG_TOP_K=4

# Optional proprietary extension. This file is provisioned separately and never committed.
XIANG_PRIVATE_LENS_ENABLED=true
XIANG_PRIVATE_LENS_PATH=/opt/xianglens-private/avatarKnowledge.ts
XIANG_PRIVATE_LENS_NAME=Private 108-Technique Lens

# The origin has no repository path component.
XIANG_ALLOWED_ORIGINS=https://ld0574.github.io
```

Security notes:

- `.env` is ignored by Git and must remain mode `600`.
- Provision the private Lens file outside the checkout with mode `600`; never place it under
  `data/`, `docs/`, `submission/`, or the static frontend.
- `XIANG_ALLOWED_ORIGINS` contains origins only, such as `https://ld0574.github.io`, not the full
  Pages path.
- Keep `XIANG_LLM_PROBE_ON_START=false`; perform an explicit readiness probe after both processes
  are running.
- The public session endpoint is designed for the hackathon UI. Keep the public tunnel active only
  while the demonstration or judging access is required.

## 6. Build the Production Knowledge Database

FastEmbed downloads its model on the first build:

```bash
XIANG_EMBEDDING_PROVIDER=fastembed \
  uv run python scripts/build_knowledge_db.py --provider fastembed
```

Run the retrieval smoke suite using the same production configuration:

```bash
uv run python scripts/run_rag_smoke.py
```

Expected results:

```text
Built 32 cards in .../runtime/xianglens_milvus.db
All 8 RAG smoke queries passed.
```

If the FastEmbed download is blocked during a time-limited demonstration, use the deterministic
fallback and change `.env` accordingly:

```bash
uv run python scripts/build_knowledge_db.py --provider hash
```

```env
XIANG_EMBEDDING_PROVIDER=hash
```

Do not build the database with one provider and start FastAPI with another provider.

### Provision the optional private Lens Tool

Transfer the existing distilled TypeScript file through the private notebook upload channel, then
install it outside the Git checkout:

```bash
sudo install -d -m 700 /opt/xianglens-private
sudo install -m 600 /secure-upload/avatarKnowledge.ts \
  /opt/xianglens-private/avatarKnowledge.ts
```

Restart FastAPI after changing the file. Verify only availability metadata—not the source text:

```bash
curl -fsS -H "X-App-API-Key: $XIANG_APP_API_KEY" \
  'http://127.0.0.1:8080/api/v1/system/status' \
  | jq '{private_lens_available, private_lens_name}'
```

Expected: `private_lens_available` is `true`. The tool remains inactive until the browser includes
`enable_private_lens: true` for a specific run.

## 7. Start the Private llama-server

Use the HIP build and keep it on loopback port 8000:

```bash
cd /workspace/llama.cpp
mkdir -p /workspace/xianglens-logs

nohup ./build/bin/llama-server \
  -hf mradermacher/Qwen3.6-35B-A3B-Fable-5-Distill-i1-GGUF:Q6_K \
  --mmproj-url "https://hf-mirror.com/mradermacher/Qwen3.6-35B-A3B-Fable-5-Distill-GGUF/resolve/main/Qwen3.6-35B-A3B-Fable-5-Distill.mmproj-f16.gguf" \
  -ngl 999 \
  -c 32768 \
  --flash-attn on \
  --cache-type-k q8_0 \
  --cache-type-v q8_0 \
  --host 127.0.0.1 \
  --port 8000 \
  > /workspace/xianglens-logs/llama-server.log 2>&1 &

echo $! > /workspace/xianglens-logs/llama-server.pid
```

Check readiness and confirm the model ID:

```bash
curl --fail http://127.0.0.1:8000/health
curl --fail http://127.0.0.1:8000/v1/models
tail -n 100 /workspace/xianglens-logs/llama-server.log
```

If `/v1/models` returns a different model ID, copy that exact ID into `XIANG_LLM_MODEL` and restart
FastAPI later. Do not expose port 8000 through `rc-tunnel`.

## 8. Start XiangLens FastAPI

Return to the project directory:

```bash
cd /workspace/Radeon-hackathon-2026-07
mkdir -p /workspace/xianglens-logs

nohup ./scripts/start_api.sh \
  > /workspace/xianglens-logs/xianglens-api.log 2>&1 &

echo $! > /workspace/xianglens-logs/xianglens-api.pid
```

The Radeon Cloud tunnel supports services listening on `127.0.0.1`, so keep `XIANG_HOST` at that
value. Do not change it to `0.0.0.0` for this platform.

Check local readiness:

```bash
curl --fail http://127.0.0.1:8080/health

TOKEN="$(curl --fail --silent --show-error \
  -X POST http://127.0.0.1:8080/api/v1/session \
  | uv run python -c 'import json, sys; print(json.load(sys.stdin)["access_token"])')"

curl --fail \
  -H "Authorization: Bearer $TOKEN" \
  'http://127.0.0.1:8080/api/v1/system/status?probe_model=true'

tail -n 100 /workspace/xianglens-logs/xianglens-api.log
```

Do not continue until the status response reports:

```text
model_configured: true
model_reachable: true
milvus_ready: true
submission_topology_compliant: true
```

The response is JSON, so the exact formatting will differ from the checklist above.

## 9. Publish FastAPI Through Radeon rc-tunnel

Radeon Cloud permits one HTTP/WebSocket tunnel per Notebook. Use it for FastAPI:

```bash
/var/run/secrets/frp-self-service/install
export PATH="$HOME/.local/bin:$PATH"

"$HOME/.local/bin/rc-tunnel" expose --port 8080
"$HOME/.local/bin/rc-tunnel" status
"$HOME/.local/bin/rc-tunnel" logs --lines 100
```

The command returns a URL similar to:

```text
https://rc-0123456789abcdef.radeon.firstdg.ai
```

This is the XiangLens API base URL. It has no `/v1` or `/api/v1` suffix.

Validate the public boundary:

```bash
export XIANGLENS_PUBLIC_API=https://rc-0123456789abcdef.radeon.firstdg.ai

curl --fail "$XIANGLENS_PUBLIC_API/health"
curl --fail -X POST "$XIANGLENS_PUBLIC_API/api/v1/session"
```

The first command should return the XiangLens health response. The second should return a
short-lived token. The public URL must not return the `llama-server` model list at `/v1/models`.

Important tunnel behavior:

- The public domain may change when the Notebook is recreated.
- Only one port can be exposed from a Notebook at a time.
- The public tunnel can terminate long HTTP/2 SSE responses even after returning `200 OK`.
  GitHub Pages therefore starts a background run with a short `202` request and polls durable run
  state; local direct deployments retain live SSE node events.
- Stopping the tunnel invalidates the public URL immediately.
- Do not copy or edit the tunnel identity files.

## 11. End-to-End Acceptance Test

Complete this checklist before recording or judging:

- [ ] The GitHub Pages workflow is green.
- [ ] The page opens without mixed-content or CORS errors.
- [ ] The UI receives a short-lived session without asking for a permanent key.
- [ ] Model status is **Reachable**.
- [ ] Milvus status is **Milvus ready**.
- [ ] Upload one fixture from `data/fixtures/images/`.
- [ ] Run a single-image review and confirm the final trace contains all agent nodes.
- [ ] Open at least one cited evidence source.
- [ ] Approve or reject a memory proposal.
- [ ] Download a metadata-free safe copy.
- [ ] Use **Forget me** and confirm the session data disappears.
- [ ] Confirm the browser never calls `/v1/chat/completions` directly.

Keep a known fixture and the exact presentation prompt ready so the recorded run is reproducible.

## 12. Process Operations

The commands below use `nohup` because a Radeon Notebook may not run `systemd` as PID 1. They are
appropriate for the controlled competition window, but they do not provide automatic failover. If
the platform supplies a process supervisor, configure the same commands, working directories,
environment file, restart policy, and log paths in that supervisor.

### Check processes and logs

```bash
kill -0 "$(cat /workspace/xianglens-logs/llama-server.pid)"
kill -0 "$(cat /workspace/xianglens-logs/xianglens-api.pid)"

tail -f /workspace/xianglens-logs/llama-server.log
tail -f /workspace/xianglens-logs/xianglens-api.log

"$HOME/.local/bin/rc-tunnel" status
```

### Restart FastAPI

```bash
kill "$(cat /workspace/xianglens-logs/xianglens-api.pid)"
cd /workspace/Radeon-hackathon-2026-07
nohup ./scripts/start_api.sh \
  > /workspace/xianglens-logs/xianglens-api.log 2>&1 &
echo $! > /workspace/xianglens-logs/xianglens-api.pid
```

### Stop the public deployment

```bash
"$HOME/.local/bin/rc-tunnel" stop
kill "$(cat /workspace/xianglens-logs/xianglens-api.pid)"
kill "$(cat /workspace/xianglens-logs/llama-server.pid)"
```

Stop the tunnel first so new public requests cannot arrive during shutdown. Destroy the Radeon
instance after the event when it is no longer needed; a running instance continues to consume
credits.

## 13. Upgrade Procedure

Before upgrading, stop the public tunnel and FastAPI. Keep `llama-server` running unless model
files or launch flags changed.

```bash
"$HOME/.local/bin/rc-tunnel" stop
kill "$(cat /workspace/xianglens-logs/xianglens-api.pid)"

cd /workspace/Radeon-hackathon-2026-07
git status --short
git pull --ff-only origin submission/track2-dale
uv sync --frozen --extra semantic --extra dev
```

If knowledge cards, sources, the embedding model, or the embedding provider changed, rebuild the
Milvus Lite file before restarting:

```bash
XIANG_EMBEDDING_PROVIDER=fastembed \
  uv run python scripts/build_knowledge_db.py --provider fastembed
uv run python scripts/run_rag_smoke.py
```

Run checks, restart FastAPI, verify locally, and then recreate the tunnel:

```bash
uv run pytest -q

nohup ./scripts/start_api.sh \
  > /workspace/xianglens-logs/xianglens-api.log 2>&1 &
echo $! > /workspace/xianglens-logs/xianglens-api.pid

curl --fail http://127.0.0.1:8080/health
"$HOME/.local/bin/rc-tunnel" expose --port 8080
```

If the tunnel returns a new URL, update `XIANGLENS_API_BASE` and rerun the Pages workflow.

## 14. Backup and Rollback

Application state is stored under `runtime/`. Stop FastAPI before copying SQLite or Milvus Lite so
the backup is consistent:

```bash
kill "$(cat /workspace/xianglens-logs/xianglens-api.pid)"
cd /workspace/Radeon-hackathon-2026-07

backup_dir="/workspace/xianglens-backups/$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$backup_dir"
cp runtime/xianglens.sqlite3 "$backup_dir/"
cp runtime/xianglens_milvus.db "$backup_dir/"
```

Uploaded images can contain personal data. Do not include `runtime/uploads/` in routine backups
unless the user has explicitly consented and the backup has a deletion policy. The knowledge
database is reproducible from the tracked knowledge cards and normally does not require long-term
backup.

For a code rollback, deploy a previously tested commit or tag, run `uv sync --frozen`, restore a
compatible state backup if required, and repeat the local readiness checks before exposing the
tunnel. Do not restore database files while FastAPI is running.

## 15. Production Security Checklist

- [ ] Only FastAPI port 8080 is public.
- [ ] `llama-server` listens on `127.0.0.1:8000`.
- [ ] `.env` is untracked and mode `600`.
- [ ] The permanent key has at least 32 random bytes of entropy.
- [ ] GitHub contains only `XIANGLENS_API_BASE`, never backend secrets.
- [ ] CORS allows only the GitHub Pages origin and any explicitly required operator origin.
- [ ] Public session lifetime is 10–30 minutes.
- [ ] Logs do not contain Bearer tokens, prompts, images, or the permanent key.
- [ ] The public tunnel is stopped when judging access is no longer required.
- [ ] Personal-data backups are avoided or have explicit consent and deletion procedures.

The built-in session issuance limiter is an in-process safeguard. A reverse tunnel may collapse
client IP information, so treat that limiter as coarse protection. For unattended public access,
put an edge rate limiter such as Cloudflare Worker in front of the tunnel and enforce request and
analysis quotas there.

## 16. Common Production Failures

### GitHub Pages shows `Not configured`

Set repository variable `XIANGLENS_API_BASE` and manually rerun the Pages workflow. A variable
change alone does not modify the repository and may not trigger a new deployment.

### The public health endpoint works but the browser reports CORS

Set exactly:

```env
XIANG_ALLOWED_ORIGINS=https://ld0574.github.io
```

Restart FastAPI. Do not include `/Radeon-hackathon-2026-07/` in the CORS origin. CORS must also wrap
authentication failures: an expired or missing short-lived token returns `401`, but that response
still needs `Access-Control-Allow-Origin` or the browser will hide the real error behind a CORS
message.

Verify both the preflight and the expected unauthenticated `401` after deploying the latest code:

```bash
xiang_public_url=https://rc-0123456789abcdef.radeon.firstdg.ai

curl -i -X OPTIONS "$xiang_public_url/api/v1/system/status" \
  -H 'Origin: https://ld0574.github.io' \
  -H 'Access-Control-Request-Method: GET' \
  -H 'Access-Control-Request-Headers: authorization'

curl -i "$xiang_public_url/api/v1/system/status" \
  -H 'Origin: https://ld0574.github.io'
```

Both responses must include `Access-Control-Allow-Origin: https://ld0574.github.io`. The second
response should otherwise remain `401 Unauthorized`; that proves the browser can now read the real
authentication result. If the token expired, start a new private access session before continuing.

### Analysis reports `ERR_HTTP2_PROTOCOL_ERROR 200 (OK)`

This means the browser received the initial SSE `200` response, but the public Radeon tunnel reset
the HTTP/2 stream before `run.completed`. It is not a CORS or model error. The Pages workflow sets
`NUXT_PUBLIC_RUN_TRANSPORT=poll`, which uses:

1. `POST /api/v1/threads/{thread_id}/runs/async` to return `202` immediately;
2. `GET /api/v1/runs/{run_id}` every second until the durable result is complete.

Pull the latest backend commit, restart FastAPI, and rerun the Pages workflow. Do not switch Pages
back to `stream` while using the `rc-*.radeon.firstdg.ai` tunnel. Direct local deployments can keep
`NUXT_PUBLIC_RUN_TRANSPORT=stream` for live node-by-node SSE.

### The UI reports `Access-session issuance is not enabled`

Confirm all three settings and restart FastAPI:

```env
XIANG_AUTH_ENABLED=true
XIANG_PUBLIC_SESSIONS_ENABLED=true
XIANG_APP_API_KEY=a-long-random-production-value
```

### The status is reachable but analysis returns `502`

- Call `http://127.0.0.1:8000/v1/models` from the Radeon machine.
- Make `XIANG_LLM_MODEL` match the returned model ID.
- Confirm the multimodal projection loaded successfully.
- Inspect both service logs.
- Verify that FastAPI uses port 8080 and `llama-server` uses port 8000.

### Comparison fails because candidate `rationale` is missing

The comparison schema still requires all five scores and every supplied image ID. XiangLens derives
the final recommendation and fixed privacy-first decision rule in application code. If the model
omits only a candidate `rationale`, the application adds a transparent summary of the scores already
returned; it never invents or repairs missing scores. Pull the latest backend commit and restart
FastAPI if an older deployment still reports this validation error.

### `rc-tunnel` cannot expose FastAPI

- Confirm FastAPI listens on `127.0.0.1:8080`.
- Confirm no other port is already exposed from the Notebook.
- Run `rc-tunnel status` and inspect its logs.
- Recreate an old Notebook if it predates the tunnel feature.
- Do not manually edit or copy the tunnel state directory.

### A deployment restart changes the public URL

Update `XIANGLENS_API_BASE`, rerun `Deploy XiangLens web to GitHub Pages`, and perform the complete
acceptance test again.
