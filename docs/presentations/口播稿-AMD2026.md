## 第 8 页 · 架构图（约 50 秒）

（手指自上而下）

这张图是**分工**，不是概念海报：

- **云**：登录、数据集、训练任务、模型登记  
- **浏览器**：你点的 Setup、遥操作、训练、部署  
- **Local Agent**：读串口、相机，在臂上跑策略  
- **Runtime**：SO-101、Reachy……每种机一个适配器  

**实线**是控制链路——必须走本机，要低延迟，敏感数据可以不出机器。

**虚线**是训练和模型——数据集、checkpoint 可以上云，用 GPU 算。

**跟 AMD 朋友可以这么说（口语）：**  

> 「真机控制这条线，我们坚持放在你电脑上，延迟和隐私都好控；训练算力这块，我们接云、也接 ROCm——**算力在云上加速，手臂在本机听指挥**，两条线分开，各干各擅长的。」

不用背「local-first」这个词，就说：**手底下这台臂，不依赖云端才能动。**

**Skills** —（指截图 · 约 40 秒）

「先分清两个词：**Models** 是你自己训出来的那一包权重；**Skills** 是我们希望机器人时代的 **App**——能安装、能填参数、能在真机上跑，将来还能**更新、分发、交易**。

今天这页，已经是 **技能注册表 + 安装运行** 的雏形：按 Runtime 筛机型、装一个技能、填参数、一键跑——证明 **『能力可以被打包』** 这件事走得通。

我们未来重点要做的，是纲领里 **阶段三：技能库和分发**——  
公开技能库、搜索分类、版本、硬件兼容性、授权和付费。  
**不是现在就说自己是 App Store**，而是：**标准格式和运行协议已经有了，货架和市场在下一棒。**

你可以这样理解：**今晚你用一条龙做出第一个能力；明天把它封成 Skill；后天别人在兼容的臂上装，不用重写十遍脚本。**  
这就是我们要做的 **分发层**。」

---

**Workflow** —（指画布 · 约 45 秒）

「如果 Skills 是 **上架的商品**，Workflow 就是 **工厂里的产线**。

纲领里写得很清楚：路线是 **先做工具 → 再做运行时 → 再做技能库 → 市场才会自然长出来**。Workflow 就是把以前散落在命令行、ROS、训练脚本里的步骤，**拉成一张可视化 pipeline**。

**终局长什么样？** 连机器人 → 读相机 → 遥操作录制 → 转数据集 → 选基座模型 → 训练微调 → 评估 → 部署到 Local Agent → **发布成 Skill**。  
一条龙里的每一步，将来都应该能在画布上 **拖、连、存、复用**。

**今天诚实说：** 中间 **Finetune 这一条链是真跑通的**——HF 数据集、相机映射、提交 Qualia 训练、盯任务状态。  
边上有些 record、deploy 节点，看着像一条龙，**还在接真 API**，是演示壳，不是骗人，是 **产线正在一节一节通电**。

**未来重点：** 把 demo 节点换成真执行，让 Workflow 成为 **『做技能』的默认方式**——不是多一个花哨编辑器，而是 **机器人时代的 Xcode / CI 流水线**。」

---

**AI Hub** —（指截图 · 约 35 秒）

「Hub 这一页，容易被人当成『又一个模型列表』。我们想把它放在更大的图里：

**对外发现层** — 今天，帮你在站内逛 HuggingFace 上的机器人相关模型，少跳十个标签页；数据集也能 **从平台发布回 HF**，让数据和模型都接得上开源社区。

**对内，它是通向分发的桥。** 纲领里分得很清：  
- **Models** = 你本地训完、要部署的那一份；  
- **Hub** = 发现别人的模型和数据，站在巨人的肩膀上；  
- **未来的 Marketplace** = BotverseX **自己的技能货架**（公开库、安装、更新、交易）——**那是下一阶段，不和 Hub 混着说**。

**未来重点：** Hub 继续强化 **发现、对比、一键进 Workflow**；Marketplace 起来之后，**模型发现 + 技能交易** 在同一个开发者入口里闭环。  
想象成：**Hub 像早期的应用推荐与搜索，Marketplace 才是应用商店本身**——我们先把发现做好，不把空货架吹成生态。」

## 第 29 页 · 谁赢了 2007（约 40 秒）
