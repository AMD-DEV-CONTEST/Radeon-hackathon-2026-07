```bash
USE_MODELSCOPE=1 bash scripts/download_models.sh
```

List of models to download:

|------|----------|------|------|
| Qwen3-8B | ~16GB | Main Chat LLM (FP16) | 8000 |
| Qwen3-8B-GPTQ-Int4 | ~5GB | INT4 quantization experiment (generated by local quantization) | 8000 |
| DeepSeek-R1-Distill-Qwen-7B | ~15GB | Reasoning enhancement | 8002 |

### R2: Inference Service Startup (Required before the competition)

The 3 services need to be started in order:

```bash
# Terminal 1: Chat LLM (Qwen3-8B)
export ROCBLAS_USE_HIPBLASLT=1
export HIP_VISIBLE_DEVICES=0
export HSA_OVERRIDE_GFX_VERSION=11.0.0  # gfx1100 (RDNA 3) compatibility
python -m vllm.entrypoints.openai.api_server \
    --model ./models/Qwen3-8B \
    --dtype bfloat16 \
    --max-model-len 8192 \
    --chat-template ./models/qwen3_nonthinking.jinja \
    --gpu-memory-utilization 0.85 \
    --port 8000

# Terminal 2: Embedding (BGE-M3)
python -m text_embeddings_router --model ./models/bge-m3 --port 8001
# Or a self-hosted Flask service (see DEPLOYMENT.md section 2.2)

# Terminal 3: Reasoning enhancement (DeepSeek-R1-Distill-Qwen-7B, optional)
python -m vllm.entrypoints.openai.api_server \
    --model ./models/DeepSeek-R1-Distill-Qwen-7B \
    --dtype bfloat16 \
    --max-model-len 4096 \
    --max-num-seqs 4 \
    --gpu-memory-utilization 0.85 \
    --port 8002
```

**VRAM allocation strategy** (48GB VRAM):

| Service | VRAM usage | Allocation |
|------|----------|------|
| Qwen3-8B FP16 | ~16GB | gpu-memory-utilization=0.85 (~40GB) |
| BGE-M3 | ~2GB | Shared or standalone process |
| DeepSeek-R1 FP16 | ~15GB | Shared with the main model by time-slicing or loaded simultaneously |

> 48GB VRAM is sufficient to load Qwen3-8B + BGE-M3 + DeepSeek-R1 simultaneously (about ~33GB total), leaving ~15GB for the KV-Cache.

## Section 5: Risks and Considerations

### 5.1 Network Risks

| Risk | Impact | Mitigation |
|------|------|------|
| HuggingFace download is slow/times out | Model acquisition fails | Use ModelScope: `USE_MODELSCOPE=1 bash scripts/download_models.sh` |
| PyTorch ROCm wheel download fails | Environment setup is blocked | Pre-download locally, then `pip install ./torch-*.whl` |

### 5.2 VRAM Risks

| Risk | Impact | Mitigation |
|------|------|------|
| Not enough VRAM when loading 3 models simultaneously | OOM | First load only Qwen3-8B + BGE-M3; start DeepSeek-R1 on demand |
| vLLM gpu-memory-utilization too high | Insufficient KV-Cache | Lower from 0.85 to 0.80, or reduce max-num-seqs |

### 5.3 Embedding Service Compatibility

Currently `models.toml` configures the Embedding to be reached via `http://localhost:8001/v1`. The following needs to be confirmed:

- Whether `text-embeddings-router` supports the `/v1/embeddings` OpenAI-compatible format
- If it is not available, use the self-hosted Flask service in DEPLOYMENT.md section 2.2 (already included in the documentation)
- The vector dimension returned by BGE-M3 must be 1024 (consistent with the FAISS index)

### 5.4 Impact of the M7 Fix

`_require_env` raises when environment variables are missing. Ensure the following variables are set in the `.env` file:

```bash
LOCAL_LLM_API_KEY=Empty-key-for-local-vllm      # any non-empty value works
LOCAL_REASONING_API_KEY=Empty-key-for-local-vllm # any non-empty value works
LOCAL_EMBED_API_KEY=Empty-key-for-local-embed     # any non-empty value works
```

> The local vLLM does not validate the API Key, but `_require_env` requires a non-empty value. `.env.example` already provides default values.
