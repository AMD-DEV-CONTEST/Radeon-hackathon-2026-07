## 0. 一句话

**M28 是止血，不是造血。**  
做完之后平台从「会骗人」变成「不骗人」，但没有任何一条改动回答「谁会为什么付钱」。

下一步**不是继续写代码**，而是用外部信号验证一个假设：  
**「装环境」是不是真实用户最长的卡点。**  
验证通过再做 WebSerial；验证失败则重新定义卖给谁，而不是再加功能。

## 2. 产品定义的死结

### 2.1 四个产品挤在一个域名下

BotverseX 现在同时是：

1. LeRobot 的 GUI 外壳  
2. 云训练平台  
3. 机器人 3D 展厅  
4. Workflow 编排器  

用户画像、付费理由、成熟度不同，且**互相没有复利**——看 3D 的人不因此跑 Workflow；跑 Workflow 的人不需要展厅。23 页 / 39 节点 / 6 机型是「技术在找问题」的形态。

### 2.2 目标用户在数学上接近空集

`apps/realtime/requirements.txt` 把 **lerobot 列为必装依赖**。

- 能装上 lerobot 的人 → 直接敲 `lerobot-record` / `lerobot-teleoperate` 就够了，不需要 GUI  
- 装不上 lerobot 的人 → 同样装不上 **2.93 GB** 的 Local Agent  

这不是 UI 问题，是**产品定义问题**。团队感觉不到墙，是因为环境两年前就配好了；数据库不会骗人。

### 2.3 「我们已经能遥操 / 摄像头 / 闭环」——正确，但不完整

能力真实存在，路径是 Local Agent → `lerobot-teleoperate`。用户点「开始遥操」之前必须：装 Python → 装 2.9 GB 全家桶 → 启 Agent → 信任自签 HTTPS。  

**「我们能做」≠「别人能用上」。**  
WebSerial 不是再加一个功能，是把同一能力从「翻 13 级台阶」搬到「推门就进」。

## 3. 「卖给谁」——修正 M28 的买家判断

M28 收窄为：

> 机器人教学实验室的多人数据采集与训练控制台；一个人装好，一屋子人用浏览器进来。

**收窄方向对（摊薄安装成本），买家判断错：**

| 教学实验室实际买什么 | BotverseX 现在给什么 |
|----------------------|----------------------|
| 能开课的完整方案（硬件 + 课件 + 保证能跑的 demo + 有人接电话） | SaaS 控制台 |
| 招标采购，预算在硬件与课程 | 订阅 / 云训 |
| 痛点：「三十个学生装不上 Python」 | 自己也要求装 2.9 GB 环境 |

在「装环境」墙没拆掉之前，**教学实验室不是可成交买家**。

更诚实的近端买家候选（待访谈验证）：

- 个人开发者 / 创客：刚买到 SO-101，卡在安装  
- 小团队 lab：有一条臂，想少写脚本  
- **不是**「已经能熟练用 CLI 的人」——他们不付 GUI 的钱

## 4. 解决什么问题（重新写清楚）

### 对外可说（Pitch，仍可用）

降低「采集 → 训练 → 部署 → 复用」的闭环成本；LeRobot 生态上的真机产品层。

### 对内必须承认（Truth）

| 层 | 现状 |
|----|------|
| **入口问题（当前真问题）** | 从「有硬件」到「第一次能动」的路径太长，绝大多数人到不了采集 |
| **闭环问题（叙事问题）** | 云训、Workflow、Skill 商店在入口为零时都是空转 |
| **付费问题（未验证）** | 没有一条路径证明有人愿意为 GUI / 云训付钱 |

**2026 下半年唯一值得用工程时间换的假设：**

> 真实 SO-101 / LeRobot 用户最长的卡点是「装环境」；若把「连接 → 点动」放进浏览器（WebSerial），会有人真的进来用。

若假设为假（多数人说「CLI 挺好」「卡的是标定 / 数据质量」），则 **停止加功能，重新定义卖给谁**。

## 5. 交互与设计含义（不是再做一版好看页面）

| 原则 | 含义 |
|------|------|
| 首屏第一 CTA | 零安装体验（Reachy 虚拟已部分落地，见 M28 T1） |
| 真机第一路径 | 未来应是 **浏览器直连串口**，不是 Setup 四步装 Agent |
| Local Agent 文案 | 降级为「进阶：CAN / 高频环 / 本地大数据集」 |
| 演示纪律 | 禁止假成功、假数据集、点了会 404 的按钮（M28 P0） |
| 不做 | 为叙事再加机型、再加无 executor 的 Workflow 节点、支付系统假入口 |

设计的「一个工作」：让用户在 **第一次会话** 里看到机器人动，而不是看到安装说明。

## 6. WebSerial 是什么（给非技术同事）

浏览器原生 API（`navigator.serial`）：网页经用户授权后直接读写 USB 串口。  
bambot.org 已证明同款 STS3215 可零安装驱动；仓库内有站点快照可参考。

| 能进浏览器 | 必须留在 Local Agent |
|------------|----------------------|
| 串口连接 / 扫舵机 / 读写真位置 / 主从遥操（双串口） | CAN（B601）、LeKiwi ZMQ Host、ROS2、高频控制环、大数据集本地存储 |
| `getUserMedia` 摄像头预览 | — |

仅 Chromium（Chrome/Edge）。Firefox / Safari 需明示。

**边界：** WebSerial 解决「能不能用上」，**不自动解决「为什么付钱」**。付费验证仍依赖访谈与后续云训/团队档。

## 7. 下一步：用户访谈门禁（先于写代码）

### 7.1 去哪找人（信号质量排序）

1. LeRobot GitHub issue（SO-101 / install / setup / calibration）  
2. 闲鱼 / 淘宝买过 SO-101 套件的人  
3. B 站 / 小红书发组装视频的人及其评论区  
4. HF Discord `#lerobot`（高手偏多，答案需校正）

目标：**5–10 人**；若 5 人高度一致也可收束。

### 7.2 核心问题（禁止先推销产品）

> **你上次搞 SO-101，花时间最长的一件事是什么？**

补充：

1. 从拿到硬件到第一次动起来，花了多久？中间放弃过吗？  
2. 现在录数据 / 训练怎么做？（区分「真在做」vs「组装完就放那」）  
3. （**最后问**）如果有个网页插上 USB 就能控制、不用装环境，你会用吗？

### 7.3 判定表

| 多数答案 | 结论 | 动作 |
|----------|------|------|
| 装环境 / 依赖冲突 | WebSerial 假设成立 | 立刻做 T2-1，2–3 周；首里程碑：无痕 Chrome → 授权 → 扫到 6 舵机 → 滑条点动 |
| 标定太麻烦 | 入口不是主矛盾 | 做浏览器标定向导；Workflow 可砍 |
| 训出来不能用 / 数据质量差 | 解错环节 | Workflow 编排器基本白写；转向数据质量诊断 |
| 「CLI 挺好，不需要 GUI」 | 买家选错 | **停加功能，重定义卖给谁** |

最后一行是最贵、也最省时间的结果。

## 9. 执行纪律（从今天起）

1. **2026-08-01 产品决策：** 按纲领向「零安装先动起来」推进，让用户肉眼可见双路径——虚拟 Reachy + SO-101 WebSerial 浏览器直连（最小：授权→扫描→滑条点动）。访谈仍做，但**不再阻塞**这条可见造血路径。  
2. **不为融资叙事加机型 / 加假节点 / 加支付按钮。**  
3. **北极星：** 陌生用户能否在 2 分钟内看到「臂/虚拟机器人在动」；辅以访谈卡点分布。  
4. Local Agent 文案统一降级为「进阶」；CAN / LeKiwi Host / 大数据集仍走 Agent。
