## 总路线

BotverseX 的路线是：

先做数据采集入口，再做本地运行时，再做技能闭环，再做技能库，最后自然形成市场。

这条路线的顺序不能颠倒：

- 没有低门槛采集入口，真实场景变不成数据。
- 没有开发工具，开发者做不出技能。
- 没有本地运行时，技能跑不回真实机器人。
- 没有可运行的技能，市场就是空的。
- 没有真实使用，更新和变现没有基础。

**2026-07-31 补充：**「低门槛」目前被 Local Agent + lerobot 全家桶否定。若访谈确认卡点是装环境，则阶段一的工程主线是 **WebSerial 浏览器直连**（Local Agent 降级为进阶路径），而不是继续堆 Workflow 节点。

## 阶段一：开发者工具

目标：让开发者和场景拥有者**在浏览器里**从零连上机器人，完成串口授权、舵机识别、点动 / 遥操作和数据录制——理想上接近「插上就能动」，而不是「先装 2.9 GB Agent」。

服务对象（待访谈验证，勿写死「教学实验室招标」）：

- 个人开发者 / 创客（刚买到 SO-101）；
- 小团队 lab；
- 学校与创客空间（**仅当入口墙拆掉之后**才成立）；
- 早期机器人创业者；
- 拥有真实任务场景、但还不知道这些场景有数据价值的人。

当前已经具备或已有雏形（**团队机器上能跑 ≠ 陌生人能用上**）：

- 端口扫描 + Wiggle 识别（经 Local Agent）；
- Leader / Follower 指派；
- 遥操作 / 数据录制（经 `lerobot-teleoperate` 等）；
- 3D URDF 可视化；
- Workflow 编辑器（部分节点无 executor，见 M28）；
- 多种硬件 Runtime：SO-101、Reachy Mini、B601、LeKiwi 等（成熟度不一）。

阶段目标：

让陌生人少折腾串口、环境、脚本，尽快让机器人动起来，录到第一段真实场景数据。  
**访谈通过后的候选工程：WebSerial 零安装点动 → 主从 → episode。**

## 阶段二：技能闭环

目标：让一个技能从数据采集、训练、评估、部署到复用在平台里完成。

Workflow 是关键抽象。它要把原来散落在命令行、脚本、ROS、PyTorch 里的流程变成可视化 pipeline，把“场景 → 数据 → 模型 → 技能 → 真机运行”串起来。

典型 Workflow：

1. 连接机器人；
2. 读取相机；
3. 遥操作录制；
4. 转换成 LeRobot 数据集；
5. 选择基础模型；
6. 训练 / 微调；
7. 评估；
8. 部署到 Local Agent；
9. 发布成 Skill。

需要继续产品化的部分：

- Workflow 节点真正执行；
- 训练节点；
- 评估节点；
- 部署节点；
- 模型管理；
- 技能打包；
- 技能安装和运行。

阶段目标：

让用户能创建、保存、复用第一个 Skill。

## 阶段三：技能库和分发

目标：让 Skill 可以被发布、发现、安装、运行和更新。

这个阶段开始建立：

- 公开技能库；
- 搜索和分类；
- 评价和示例；
- 版本管理；
- 硬件兼容性匹配；
- 授权和未来付费。

阶段目标：

机器人技能可以被交易和流通。

## 阶段四：企业和生态

目标：让企业管理多台机器人、多个任务、多个模型版本、多个团队成员。让硬件厂商通过接入 BotverseX 获得开发者生态和技能分发能力。

企业场景需要的能力：

- 设备管理；
- 任务调度；
- 模型版本管理；
- 技能部署管理；
- 权限管理；
- 日志和监控；
- 远程诊断；
- 数据回收和再训练；
- 私有化部署。

阶段目标：

从开发者工具升级为机器人运营平台和生态入口。

## 技术问题的稳定回答模板

当被问到“不同机器人怎么通用”“你们是不是只是套壳”“底层怎么适配”时，用三层回答：

底层，不同机器人一定需要 Adapter，因为关节、坐标系、SDK、相机、夹爪都不同。

中层，BotverseX 把不同硬件抽象成 Runtime，把开发流程抽象成 Workflow，把机器人能力抽象成 Skill。

上层，用户不应该直接面对每个厂商的 SDK 和命令行脚本，而应该在浏览器里完成连接、采集、训练、部署和复用。

我们现在先在 SO-101 和 Reachy Mini 这类开放硬件上打通闭环，再逐步扩展更多硬件。

## 功能优先级判断

后续产品推进时，所有功能尽量围绕这条主线判断：

1. 它是否降低真实场景进入数据闭环的门槛？
2. 它是否让开发者更容易接入机器人？
3. 它是否让数据采集、训练、部署更闭环？
4. 它是否让 Skill 更容易被复用、发布、安装或更新？
5. 它是否增强 Local Agent / Realtime / Runtime 作为本地运行层的地位？
6. 它是否让未来的技能市场更可信？

如果答案是否定的，就暂时不要偏航。

## 当前不要急着做的事

- 不要一开始就做空的 marketplace。
- 不要为了讲故事而承诺支持所有机器人。
- 不要把主线偏成单纯机械臂控制台。
- 不要过早重投入自研硬件。
- 不要为了演示堆功能，而忘记“开发、运行、分发”这条主链路。
- 不要为了宏大叙事跳过真实数据闭环：没有采集、训练、部署和复用，生态就是空的。

## 近期推进原则

短期每个阶段都应该有真实用户价值：

- 第一阶段，用户能更快让机器人动起来。
- 第二阶段，用户能沉淀自己的数据和技能。
- 第三阶段，用户能复用别人的技能，也能发布自己的技能。
- 第四阶段，企业能管理机器人、技能、数据、模型和团队。

BotverseX 的产品方向不是“做更多页面”，而是让机器人能力更容易被创造、验证、运行、复用和分发。

更底层地说：

> BotverseX 的方向是降低真实世界机器人数据闭环的成本，让更多场景、更多开发者、更多硬件进入“采集 → 训练 → 部署 → 复用”的循环。
