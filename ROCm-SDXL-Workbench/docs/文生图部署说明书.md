# AMD 显卡 文生图（AI 画图）一键部署说明书

> 适用对象：完全没接触过 Linux / AI 部署的小白
> 环境：AMD GPU + ROCm 平台，Ubuntu/Debian 系容器
> 目标：把 **A1111 WebUI**（经典 Stable Diffusion 网页界面）和 **ComfyUI**（节点式工作流）跑起来，能在外网通过浏览器画画

---

## 一、整体是啥？先看图

```
你的电脑（浏览器）
     │  通过 SSH 隧道连接（安全，见第八章）
     ▼
服务器（这台 AMD 机器）
  ├── A1111 WebUI  ──> 127.0.0.1:7860  （文生图网页界面）
  ├── ComfyUI      ──> 127.0.0.1:8188  （节点式工作流界面）
  └── 共享 AI 环境   ──> 装好的 torch（AMD 专用版）
```

两个界面共用同一块 AMD 显卡，可以同时开。网页界面只在本机（127.0.0.1）上，外面连不上，所以要用 SSH 隧道"打洞"（第八章）。

## 二、准备工作（一次性）

### 1. 目录规划（重要！）
| 东西 | 路径 | 说明 |
|---|---|---|
| A1111 WebUI 程序 | `/workspace/stable-diffusion-webui` | 主程序 |
| ComfyUI 程序 | `/workspace/ComfyUI` | 主程序 |
| WebUI 专用虚拟环境 | `/persistent/webui_env` | 只装 WebUI 的依赖 |
| 共享 torch 环境 | `/persistent/amd_ai_env` | AMD 版 torch，两个程序共用 |
| 模型目录 | `/persistent/comfyui/models/` | 所有大模型放这 |

> ⚠️ **为什么搞两个环境？**
> torch（AI 计算库）很大而且必须匹配显卡驱动，所以单独做一个共享的放 `/persistent`（重启不丢）。
> WebUI 自己又有一堆小依赖（clip、open_clip 等），单独放一个 venv，不和 torch 混在一起。

### 2. 检查显卡是否被识别
```bash
rocm-smi --showmeminfo vram
```
看到 `VRAM Total Memory` 就说明 AMD 驱动 OK。我们这台是 48GB 显存。

## 四、最重要的坑：环境变量 LD_LIBRARY_PATH

**这是整个部署里最容易翻车、最坑的一步。**

容器里默认有 `LD_LIBRARY_PATH=/opt/rocm/lib:/usr/local/lib:`，它会让 AI 库去加载"系统的旧库"，而不是 WebUI 自带的正确库，导致这种报错：

```
RuntimeError: operator torchvision::nms does not exist
```

**解决办法：启动前必须 unset 掉：**
```bash
unset LD_LIBRARY_PATH
```

> 🧠 简单理解：`LD_LIBRARY_PATH` 是"找共享库的搜索路径"，被系统预置了一个坑爹路径。Unset 掉之后，torch 就用自己的 RPATH 找到正确的库，一切正常。

## 五、装 WebUI 的依赖（逐个排雷）

### 1. 创建 venv 并接入共享 torch
```bash
# 创建 venv（python3.12）
/usr/bin/python3.12 -m venv /persistent/webui_env
/persistent/webui_env/bin/pip install --upgrade pip

# 把共享 torch 接进来（软链接，不是重新装！）
ln -s /persistent/amd_ai_env/lib/python3.12/site-packages/torch* /persistent/webui_env/lib/python3.12/site-packages/
ln -s /persistent/amd_ai_env/lib/python3.12/site-packages/torchvision* /persistent/webui_env/lib/python3.12/site-packages/
ln -s /persistent/amd_ai_env/lib/python3.12/site-packages/torchaudio* /persistent/webui_env/lib/python3.12/site-packages/
ln -s /persistent/amd_ai_env/lib/python3.12/site-packages/triton* /persistent/webui_env/lib/python3.12/site-packages/
```

> ⚠️ **绝对禁止** `pip install torch torchvision`！会破坏共享环境，且 `download.pytorch.org` 还被墙（403）。

### 2. 用小 pip 装的依赖（PyPI 可达）
```bash
VENV=/persistent/webui_env/bin/pip

# open_clip 版本非常关键：必须 2.20.0！装 3.x 会报 attn_mask 形状错误
$VENV install --no-deps open-clip-torch==2.20.0
# OpenAI 的 clip
$VENV install --no-deps git+https://github.com/openai/CLIP.git
# 调试工具（可选）
$VENV install py-spy
```

### 3. 用 GitHub 压缩包下的依赖（放在 WebUI 的 repositories 目录）
GitHub 主页和 codeload 下载可达，但 release 附件下载被墙。所以全部用 codeload 的 tar.gz。

```bash
cd /workspace/stable-diffusion-webui/repositories

curl -Lk -o gm.tar.gz https://codeload.github.com/Stability-AI/generative-models/tar.gz/refs/heads/main
mkdir generative-models && tar xzf gm.tar.gz -C generative-models --strip-components=1

# BLIP（图像理解，注意是 salesforce/BLIP，不是 openai）
curl -Lk -o blip.tar.gz https://codeload.github.com/salesforce/BLIP/tar.gz/refs/heads/main
mkdir BLIP && tar xzf blip.tar.gz -C BLIP --strip-components=1

# k-diffusion（采样器，必须固定版本，新 master 需要 dctorch 会报错）
curl -Lk -o kd.tar.gz https://codeload.github.com/crowsonkb/k-diffusion/tar.gz/ab527a9a6d347f364e3d185ba6d714e22d80cb3c
mkdir k-diffusion && tar xzf kd.tar.gz -C k-diffusion --strip-components=1

# taming-transformers（155MB）
curl -Lk -o taming.tar.gz https://codeload.github.com/CompVis/taming-transformers/tar.gz/refs/heads/master

# 重点：Stability-AI/stablediffusion 已被删除（404）！
# 用 w-e-w 的 fork，包含需要的 midas 模块
```

## 六、两个必须打的补丁（都是实测踩过的坑）

### 补丁 1：transformers 版本兼容（不开这个 WebUI 会"假死"）
WebUI 自带的"禁用 CLIP 下载"机制在 transformers 4.40.2 下会崩。改文件：

`/workspace/stable-diffusion-webui/modules/sd_disable_initialization.py`
把 `CLIPTextModel_from_pretrained` 函数改成：
```python
def CLIPTextModel_from_pretrained(pretrained_model_name_or_path, *model_args, **kwargs):
    res = self.CLIPTextModel_from_pretrained(None, *model_args, config=CLIPTextConfig(pretrained_model_name_or_path), state_dict={}, **kwargs)
    res.name_or_path = pretrained_model_name_or_path
    return res

def CLIPTextConfig(pretrained_model_name_or_path):
    from transformers import CLIPConfig, CLIPTextConfig
    try:
        return CLIPConfig.from_pretrained(pretrained_model_name_or_path, local_files_only=True).text_config
    except Exception:
        return CLIPTextConfig(
            vocab_size=49408, hidden_size=768, intermediate_size=3072,
            num_hidden_layers=12, num_attention_heads=12, max_position_embeddings=77,
            hidden_act="quick_gelu", layer_norm_eps=1e-5,
            pad_token_id=1, bos_token_id=0, eos_token_id=2, projection_dim=768,
        )
```

> 🧠 为什么：SDXL 的配置里有一个旧版 CLIP（CLIP ViT-L/14），它用 transformers 的 `from_pretrained` 加载。原补丁传的是字符串配置，新版 transformers 会拿 `None` 当仓库名去网上找 → 404 → 后台线程悄悄死掉，看起来就是"卡死"。改成传一个离线构建的配置对象就绕过去了。

### 补丁 2：VAE 预览模型（不开的话出图最后一步报 SSL 错误）
WebUI 需要一个 `vaeapprox-sdxl.pt` 小模型，它默认从 GitHub release 下载（被墙）。手动从镜像站拿：
```bash
mkdir -p /workspace/stable-diffusion-webui/models/VAE-approx
curl -Lk -o /workspace/stable-diffusion-webui/models/VAE-approx/vaeapprox-sdxl.pt \
  "https://hf-mirror.com/ashleykleynhans/a1111-models/resolve/main/VAE-approx/vaeapprox-sdxl.pt"
sha256sum /workspace/stable-diffusion-webui/models/VAE-approx/vaeapprox-sdxl.pt
# 期望：6c8db511f910184436a613807ce06a729f4cf96bbf7977c7c6c40d5b3e4a8333
```

## 八、启动

### 启动脚本（推荐，直接复制保存为 `/persistent/start_webui.sh`）
```bash
#!/bin/bash
# 启动 A1111 WebUI
VENV=/persistent/webui_env/bin/python
WEBUI=/workspace/stable-diffusion-webui
LOG=/tmp/webui_run.log

if pgrep -f "webui.py --skip-torch-cuda-test" > /dev/null; then
    echo "WebUI 已在运行"
else
    setsid bash -c "export ROCM_PATH=/opt/rocm HSA_OVERRIDE_GFX_VERSION=11.0.0 HF_HUB_OFFLINE=1; unset LD_LIBRARY_PATH; cd $WEBUI && exec $VENV webui.py --skip-torch-cuda-test --server-name 127.0.0.1 --port 7860 --no-half-vae --opt-sdp-attention --api > $LOG 2>&1" < /dev/null &
    echo "WebUI 启动中，日志: $LOG"
fi
```

参数解释（小白注意，v1.10.1 和网上旧教程不一样）：
| 参数 | 说明 |
|---|---|
| `--skip-torch-cuda-test` | AMD 卡跳过 NVIDIA 检测 |
| `--server-name 127.0.0.1` | 只在本机监听（安全）。⚠️ 没有 `--rocm` 这个参数！`--listen` 是裸开关，指定地址用 `--server-name` |
| `--no-half-vae` | VAE 用 fp32，防止图片发黑/色块 |
| `--opt-sdp-attention` | 注意力优化，AMD 下稳定 |
| `--api` | 开 API，方便脚本调用 |

### 停止/重启
```bash
# 停止（注意 [p] 的写法，防止误杀自己）
pkill -9 -f '[p]ython webui.py'
# 再启动
bash /persistent/start_webui.sh
# 看日志
tail -f /tmp/webui_run.log
```

## 十、从外网使用（SSH 隧道，最安全）

WebUI 只在本机，外面连不上。用 SSH 隧道"打通"：

### 1. 服务器上确认 sshd 在跑
```bash
bash /persistent/start_sshd.sh
```
公网 IP / 端口以"服务器给我的"为准（例如 `<SERVER_IP>:<SSH_PORT>`，这个端口只映射到服务器的 22）。

### 2. 在你自己的电脑上执行
```bash
# 方式 A：密钥登录
ssh -i 你的私钥路径 -N -L 7860:127.0.0.1:7860 -L 8188:127.0.0.1:8188 root@服务器IP -p 端口

# 方式 B：密码登录（提示时输入 root 密码）
ssh -N -L 7860:127.0.0.1:7860 -L 8188:127.0.0.1:8188 root@服务器IP -p 端口
```

### 3. 浏览器打开
- `http://localhost:7860` → A1111 WebUI（文生图界面）
- `http://localhost:8188` → ComfyUI

> 隧道命令保持窗口不关；断线就重跑。外网 IP/端口变化以服务器给的最新为准。

## 十一、常见问题速查表（全是我们实测遇到的）

| 现象 | 原因 | 解决 |
|---|---|---|
| `RuntimeError: operator torchvision::nms does not exist` | 系统 LD_LIBRARY_PATH 干扰 | 启动前 `unset LD_LIBRARY_PATH` |
| `No module named 'clip'` | 没装 OpenAI clip | `pip install --no-deps git+https://github.com/openai/CLIP.git` |
| `No module named 'sgm'` / `'BLIP'` / `'k_diffusion'` / `'taming'` | 对应仓库没放好 | 见第五章第 3 步 |
| `No module named 'ldm.modules.midas'` | 官方 stablediffusion 仓库已删 | 用 w-e-w 的 fork（cf1d67a6） |
| `RuntimeError: The shape of the 2D attn_mask is torch.Size([77, 77])...` | open_clip 装成了 3.x | `pip install --no-deps open-clip-torch==2.20.0` |
| 启动后日志停在 `Creating model from config:`，进程"假死" | transformers 版本不兼容 | 打第六章补丁 1 |
| 出图时 `SSL: CERTIFICATE_VERIFY_FAILED`（sd_vae_approx） | vaeapprox 模型下载被墙 | 打第六章补丁 2 |
| `Directory '.../stable-diffusion-webui-assets' does not exist` | 前端资源没下 | 放 webui-assets 仓库（见第五章第 3 步） |
| 日志半天没新输出，但进程活着 | stdout 被缓冲（正常现象） | 等它出图；或启动加 `python -u` |
| 想停 WebUI 却把自己 shell 杀了 | 命令误匹配 | 用 `pkill -9 -f '[p]ython webui.py'` |
