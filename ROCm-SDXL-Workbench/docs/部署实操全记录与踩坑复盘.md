## 三、实操全流程（按时间线）

### 阶段 0：环境摸底
```
先搞清楚三件事：
1. ComfyUI 怎么跑起来的？→ /persistent/start_comfyui.sh
   （venv=/persistent/amd_ai_env/bin/python，目录=/workspace/ComfyUI，端口 8188）
2. 共享的 AI 库放哪？→ /persistent/amd_ai_env
   （torch 2.9.1+rocm7.2.1、torchvision、torchaudio 都在里面）
3. WebUI 缺啥？→ 缺一个自己的 venv，torch 要用共享的，不能重装
```

### 阶段 1：建 venv + 接入共享 torch
```bash
/usr/bin/python3.12 -m venv /persistent/webui_env
/persistent/webui_env/bin/pip install --upgrade pip

# 关键：torch 系列全部软链进 webui_env，绝不 pip install torch
ln -s /persistent/amd_ai_env/lib/python3.12/site-packages/{torch,torchvision,torchaudio,triton}* \
      /persistent/webui_env/lib/python3.12/site-packages/
```

### 阶段 2：装 WebUI 的小依赖

**弯路 ①：一开始以为 pip 全被墙**
- 前几轮尝试 `pip install torch` 失败（`download.pytorch.org` 403），误以为 pip 全不能用
- **复盘**：只有 pytorch 官方源被墙，PyPI 本身和 GitHub 都是通的！
- 实际可用：`pip install open-clip-torch==2.20.0`、`pip install py-spy`、`pip install git+https://github.com/openai/CLIP.git`

```bash
VENV=/persistent/webui_env/bin/pip
$VENV install --no-deps open-clip-torch==2.20.0
$VENV install --no-deps git+https://github.com/openai/CLIP.git
$VENV install py-spy
```

**弯路 ②：GitHub 下载源试了个遍，只有两个能通**
| 源 | 结果 |
|---|---|
| `codeload.github.com`（仓库 tar.gz） | ✅ 通 |
| `hf-mirror.com`（HF 镜像） | ✅ 通 |
| `github.com` 主页 | ✅ 通（要 `curl -k` 绕过自签证书） |
| `release-assets.githubusercontent.com`（GitHub release 附件） | ❌ 连接超时 |
| `ghproxy.com` / `ghfast.top`（加速代理） | ❌ 超时 |

**结论**：所有仓库一律用 codeload 的 `tar.gz` 下载，模型/附件用 hf-mirror。

### 阶段 3：第一次启动 → 崩溃在 torchvision
启动 `webui.py` 直接崩：
```
RuntimeError: operator torchvision::nms does not exist
```

**弯路 ③（本阶段最耗时）：一开始方向错了**
- 第一反应：torchvision 坏了 → 怀疑是之前装坏残留（发现有个无效的 dist-info）
- 折腾：查 torchvision 二进制、对比 amd_ai_env、甚至想重装 torchvision
- **转机**：单独跑 `import torchvision` 却完全正常 → 说明不是 torchvision 本身坏
- 才想到环境变量 → 发现容器预置了 `LD_LIBRARY_PATH=/opt/rocm/lib:/usr/local/lib:`
- **根因**：`LD_LIBRARY_PATH` 让 `torchvision._C.so` 去 `/opt/rocm/lib` 加载了**系统自带的旧 libtorch**，而不是 torch 自带的那份 → dispatcher 对不上 → nms 算子找不到

**修复**：启动前 `unset LD_LIBRARY_PATH`，彻底解决。

> 🧠 复盘：`RuntimeError: operator xxx does not exist` 这种"算子不存在"，在 AMD 环境十有八九是库加载错乱，不是算子真没有。

### 阶段 4：缺模块逐个修（弯路最密集的一段）
每次启动都报不同的 `No module named 'xxx'`，逐个解决：

| 报错 | 真相 | 弯路 |
|---|---|---|
| `No module named 'clip'` | OpenAI CLIP 没装 | 无，pip 装好 |
| `No module named 'sgm'` | 缺 Stability generative-models | 无，codeload 下 main |
| `No module named 'BLIP'` | **弯路 ④：openai/BLIP 根本不存在（404）**，正确是 salesforce/BLIP | 试错一次 |
| `No module named 'k_diffusion'` | 缺 k-diffusion | **弯路 ⑤**：下了 master 版，结果它 import `dctorch`（没装）→ 必须固定到 A1111 要的 commit `ab527a9` |
| `No module named 'taming'` | 缺 taming-transformers | 无，codeload 下 master；但**弯路 ⑥**：还要在 venv 放 `.pth` 挂接路径，否则搜不到 |
| `No module named 'ldm.modules.midas'` | **弯路 ⑦：Stability-AI/stablediffusion 官方仓库已被删（404）** | 用 w-e-w 的 fork `cf1d67a6` 才有 midas 模块 |

**弯路 ⑧：前端资源**
启动又报 `Directory '.../stable-diffusion-webui-assets' does not exist`
→ 从 codeload 下 AUTOMATIC1111 的 assets 仓库补上。

### 阶段 5：模型能建了，但 CLIP 报形状错
```
RuntimeError: The shape of the 2D attn_mask is torch.Size([77, 77]), but should be (1, 1).
```
- **根因**：webui_env 里 open_clip 是 **3.3.0**（从 amd_ai_env 共享栈带进来的），它的注意力块是 `batch_first=True`，SDXL 要的是 2.x 的 LND 格式
- **修复**：`pip install --no-deps open-clip-torch==2.20.0`（A1111 官方固定版本）
- **弯路**：第一次升级后日志看起来没变，差点以为白改 —— 其实是读到了**旧日志文件**（mtime 判断失误）

### 阶段 6：最坑的"假死"（排查最久的一段）
open_clip 换成 2.20.0 后不报错了，但日志永远停在：
```
Creating model from config: .../sd_xl_base.yaml
```
进程活着、HTTP 200、CPU 0%、线程全在 futex_wait —— 就是不往下走。

**弯路 ⑨~⑬（这个阶段试错最密）：**
1. 先猜"open_clip 在下载预训练权重被卡" → 改 sgm 源码 `pretrained=""`、加 `HF_HUB_OFFLINE=1` → **无效**
2. 怀疑 sgm 模块没生效（`__pycache__`） → 查缓存 → 不是
3. 怀疑 6.9GB 大文件读取慢 → 看 RSS/页缓存 → 不是
4. 想上 py-spy 看线程栈 → **ptrace 被限制，白装**
5. 加 DBG print 到 CLIP forward → 一直没打印 → 说明卡在更前面

**转机：写独立探针脚本**（脱离 webui.py，一步一打印）：
```bash
env PYTHONPATH=/workspace/stable-diffusion-webui /persistent/webui_env/bin/python -u /tmp/probe_load.py
```
**一次跑到底，当场现形**：
```
sgm/modules/encoders/modules.py:353  FrozenCLIPEmbedder.__init__
  → CLIPTextModel.from_pretrained("openai/clip-vit-large-patch14")
  → transformers 4.40.2 拿着 repo_id=None 去 hf-mirror 拉 config.json
  → https://hf-mirror.com/None/resolve/main/config.json → 404
```

**根因**：
- SDXL 配置第一个 embedder 是旧版 `FrozenCLIPEmbedder`（transformers 的 CLIP ViT-L/14）
- A1111 的"禁用 CLIP 下载"补丁把它改成 `from_pretrained(None, config=<字符串>)`
- transformers 4.40.2 在 commit_hash 分支会先 `cached_file(None, config.json)` 访问网络 → 404
- **异常发生在后台模型线程，被吞掉** → WebUI 进程"活着但永远不出图"

**修复**（补丁 A）：`modules/sd_disable_initialization.py` 里改为传**离线构建的 CLIPTextConfig 实例**
- 第一次传 `CLIPConfig` 整体 → 报 `CLIPConfig has no attribute hidden_size`
- 改成传 `.text_config` → ✅ 探针 5.3s 加载完成

> 🧠 复盘：后台线程异常会"假死"，这是最误导人的坑。**先怀疑输出缓冲，再写独立脚本复现，不要盯着日志猜。**

### 阶段 7：能出图了，最后一步又崩
txt2img API 报 `SSL: CERTIFICATE_VERIFY_FAILED`：
```
modules/sd_vae_approx.py  download_model  torch.hub.download_url_to_file(...)
```
- 定位：缺 `vaeapprox-sdxl.pt`（出图前预览解码要用），默认从 GitHub release 下载 → 被墙
- **修复**（补丁 B）：从 hf-mirror 手动下，sha256 校验通过：
  ```
  6c8db511f910184436a613807ce06a729f4cf96bbf7977c7c6c40d5b3e4a8333
  ```
  放 `/workspace/stable-diffusion-webui/models/VAE-approx/`
- 之后 txt2img ✅ 512×512 PNG，8步约 20s

**弯路 ⑭：stdout 缓冲再次骗人**
- 重启后日志又停在 "Creating model from config"、"Model loaded" 计数 0
- 以为又卡死 → 实际是 `> 日志文件 2>&1` 的块缓冲
- 用 GPU 显存占用（16GB，模型确实上卡了）+ API 实测出图，证明其实早就加载好了

### 阶段 8：外网访问
- WebUI 只绑 127.0.0.1 → 必须 SSH 隧道
- 用户给了公网映射 `<SERVER_IP>:<SSH_PORT>`（只映射服务器 22）
- 实测 TCP 连通 + SSH 握手正常
- 隧道命令：
  ```bash
  ssh -N -L 7860:127.0.0.1:7860 -L 8188:127.0.0.1:8188 root@<SERVER_IP> -p <SSH_PORT>
  ```

## 四、弯路总览表（按坑的"贵"程度排序）

| 排名 | 坑 | 耽误点 | 一句话教训 |
|---|---|---|---|
| 1 | WebUI 假死（transformers 404 被吞） | 最久 | 后台线程异常会静默，写独立脚本复现 |

| 6 | k-diffusion master 需要 dctorch | 短 | 固定 commit 最稳 |
| 7 | stdout 块缓冲误判"卡死" | 短 | 先看 GPU 显存再下结论 |
| 8 | pkill 把自己 shell 杀了 | 短 | 用 `'[p]ython'` 反匹配 |
| 9 | 误以为 pip 全被墙 | 短 | 只有 pytorch 官方源被墙 |

## 五、最终配置快照

**启动脚本** `/persistent/start_webui.sh`：
```bash
#!/bin/bash
VENV=/persistent/webui_env/bin/python
WEBUI=/workspace/stable-diffusion-webui
LOG=/tmp/webui_run.log

if pgrep -f "webui.py --skip-torch-cuda-test" > /dev/null; then
    echo "WebUI 已在运行"
else
    setsid bash -c "export ROCM_PATH=/opt/rocm HSA_OVERRIDE_GFX_VERSION=11.0.0 HF_HUB_OFFLINE=1; unset LD_LIBRARY_PATH; cd $WEBUI && exec $VENV webui.py --skip-torch-cuda-test --server-name 127.0.0.1 --port 7860 --no-half-vae --opt-sdp-attention --api > $LOG 2>&1" < /dev/null &
    echo "WebUI 启动中，日志: $LOG"
fi
```

**两个补丁**：
- `modules/sd_disable_initialization.py` → 离线 CLIPTextConfig（阶段 6）
- `models/VAE-approx/vaeapprox-sdxl.pt` → hf-mirror 手动下载（阶段 7）

**关键目录**：
```
/workspace/stable-diffusion-webui            A1111 主程序
/workspace/stable-diffusion-webui/repositories/   依赖仓库（generative-models/BLIP/k-diffusion/taming/sd-fork/assets）
/persistent/webui_env                        WebUI venv（torch 为软链）
/persistent/amd_ai_env                       共享 torch（勿动）
/persistent/comfyui/models/                  模型目录（checkpoints 直接放根下）
/persistent/文生图部署说明书.md               小白部署步骤版
/persistent/opencode_logs/会话记录_2026-08-04.md   对话导出
```
