## 6.1 技术报告
- **应用目标**：面向什么场景、解决什么问题、为什么值得研究。
- **系统架构**：数据、仿真、训练、推理、评估之间的关系，推荐画系统架构图。
- **数据集**：数据来源/数据量/观测和动作格式/训练集与评估集划分/预处理；无训练数据则明确说明用的是规则控制、在线环境交互还是仿真生成状态。
- **AMD GPU 和 ROCm**：说明 AMD GPU 用在哪些阶段（仿真/神经网络训练/策略推理/图像渲染/性能测试），提供 `rocm-smi`、`amd-smi` 和 `torch.__version__`、`torch.version.hip`、`torch.cuda.get_device_name(0)` 的终端截图或日志。
- **创新点**：不限于新算法，也可以是新应用场景、新数据生成方式、新系统组合、ROCm 生态适配、更好的评估方法、更完整的可复现工程、面向真实问题的交互设计。
- **团队分工**：列出成员及贡献（仿真环境/算法训练/数据处理/前端可视化/技术报告/演示视频）。

## 6.2 GitHub 仓库
推荐结构：
```
project/
├── README.md
├── requirements.txt
├── Dockerfile
├── scripts/
├── configs/
├── assets/
├── outputs/
│   ├── metrics/
│   └── videos/
├── docs/
└── LICENSE
```
README 至少包括 10 项：
1. 项目简介
2. 系统架构
3. 环境要求
4. 安装步骤
5. 数据或模型下载方式
6. 运行命令
7. 评估命令
8. 预期输出
9. 已知问题
10. 复现所需时间

> 评委按照 README 操作，应能够**从零开始得到与报告一致的结果**。

## 6.3 依赖与 Docker
- `pip freeze > requirements-lock.txt`
- 人工维护核心依赖 `requirements.txt`
- Docker 镜像属于优先项，但不是唯一交付形式。

## 6.4 演示视频
推荐时长 **3～5 分钟**，结构：
1. 20 秒：项目背景与目标
2. 30 秒：系统架构
3. 40 秒：AMD GPU 和 ROCm 环境
4. 1～2 分钟：运行过程
5. 1 分钟：最终效果和量化指标
6. 30 秒：创新点与未来工作

视频应同时展示：
- 命令行或 GUI 操作
- 程序运行过程
- 最终效果
- 指标结果
- AMD GPU 使用证据

**建议添加字幕，不要只播放无说明的 Demo 视频。**
